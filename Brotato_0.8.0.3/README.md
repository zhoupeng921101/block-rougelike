# Brotato（土豆兄弟）v0.8.0.3 拆包

源包 `E:\AniRes\tudouxiongdi.apk`（108 MB），包名 `org.godotengine.brotato`
（导出时被 apktool 认出重命名成 `com.godot.game`），versionName `0.8.0.3`、versionCode 1。

**引擎 Godot 3.5.1.stable**（从 `lib/arm64-v8a/libgodot_android.so` 里读出来的版本串）。
Godot 的 Android 导出把 PCK 摊开成了 `assets/` 目录树，**全包无加密、无壳、无热更**，
只有三类格式需要解：

| 格式 | 是什么 | 怎么解 |
|---|---|---|
| `.gdc` | GDScript **tokenizer 输出**（不是虚拟机字节码） | `工具/brotato_gdc.py` 逆 token 化 |
| `.stex` | StreamTexture，内嵌 WebP/PNG | `工具/godot_fmt.py::stex_payload` |
| `.translation` | PHashTranslation，**只存 key 的哈希** | `工具/brotato_text.py` 靠 key 名单反查 |

`.tres` / `.tscn` / `.import` 全是明文文本，数值直接可读。

> 数值/玩法结论请先读 **[数值设计报告.md](数值设计报告.md)**；
> 角色流派看 **[角色构筑指南.md](角色构筑指南.md)**，武器/套装搭配看 **[武器搭配与套装组合.md](武器搭配与套装组合.md)**，
> 升级卡抽取与保底看 **[升级卡系统.md](升级卡系统.md)**，敌人行为与刷怪投放看 **[敌人与威胁设计.md](敌人与威胁设计.md)**，
> 效果 DSL（`_效果总表.csv` 怎么读）看 **[效果系统.md](效果系统.md)**；
> 查表先看 **[配置/总表索引.md](配置/总表索引.md)**；
> 和 Balatro / Block 的机制对比看 **[../横向对比.md](../横向对比.md)**。

## 一键重跑

```bash
python 工具/brotato_all.py                   # 全量，约 20 秒
python 工具/brotato_all.py --skip=unpack     # 资源已在盘上，约 10 秒
python 工具/brotato_all.py --only=config,index
python 工具/brotato_all.py --dry             # 只列计划
```

**产物幂等**：连跑两次 `源码/` + `文本/` + `配置/` 下 306 个文件逐字节相同，可用 md5 比对验证改动。

单步调用：

```bash
python 工具/brotato_unpack.py [apk] [输出目录] [--dry]   # APK -> 资源/ 图片资源/ 音频/ 安卓壳/
python 工具/brotato_gdc.py    [资源目录] [源码目录]       # 255 个 .gdc -> 源码/
python 工具/brotato_gdc.py    --tables <libgodot_android.so>   # 重新核对三张表（见下）
python 工具/brotato_text.py   [资源目录] [文本目录]       # 13 语言 -> 文本/
python 工具/brotato_tres.py   [资源目录] [JSON目录]       # 2527 个 .tres 逐个转 JSON（可选，体积大）
python 工具/brotato_config.py [资源目录] [文本目录] [配置目录]   # -> 15 张总表
python 工具/brotato_builds.py [资源目录] [文本目录] [配置目录]   # -> 角色构筑/属性道具/套装武器 3 张表
python 工具/brotato_loadouts.py [资源目录] [文本目录] [配置目录] # -> 武器协同/套装交集/最优组合 3 张表（穷举约 70 秒）
python 工具/brotato_index.py  [配置目录]                  # 总表 -> 配置/总表索引.md
python 工具/brotato_curve.py  [输出目录]                  # 总表 -> 图表/ 两张 SVG（分析脚本，不在 all 链路里）
```

`brotato_curve.py` 和 Balatro 的 `balatro_curve.py` 一样是**独立的分析脚本**，
不属于 `brotato_all.py` 的七步流程；它只读 `配置/配置CSV/`，改了总表重跑即可刷新图。

## 踩坑清单

- **`.gdc` 的三张表不能凭印象写**。token 名序、内置函数序、内置类型序都是从本包自带的
  `libgodot_android.so` 的 `.rodata` 指针数组里读出来的（`brotato_gdc.py --tables`）。
  Godot 3.5 的 27 号内置函数是 `decimals`、28 号才是 `step_decimals`，
  按 Godot 4 的印象写会整体错位一格，产出的源码看着像对的、函数名全错。
- **marshalls 的 `decode_variant` 和 RSRC 的 variant 是两套不同编码**，类型号都不一样，
  别互相套（`godot_fmt.py` 里分成 `decode_variant()` 和 `BinResource._var()` 两份）。
- **`.translation` 倒不出全量**。PHashTranslation 只存 key 的哈希，必须先有 key 名单。
  当前覆盖 691/732 = 94.4%（分母是哈希桶里数出来的真实条目数，写在 `文本/_覆盖率.txt`）。
  没命中的 41 条是没在资源/源码里以字面量出现过的 UI 串；道具/武器/角色/效果的名称与描述全覆盖。
- **效果描述不能一律套基类 `effect.gd`**。21 个效果子类里有 19 个重写了 `get_args()`，
  套基类会把 `{1}` 填成模板自己（出现"击中敌人时产生3投射物，造成击中敌人时产生{0}投射物…"这种套娃）。
  `brotato_config.py::Loc.effect_args` 逐个照抄了子类实现；依赖玩家当前状态的量填 `«运行期»`。
- **武器的「伤害」列不能单看**。火把/掌/魔杖/土豆发射器的基础伤害写的是 1，
  伤害全从 `scaling_stats`（加成属性列）和燃烧效果来，单看伤害会误判成垃圾武器。
- **角色的 `gain_<stat> = -100` 是"整条属性乘成 0"，不是"减 100 点"**
  （`run_data.gd:537` 的 `get_stat` 是乘法）。法师的近战/远程/工程学、Cyborg 的近战/元素
  就是这样被焊死的，对应的道具是字面意义的废纸 —— `_角色构筑总表.csv` 的
  「对它无效的道具」列按这条算。
- **`_角色构筑总表.csv` 的「模拟DPS」是相对量不是实战值**：口径写死为"给还活着的主伤害属性
  均分 60 点、另给 30 点 %伤害"，只用来把武器排出高下。口径写在 `brotato_builds.py` 文件头。
- **套装按"持有的武器件数"计数，6 把同款也算 6 件**（`run_data.gd:401-423`），而且
  **只取当前件数那一档、不累加、>6 件封顶**（同上 419 行）。所以"6 把同一族双套装武器"
  才是套装收益的上限走法 —— 但穷举下来**专门凑套装是负收益**，见 `武器搭配与套装组合.md` §0。
- **落盘前排序的次键要显式给**。`_最优套装组合.csv` 早先按 `-件数` 单键排套装，
  件数相同的两套顺序会随 `set` 的哈希顺序在两次运行间变化，复跑就出假差异。
- **`zone_2` / `zone_3` 是空壳**，`waves_data` 为空；`zone_1/021` 是 dev 用的 test 波次。
  统计"有几个区域"时别把它们算进可玩内容。
- `资源/.import/` 是扁平的资源本体目录，文件名带 md5；原始路径写在各自的 `*.import` 文本里，
  `brotato_unpack.py` 靠这层映射把图片/音频还原回 `res://` 路径。
- 包里带了 **mod_loader**（`资源/addons/mod_loader/`，13 个文件），`project.binary` 的
  `application/run/main_scene` 指向 `res://addons/mod_loader/pause.tscn` —— 主场景被 mod loader 接管了。
- `lib/` 有 arm64-v8a 与 armeabi-v7a 两套，各 ~30 MB，是 `安卓壳/` 65 MB 的大头。

细节见 `../工具文档/Godot-Brotato技术细节.md`。
