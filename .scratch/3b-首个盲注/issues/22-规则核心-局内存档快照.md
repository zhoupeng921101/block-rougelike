### 代决策（轻量无人值守，依据附后）

- **成员名与次序和 09 §1 的 v1 样例完全一致**，不用回写 09。排版和样例有出入：`rng` 和 `streams` 分行写（键多了也不会挤成一行），行内列表写成 `[1, 2]`，带空格。
  `genes` 的元素定为 `{ "id": n }`：09 只写了空列表，以后基因的计数加成员就是升 schema。
- **样档是对局中间的状态**，不是 09 §1 那份开局样例：盘上有块、托盘有朝向不为 0 的槽、有死格和弃置堆，形状覆盖得更全。
- **随机流的四条（种子规范、键合法、键升序不重复、状态不全零）不在 `Validate()` 里查，在 `Read` 构造 `RngStreams` 之前查**（BadValue）。
  原因：`RngStreams` 的构造对坏种子、坏键、重复键直接抛；`XorShift128PlusRng(s0, s1)` 遇到全零会悄悄改成别的状态，构造之后就看不见了。走得出来的 `RunState` 不可能违反这四条，放进 `Validate` 只是查不出东西的代码。`Validate` 的注释写明了这一点。
- **`Validate` 补的条目**：块的三个枚举有定义；类型等级在 1..`MaxLevel`；基因在 `Config.Effects` 登记过（20 改的口径）；`step`、`group`、`score`、`combo` 非负，`discardsLeft` 在 0..规格；托盘长度 = `groupSize`，非空槽 `rot` 在 0..3；`Lost` ⇔ `failReason` 不是 `None`（枚举注释写的「胜或进行中时为 None」）。
  09 §5 没列的只加了最后这条，前后两种结局都会写进档，它防的是改档改出「输了却没原因」。
- **报错一律写成「路径: 说明」，路径用快照的成员名**。`Validate` 原来的 `blind.board[格号]` 改成 `blind.owner[行][列]`，`RunStateTests` 跟着改了一行断言。`Read` 遇到 Invalid，把前缀拆出来当 `Path`。
- **错误码分了 11 种**：语法、上限、数的种类各自分开；还原不成状态的（枚举名、种子、键、数字串、id ≤ 0、规格越界、全零流）是 BadValue；还原得出但约束不过的是 Invalid。文件层一律挪成 `.bad`，分这么细只给日志和单测用。
- **形状错报得尽量准**：碰到不认识的成员名报「多出的成员」，路径写这个多出来的名字；碰到排在前面已经出现过的名字报「重复」；期望的名字后面根本没有，报「缺这个成员」；名字都在、只是位置不对，报「次序不对」。
- **读入端在词法上放宽**：任意空白、CRLF、Tab、标准 JSON 转义都收。规范形只约束写出端，读回再写就是规范形（`Read_SkipsBomAndToleratesOtherWhitespace`）。形状和取值仍然从严。
- **64 位的十进制串只认 `long.ToString(InvariantCulture)` 写得出来的样子**：不认 `+`、前导零、`-0`；`s0` / `s1` 只认 16 位小写十六进制。
- **`Write` 不替调用方调 `Validate`**：前提写在注释里，未定义的枚举值写不出名字时直接抛。`Read` 的配置为 null 也直接抛：这是调用方的错，不是不可信输入。
- **`blind` 为 null 时 `Write` 抛**：09 §1 定了本图的快照恒带盲注，不为「开局后、开盲注前」这一刻造第二种形状。
- 新目录与文件的 `.meta` 手写（随机 GUID，形状同 19、20）。提交 trailer 由 `单仓提交.ps1` 自动补成 `agent-zp`，同 20。
