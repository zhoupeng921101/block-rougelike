# 12 · PC 上的落子、旋转与弃置操作

Type: wayfinder:grilling
Status: resolved
Claimed by: pc-input
Blocked by: 02, 05

## Question

首发是 PC 横屏（工程计划），block-client 的手势是为触屏写的：按下不拾起、越过阈值才拾起、拇指上方 offset、原地点击转朝向。3B 在 PC 上怎么操作：

- **拾起、拖动、落下**：拖拽，还是点选后点格子，或两者都支持；
- **旋转**：右键、滚轮、R 键、原地点击；拖拽中能不能转；
- **弃置**：拖到右侧弃置区（规则 §8.5），要不要快捷键或确认；
- **吸附与虚影**：落点吸附、虚影预览沿用 block-client 的口径到什么程度；
- **预览时机**：拖动中显示消除类型、底分、倍率（§8.5）什么时候出现。

依 [可移植面](02-block-client盘面与手势的可移植面.md) 的结论，决定 `BoardGestureFlow` 是裁着用还是重写。

[切片边界](05-首个可玩盲注的切片边界.md) 加了两件：Esc 返回主界面；托盘里任何朝向都放不下的块置灰。预览只显示类型名与类型本级的底注、倍率。

## Answer

**据此裁定（按授权自裁，没问用户）：PC 上只有一种拾取方式，就是左键按住拖拽；旋转不限时机，绑右键、R、滚轮和原地左键单击四个入口；弃置就是拖进弃置区松手，不做快捷键，也不弹确认。**
虚影、吸附、换格才重算照 block-client 原样用；预览和虚影同时出现、同时消失。`BoardGestureFlow` 不裁，新写一个类，拿 02 研究里那几段约 310 行当骨架。
这些都不改目的地和产品形状，所以没回去问。最可能被推翻的是旋转键位，它们集中在一张键位表里，改一处就行。

### 键位总表

| 操作 | 鼠标 | 键盘 |
|---|---|---|
| 拾起、拖动、落下 | 左键按住托盘里的块拖走，在盘上松手落子 | — |
| 弃置 | 拖进弃置区松手 | 不设 |
| 顺时针转一档 | 右键；滚轮向下一格；托盘上原地左键单击 | R |
| 逆时针转一档 | 滚轮向上一格 | 不设 |
| 取消这一手（块弹回托盘） | 在盘外、托盘上或放不下的地方松手 | 拖拽中按 Esc |
| 返回主界面 | 「返回主界面」按钮 | 没在拖拽时按 Esc |

### 逐项裁定

| 项 | 裁定 | 依据 |
|---|---|---|
| **拾取方式** | 只做拖拽。「点一下拾起、再点一下落下」这种点选式拾取不做 | 规则 §8.5 的原文就是拖：「把方块拖进去即弃置」「拖动上去时显示」。手机移植时还是这一套，block-client 的触屏拖拽也能直接对上。点选式拾取的事件可以和拖拽完全相同（拾起 / 移动 / 落下 / 取消），以后只在输入层补，不动规则核心和布局。理由见下文「为什么不是别的做法」 |
| **按键过滤** | 只有左键能拾起和拖动，右键、中键一律不进拖拽器 | 这是 [02](02-block-client盘面与手势的可移植面.md) 列的必改项：`BlockPieceDragger.cs:75-119` 从不看 `e.button`，旧输入系统的 `StandaloneInputModule` 对三个键都发拖拽事件。Balatro 1.0.1o 也只有左键进拖拽和点击，右键另走一条路（`参考/产物/Balatro_1.0.1o/源码/main.lua:269-282`） |
| **起拖阈值** | 沿用「按下不拾起，移动越过阈值才拾起；没越过算原地点击」。PC 的阈值单独取一个常量，先填 10 设计像素（触屏是 20），归入布局常量，调手感时改它 | 原地点击要留给旋转（见下），所以得有阈值。鼠标的抖动比手指小，20 偏大，会让人觉得块「粘」在槽里。Balatro 判点击也用距离阈值（`engine/controller.lua:397-398`，`globals.lua:385` 的 `MIN_CLICK_DIST`） |
| **跟手** | 拇指偏移取 0，位移倍率取 1.0：拾起后块心就在指针下，指到哪里就落在哪里。拾起时块放大到和盘格一样大，这一点照旧 | 偏移 180 和倍率 1.2～1.4 都是为了不让指尖挡住落点（`BlockLayout.cs:46, 51`），鼠标没有这个问题。倍率一旦大于 1，块就会离开指针，落点和手感都对不上。落点解析本来就按「容器中心 = 块阵中心」算（`BoardGestureFlow.cs:645-674`），块心在指针下正好对得上 |
| **悬停** | 指针停在托盘某块上时轻微高亮，表示这块可以拿；置灰的块也高亮 | 这是 PC 才有的可供性提示，也用来确定旋转对象（下一行） |
| **旋转对象** | 拖着的时候转手上那块；没拖的时候转指针悬停的那块；指针不在任何一块上时，R、右键、滚轮都不起作用 | 规则 §2.1、§2.2 写的是「随时免费、不限次数」。拖着的时候转是 PC 上最顺手的用法：一边瞄落点一边转。没拖的时候按悬停对象来转，就不用另外做一个「当前选中块」的状态 |
| **旋转入口** | 右键、R、滚轮向下一格都是顺时针转一档；滚轮向上一格是逆时针一档；托盘上原地左键单击也是顺时针一档（block-client 的点击转向，`BoardGestureFlow.cs:358-364`）。高精度滚轮按累计量满 1 才转一档 | 四个入口都不花代价，误触也只是多转一下。右键配合按住的左键，单手就能完成「拖 + 转」；R 给习惯左手放键盘的人；滚轮是唯一提供逆时针的入口，四朝向的块省两次按键。原地单击照留，PC 和以后的手机版用同一套肌肉记忆。如果笔记本触控板的惯性滚动转得太多，把滚轮那一项去掉即可，其余入口不受影响 |
| **拖拽中旋转的实现** | 逻辑朝向立即生效，并**立即重算虚影和预览**（指针没动也要重算）。视觉上直接转手上那个容器（`RotateFx`），拖拽期间绝不重建托盘，落下或取消之后再重建。块绕自己包围盒的中心转 | block-client 只在指针移动时才重算虚影，而且「同格不重画」的缓存只按 `(col, row)` 记（`BoardGestureFlow.cs:481`），转了朝向也不会重画。3B 要把缓存键改成 `(col, row, rot)`。不重建托盘的理由见 `BoardGestureFlow.cs:302-304`：重建会销毁正在处理拖拽事件的那个节点 |
| **落下与吸附** | 落点 = 几何反算 + 吸附，虚影和真落子共用同一个方法。吸附照 block-client 原样：精确格放不下时，在周围 1 格内找最近的可放格；向上吸附不吸进最底两行（`BoardPlayFlow.cs:225-249`，`BlockLayout.cs:62, 67`）。是否可放用规则核心的落子判定（含死格掩码，见 05） | 吸附只挪虚影和落点，而且虚影就画在会落下的格上，玩家看到的就是会发生的，所以这份宽容没有代价。「待放置区在盘下方」这个前提在 3B 成立（§8.5）；如果 13 把托盘挪走，底两行禁入要跟着改 |
| **放不下** | 块弹回原槽，不弹提示，也不算任何操作 | 虚影只在放得下时出现（`BoardGestureFlow.cs:474-479`），没有虚影就已经说明了「这里放不下」。block-client 在盘内放不下时会弹「这里放不下」（`:400`），3B 不要，省一条文本 key，也不打断拖拽 |
| **弃置** | 拖进弃置区松手立即弃置，不弹确认。块悬在弃置区上方时，弃置区高亮并显示剩余次数，盘上不画虚影。弃置次数用完时弃置区显示不可用，拖进去松手和放不下一样弹回。判定看指针（也就是块心）在不在弃置区内 | §8.5 原文就是「拖进去即弃置」。把块拖到一个专门的区域本身就是明确的意图，再加一个确认，会把一个有限次数的关键操作变成两步。误弃的风险靠布局来防，不靠确认框，约束交给 13（见「对下游票」） |
| **弃置快捷键** | 不做 | 弃置次数稀缺，而且做了就撤不回。「悬停 + 按一个键」太容易误触。Balatro 1.0.1o 的弃牌也只有按钮，正式版键盘只认 Esc 和长按 R 重开（`engine/controller.lua:976-988, 1084-1104`），其余键都在 `if not _RELEASE_MODE` 里（`:994`；`conf.lua:1`） |
| **虚影与行列高亮** | 沿用 block-client：只在放得下时画虚影（半透明、外观和手上的块相同）；会满的行列画填充和光带（`BoardPreviewLayer` 的最小集，见 05） | 05 已经定了表现层最小集，这里只确认口径不变 |
| **预览时机** | 和虚影同时出现、同时消失，没有延迟：落点可放，而且试放后至少完成 1 条线时，显示类型名和这个类型本级的「底注 × 基础倍率」；可放但不成线时只画虚影，不显示类型。只在 `(col, row, rot)` 变化时重算。拖到弃置区上、拖出盘外、松手、取消时立即收起 | 11 种类型都以成线为前提（§3.3），不成线就没有类型可显示。试算是 8×8 上的纯函数，算一次很便宜，用不着防抖。Balatro 选牌时也是加选或减选一张就立即刷新牌型（`cardarea.lua:182` 的 `update_hand_text`，`immediate = true`）。预览框摆在哪里归 13 |
| **置灰的块** | 照样能拿起、能转、能拖进弃置区，只是在盘上永远没有虚影、松手就弹回。置灰在每一步结束后（落子、弃置、发新一组）重算，转动不影响置灰 | 放不下的块最主要的出路就是弃掉。如果置灰的块拿不起来，玩家就没法弃它。置灰看的是「任何朝向都放不下」，和朝向无关 |
| **结算演出期间** | 从松手落子起，到这一步的演出播完、新一组发好为止，托盘不接受拾起和旋转；Esc 和「返回主界面」不锁。不成线的落子没有演出，只有落子那一下的放大 | 规则核心是同步结算的，盘面数据比画面先到终态。演出时被消的格还在画面上（延迟退场），这时允许拖块，虚影就会画在画面上还有块的格上。Balatro 计分演出期间也不能再选牌出牌（`functions/state_events.lua:489` 切到 `HAND_PLAYED`；`engine/controller.lua:1213-1222` 在 `G.play` 有牌时连右键取消都拦）。锁多久等于演出多长，归迷雾里的「消除演出的节奏」 |
| **Esc** | 拖拽中按 Esc：取消这一手，块弹回。没在拖拽时按 Esc：等同「返回主界面」按钮，直接切到主界面，不弹确认。结果浮层上按 Esc：等同浮层上的「返回主界面」 | 状态每一步都存好了（05），退出不丢东西，确认框没有可保护的对象。Balatro 的 Esc 是打开选项浮层，主菜单入口在里面（`engine/controller.lua:976-988`）。本图没有选项界面，等阶段 5 有了选项界面，Esc 应改成打开它 |
| **失焦与丢失抬起事件** | 拖拽中窗口失焦，或者某一帧发现左键已经不在按下状态而又没收到抬起事件，都按「取消」处理：块弹回，不落子 | 在 Windows 上切窗口或在窗外松开鼠标，抬起事件可能不会送到。卡在「拿着块」的状态是 PC 拖拽最常见的坏状态 |
| **`BoardGestureFlow` 裁还是重写** | **重写**，新类暂名 `PieceGestureFlow`。骨架用 02 研究 §3.3 的几段：拾起、拖动、抬手 `:293-406`，转向 `:412-444`，虚影 `:459-542`，收预览 `:618-636`，落点解析 `:645-674`；卡死判定 `:273-289` 挪进规则核心，同时供置灰用。另外补：按键过滤、旋转输入、悬停对象、弃置区落点（接在抬手分支里）、预览试算（放在原来 `ShowHarvestPreview` 的位置）、结算锁、Esc、失焦取消。`BlockPieceDragger` 拷过来改四处：只认左键、偏移 0、倍率 1.0、用 PC 阈值，再加一个对外的「取消」入口 | 和 02 的结论一致：原类构造函数要注 11 个参数，其中 4 个属于消除道具，弃置区和预览试算在原类里没有位置可放。旋转输入在窗的 `OnUpdate` 里用旧输入系统轮询（`Input.GetMouseButtonDown(1)`、`GetKeyDown(KeyCode.R)`、`mouseScrollDelta.y`），因为 Demo 的 `activeInputHandler` 是 0。悬停对象用拖拽器上的 `IPointerEnterHandler`/`IPointerExitHandler` 记录。键位集中在一张表里，以后做改键时只换这张表 |

### 为什么不是别的做法

- **点选式拾取（点一下拿起、块跟着指针走、再点一下落下）**：好处是不用一直按着鼠标，手柄也好接。但「原地单击」就不能再当旋转，而且要多管一个「拿着但没按键」的状态（点到哪里算落下，点到按钮算什么）。规则原文写的是拖，手机版也是拖。它和拖拽吐的是同一组事件，以后作为无障碍或手柄方案补上，不影响任何已定的东西。
- **右键 = 取消（Balatro 的口径）**：Balatro 的右键是「取消全部选中」（`engine/controller.lua:1213-1222`），因为它的选牌是一个持续的状态。3B 拖拽时松手就能取消（拖回托盘、拖出盘外），右键空着，拿来做旋转最顺手。
- **拖拽中不能转（block-client 的现状）**：那是触屏的限制，一根手指没法同时拖和点。PC 能做到，而「边瞄边转」正是放置手感的核心。
- **弃置弹确认**：误弃的根源是弃置区挨着托盘，应该从布局上解决。确认框会让每次弃置都多一步。

### 对下游票

- **[13 战斗界面线框](13-战斗界面线框.md)**：
  - 弃置区的命中区不能和托盘相邻，中间至少隔出一个槽宽左右的空隙。草图 `8.5战斗界面-1.png` 里垃圾桶紧挨着第 5 个槽，从这个槽往右一拖就会误弃。
  - 弃置区要画三种状态：常态显示剩余次数；块悬在上面时高亮；次数用完时显示不可用。
  - 预览框（类型名 + 底注 × 倍率）不能盖住虚影和将被消的行列：要么固定放在盘外的信息位，要么贴着手上那块的上沿（block-client 的徽章就贴上沿，`BoardGestureFlow.cs:484-489`）。
  - 托盘里的块要有悬停态和置灰态。
  - 「返回主界面」按钮旁边可以标一个 Esc 提示。
- **[09 局内存档](09-局内存档的形态与时机.md)**：
  - 演出期间 Esc 和关窗都不锁，所以一步的存档要在演出开始前写完，读回来就是这一步结算后的状态。
  - 旋转不算「步」，但 05 要求续局后朝向不变，所以转动也要触发存档（可以合并写），否则关窗会丢掉上一步之后的转动。
- **[07 结算管线](07-结算管线与事件流.md)**：预览试算的输入是 (局面, 块, 朝向, 落点)。拖拽中转动也会触发试算，试算必须便宜、无副作用（05 已经要求）。置灰和第二种失败共用同一个查询「这块任何朝向都放不下」。
- **执行票（迷雾「执行票的切分」）**：输入层（`PieceGestureFlow` + 拖拽器 + 键位表）可以和表现层的 Part 放进同一张票，也可以单开一张。它依赖规则核心的落子判定、试算和置灰查询。
