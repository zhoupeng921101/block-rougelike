### 编辑器自查（反射调用，不是真输入）

手拨 MCP 进 Play，对「开始游戏」调 `onClick.Invoke()` 开局，然后经反射直接调手势流的回调（`OnBegin` / `OnDragMove` / `OnEnd` / `RotateHeld` / `Cancel` / `Lock`），每段在同一帧里走完。**这一层绕过了 EventSystem、`e.button` 过滤、`Input.GetKeyDown` 轮询和失焦判定，不能当真输入的结论用**，只证明落点、预览、命令与刷新这一段逻辑对：

- 三个托盘槽都挂上了拖拽器；悬停上浮 0 → 6 → 0。
- 拿起：块挪到窗根、放大 2.857（= 80 / 28），原槽画成空槽。拖到 (0,7)：虚影 4 格。拖着顺时针一档：托盘朝向 0 → 1，缓存键当帧变成新朝向的落点（竖 I 在底两行放不下、也不往上吸，虚影消失，符合吸附口径）；逆时针一档回到 (0,7,0)、虚影 4 格。松手：第 0 → 1 步，`DebugVerify` 逐项一致。

### 落了什么

- **`PieceGestureFlow`**（`GameLogic/UI/Battle/`，普通 C# 类，战斗窗持有、每帧经 `Update` 驱动）：骨架照 02 研究 §3.3 的拾起 / 拖动 / 抬手、转向、虚影、收预览、落点解析。
  - 落点 = 几何反算 + 吸附，虚影与真落子共用 `ResolveDrop`；吸附照 block-client（半径 1，向上不吸进最底两行），能不能放问规则核心 `CanPlace`。
  - 虚影与预览按 `(col, row, rot)` 缓存；拖拽中转朝向立即重算（不等指针动）、视觉上直接转手上那个容器、不重建托盘。
  - 预览：`ResolveClear` 合法且成线时，画行列光带、挂徽章、亮类型表那一行；数取 `LevelOf` / `BaseOf`。
  - 弃置区：块心（= 指针）在区内时亮区、挂签，盘上不画；次数用完时不亮，松手弹回。
  - 松手：调 `Place` / `Discard`，被拒或没地方放就按规则核心状态重建托盘（弹回，不提示）；接受后回调窗的 `OnStepAccepted`，本票是 `Refresh(_run)`，盘面直接跳到终态。
  - 结算锁 `Lock()` / `Unlock()` / `IsLocked`：锁着不接受拾起、单击转与键鼠旋转，悬停态也不画；Esc 与「返回主界面」不锁。锁的时候块还在手上就按取消处理。本票自己不调。
  - Esc：拖拽中是 `Cancel()`，否则回主界面（窗的 `OnUpdate`）。失焦（`Application.isFocused`，包开了 runInBackground）或左键已松开又没收到抬起事件（松开那一帧不算），都按取消处理。
  - 盲注结束后（`Outcome ≠ InProgress`）托盘不让拿起、不让转，和规则核心拒绝后续命令是同一个结果。
- **`BlockPieceDragger`**：block-client 同名类拷来改四处（只认左键、偏移 0、倍率 1.0、阈值 10），加 `Cancel()` 与悬停回调。拖拽器挂在槽根（整槽命中区），移动的是块的视觉根 `PieceRoot`。
- **`PieceKeymap`**：键位只写这一处（右键、R、滚轮下顺时针，滚轮上逆时针，累计满 1 才转一档；托盘上原地单击顺时针一档；Esc）。
- **Part**：`TraySlotPart` 加悬停态（框变亮、槽内整体上浮 6，命中区不动）与「块在手上」的空槽态；`TrayAreaPart.PlayRotate` 加方向；`RotateFx.PlayStep` 加逆时针；`DiscardAreaPart` 加高亮态与签；`ClearTypeRowPart` / `ClearTypeTablePart` 加高亮；新写 `PreviewBadgePart`。
- **预制体**：`ClearTypeRow` 首个子节点加 `m_img_Highlight`；战斗窗弃置区加 `m_img_Drop` / `m_tmp_Drop`（挂在区上沿外，底边离区顶 8，宽 320），窗根末尾加 `m_part_Badge`（404×64，pivot 在底边中点）。`_Gen` 由 `ScriptGenerator` 重生成（只多了 `m_part_Badge` 一行），绑定走 `UIBindingService.BindByNodeName`。
- **文本**：`ui.battle.discard_drop`（「松手弃置 · 剩余 {0} → {1}」/「Release to discard · {0} → {1} left」），`TextKeys.Battle.DiscardDrop`。

### 代决策（轻量无人值守，依据附后）

- **两个预览 shader 不搬**（28 交给本票定）：`UI_GlowCell`、`UI_Brighten` 的来源仍没查清（2026-07-07 那次提交进的 block-client），而纯色光带加呼吸、被消块上浮在截图里已经读得清哪几条线要消。提亮与描边辉光归正式美术（地图 Out of scope），不另开票。
- **拿起的块挂到窗根最上层**：窗根的子节点次序是托盘在弃置区之前，块留在槽里拖到弃置区上会被区盖住，13 要的是块盖住区的中部、签挂在外面。松手或取消时先把块放回槽里，再重建托盘，让它随槽一起销毁。
- **托盘只经手势流重建**：`UIBattlePanel.Refresh` 第一步改成 `_gesture.RefreshTray()`，块在手上时先收回、收预览，再重画别的；调试键（F5–F7）在拖拽中按下也不会留下孤块。
- **悬停对象重建后按指针位置重认**：被销毁的旧槽收不到移出事件，只靠事件记会留下「指着别处却还亮着、R 还能转它」的状态。
- **转到位时块在手上或左键按着，就推迟重建**：重建会销毁正在处理按下 / 拖拽事件的槽、作废这一手；转到位的画面本来就是新朝向的样子，手放开后在 `Update` 里补重建。
- **盲注结束后托盘不让拿起**：没有结果浮层时，拿起后被规则核心拒、再弹回，不如直接拿不起；结局时战斗窗记一条 Info（结局、失败原因、累计 / 目标、第几步）。
- **徽章内容用类型表那一行的 prefab 建**：13 写的徽章内容（类型名、Lv、底注 × 倍率）正是类型表一行，复用后字体、颜色、英文缩字都同源。
- **弃置签的英文**：Release to discard · {0} → {1} left。
- **提交署名**：trailer 由 `单仓提交.ps1` 补成 `agent-zp`，同 15、20、22、28。
