# 03 · 纯 C# 规则核心怎么同时进 Unity 和 dotnet test

Type: wayfinder:research
Status: resolved

## Question

工程计划要求规则核心「不依赖 UnityEngine，定标要在 Unity 外批量跑局，也方便单测」，阶段 2 还写了「客户端自检加一道规则核心的 dotnet 单测」。
同一份源码要同时被 Unity（asmdef）和 dotnet SDK（测试工程）编译，有哪几种成熟做法，各自的坑？

要查的事实：

- **block-client 的先例**：`BlockScoring.cs` 被服务端 `BlockEntity.csproj` 链接编入——怎么链的（`<Compile Include>` 通配还是逐个文件）、
  有没有配套的 dotnet 单测、`Tools/BlockBlast/形状表自检` 是什么形态。
- **Unity 6000.3 的语言上限**：C# 版本与 BCL 上限，dotnet 侧要锁到同一 LangVersion，免得写出 Unity 编不过的语法；asmdef 的 `noEngineReferences`。
- **目录冲突**：dotnet 测试工程放在 `Demo/` 里会不会被 Unity 扫进去（`~` 后缀目录、`.csproj` 与 Unity 生成的同名 csproj 冲突）。
- **本机与现状**：dotnet SDK 7/8/9/10 都装了；`Demo/.claude/devflow/` 里的 `客户端自检.ps1` 现在跑什么、有没有预留挂点（该目录在 git 暂存区里，只读不改）。
- **跑局测试要的自动落子策略**：block-client 的 `AutoPlay/`、`Module/BlockBlast/MoveScoring.cs` 能不能借。

产出：2–3 个可行布局，各自的取舍与坑，附出处。只读调查，不建工程。

## Answer

**推荐布局 A：源码正本放 `Assets/GameScripts/<规则核心>/`，独立 asmdef（`noEngineReferences: true`、`references: []`）；`Demo/DotNet/` 下放一个只做通配链接的镜像库（`netstandard2.1` + `LangVersion 9.0`），测试工程（net8.0 + NUnit）和跑局工程都 `ProjectReference` 它。**

- **block-client 先例**：四个 dotnet 工程用 `<Compile Include Link>` 链 UnityProject 源码，逐个链和通配链都有，没有一个是单测工程。边界只靠头注自律，NumericSim 要写桩。形状表自检是 Unity 编辑器菜单，不是 dotnet；它查的不变量正好拿来做第一批单测。
- **Unity 6000.3**：实际编译是 `-langversion:9.0` + netstandard 2.1（`GameLogic.rsp:360`、`:257`）。实测 9 种 Unity 编不过的写法，镜像库全拦；照先例链进 net8.0 只拦 1 种，所以目标框架也要锁。
- **目录**：不能放 `Demo/` 根（Unity 在那里重生成 csproj/sln、MSB1011、默认通配会扫进整个 Assets）；`Directory.Build.*` 只能放 `DotNet/` 里（会混进 Unity csproj 的构建）。`Assets/…/Tests~` Unity 不导入，但命名空间扫描不跳 `~`。
- **必改 `Demo/.gitignore` 三行**：`*.csproj` 任意深度都被忽略，子目录的 bin/obj 没被忽略。不改的话测试工程入不了库，自检因树哈希变化判 STALE。
- **devflow**：客户端自检现在没有单测道，台账已登记这个缺口（`obligation-ledger.md:72`），flow-config 没有相关键。工程链接核对会自动覆盖镜像库；Editor程序集编译 经 GameLogic 引用，会用 Unity 自己的 csproj 再编一遍规则核心。新 asmdef 第一次落地前，要在编辑器里刷新一次 csproj。
- **落子策略**：`AutoPlay/` 里 8 个文件引 UnityEngine，不能借。`MoveScoring` 和 `BoardMetrics` 是纯 C#，可以借枚举骨架和盘面度量，但签名绑着 Block Blast 的 `PendingPiece`/`BinaryBoard`，评分目标也不同。阶段 3 用零随机贪心，同分按字典序破平；阶段 6 再加 3B 计分项。
- **另防跨进程不确定**：CoreCLR 的字符串哈希每个进程都不同（实测三次三个值）。「逐项一致」最好有一项跨进程比对。
- B（嵌入式 UPM 包）与 devflow 的通道和扫描面处处对不上；C（预编 DLL 入库）会撞 `BLOCKED-BINARY`，改一次要编两遍。都不推荐。名字、命名空间、热更归属、测试框架交 10 号票。

详细记录见 [03-双端编译](../research/03-双端编译.md)。
