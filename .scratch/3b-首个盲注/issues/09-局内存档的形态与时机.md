# 09 · 局内存档的形态与时机

Type: wayfinder:grilling
Status: open
Blocked by: 06, 07, 08

## Question

目的地要「中途退出重进能接着打」；工程计划说「局内状态第一天就要可序列化，后补得全部返工」。

要裁的：

- **存什么**：全量状态快照，还是种子加操作日志重放（后者天然验证确定性，但规则一改旧档全废）；
- **什么时候存**：每次落子、弃置之后，退出时，还是都存；结算演出播到一半退出，读回来是哪个状态；
- **格式与位置**：JSON 还是二进制，放 `Application.persistentDataPath` 下哪个文件，要不要版本号与校验；
- **分工**：序列化在纯 C# 规则核心里做，Unity 侧只管读写文件。

block-client 的 `MergeIngameSave`、`IngameBoardCodec`（按不可信输入解码）可以参考，但它的存档要经服务端，本作单机。

[切片边界](05-首个可玩盲注的切片边界.md) 已定的前提：要存的状态清单；关窗、强退也要能续；结局一确定就删档；主界面凭有没有档显示「继续」。见其 Answer。

[规则核心的工程形态](10-规则核心的工程形态与跑局测试.md) 已定的前提（见其 Answer「对其它票」）：
- **快照序列化要规范**：同一状态必须输出逐字节相同的文本，做法是成员次序固定、一律用 InvariantCulture、不依赖哈希容器的遍历序。跑局测试比终局状态时直接比这份文本；
- 规则核心目前零外部引用。序列化如果要用 Newtonsoft 这类库，asmdef 的 `precompiledReferences` 和镜像库的 `PackageReference` 要在同一笔改动里一起加，版本对齐 Unity 包里的那份；
- 跑局测试会隔几步存读一次再接着打，和不中断的那一局逐行比对。存档漏存了状态，续打就会分叉，测试变红。

[PC 操作](12-PC上的落子与旋转操作.md) 加了两条：
- 结算演出期间 Esc 和关窗都不锁，所以一步的存档要在演出开始前写完。
- 转动不算「步」，但续局要保留朝向，所以转动也要触发存档（可以合并写）。

[结算管线](07-结算管线与事件流.md) 已定的前提（见其 Answer「对下游票」）：
- 一步在规则核心里同步算完，返回 `StepResult`（有序事件）。存档点在它返回之后、表现层开演之前；读档后直接显示这一步之后的状态，不重放事件。
- 底分、倍率、独立倍率三个累加器是步内临时量，不进存档。要存的计分状态只有累计分（`long`）、连击、类型等级（本图恒为 1）和基因槽上的效果状态（本图没有）。累计分建议写成十进制文本，以后换大数类型时旧档还能读。
- 计分全是整数，存档里没有浮点。
- 效果注册表和类型表一样是开局时传进来的规则配置，不进存档。
