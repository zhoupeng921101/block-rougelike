要做：

1. **文件层 `RunSaveFile`**（GameLogic，只用 `System.IO`，不引 UnityEngine，目录由构造参数传入）：
   - 四个文件 `run.json` / `.tmp` / `.bak` / `.bad`；
   - 写：先写 `.tmp`，再 `File.Replace` 或 `File.Move`，失败重试一次，再失败记日志、不抛；
   - 读：删残留的 `.tmp`；正档坏了挪成 `.bad`、改读 `.bak`；读到终局当无档并删档；正档不存在不回退；
   - 删档：先 `.bak`，后正档。
2. **时机 `RunSaveService`**（GameLogic，Unity 侧）：
   - 开新局：先删，再写第一份；
   - 每一步被接受：在交给表现层之前同步写；定了结局就先写终局快照、再删；
   - 转动置脏：0.5 秒防抖（占位，放进表现层的常量表），下一次写档、离开战斗界面、`Application.focusChanged(false)`、`Application.quitting` 时写掉。
3. **主界面**：
   - 「开始游戏」进战斗、「返回主界面」和 Esc 回主界面，由 [战斗窗的静态呈现](28-表现层-战斗窗的静态呈现.md) 做。本票只往这两处插存档点：开新局时先删档、再写第一份；回主界面时写掉脏标记，主界面重新探测；
   - 打开主界面时探测，有能读、校验通过、进行中的档才显示「继续」；
   - 点「继续」用探测得到的状态进战斗窗。战斗窗按状态全量刷新，不重放事件；
   - 「继续」的文案 key 由 [文本表与字体的基础件](15-文本表与字体的基础件.md) 建，本票接按钮的行为。
4. **dotnet 测试**：`Tests.csproj` 用 Link 编入 `RunSaveFile.cs`（同 `TextKeys.cs` 的做法），在临时目录里测：
   - 写两次之后 `.bak` 是第一份；
   - 正档写坏了，回退到 `.bak`，坏档挪成 `.bad`；
   - 留一个半截的 `.tmp`，读的时候被删掉，不影响正档；
   - 终局档读出来当无档，两个文件都删掉；
   - 只有 `.bak`、没有正档时当无档；
   - 读入任何内容都不抛异常。
   扩 `dotnet单测.ps1` 的读取面，加上 `RunSaveFile.cs`。
5. **在 Windows 包里验**，每条都要走一遍：
   - 打几步，点「返回主界面」，再点「继续」，局面不变；
   - 打几步，在消除演出中途 Alt+F4，重进「继续」，看到的是这一步之后的局面；

## 22 落地后补的约束（2026-10-27，`36f96a77`）

- [局内存档快照](22-规则核心-局内存档快照.md) 已落地。接口：`RunSnapshot.Write(RunState) → string`、`RunSnapshot.Read(string, RuleConfig) → SnapshotReadResult`（`Ok`、`State`、`Error`、`Path`、`Detail`）。
- 文件层只搬字符串：写的文本全是 ASCII，按 UTF-8 无 BOM 写入即可；读档时把文件全文交给 `Read`。开头有 BOM、换行是 CRLF 的档，`Read` 都照收。
- `Ok` 为假：挪成 `.bad`，日志打 `Error`、`Path`、`Detail`。错误码有 11 种，只给日志用，处置不按错误码分。
- 终局快照照常读得出来（`Ok` 为真）。`State.Blind.Outcome` 不是 `InProgress` 时当无档，删正档和 `.bak`（09 §6 读档第 3 步）。
- `Write` 要求盲注已开：开新局时先 `StartBlind`、发完第一组，再写第一次。这和 09 §2 的时机一致。
