# 06 · 盘面与方块实例的数据模型

Type: wayfinder:grilling
Status: resolved
Claimed by: data-model
Blocked by: 02, 05

## Question

3B 的方块是带身份的实例：形状、点数、强化、版本挂在块上，跟着块走，盲注结束整块洗回。盘面要能回答「这一格属于哪一块」，
而 block-client 的 `BinaryBoard` 只有 64 位占用掩码。规则核心的状态怎么建模？

要裁的：

- **方块实例**：实例 id 怎么发（本局唯一？）；形状、点数、强化与版本的槽；旋转是块的属性还是落子参数。
- **盘面**：占用掩码（判放置、判消行）加「格 → 实例 id」层，要不要再加死格层；一块分几次被消时，块实例什么时候算离场。
- **几个集合**：方块库、抽牌堆、当前一组、弃置堆、已放置，实例在它们之间怎么流转；盲注结束怎么整块洗回。
- **层次**：一局、一盲注、一组、一步，各挂哪些状态。
- **同形态判定**要的「形状种类」和形状 id 的关系（七种骨牌 vs 它们的旋转朝向）。

约束：状态要能序列化（见 [局内存档](09-局内存档的形态与时机.md)）；表现层只读，经事件得知变化。

[种子与随机流](08-种子与随机流.md) 已定的前提：实例 id 是整数，本局唯一，只增不复用，要进存档；盲注开始时先按 id 升序排，再洗牌；洗完的列表就是抽牌顺序，下标 0 先抽。见其 Answer「对其它票的约束」。

## Answer

**据此裁定：**

- **方块实例只装跟着块走的永久属性**：`Id`、`Kind`（七值枚举，可改写）、`Points`、`Enhancement`、`Edition`。不存形状 id，不存朝向，不存「在哪个区」。
- **id** 由局上唯一的计数器发，从 1 起，0 留给「空格」。只增不复用，计数器本身进存档。首领预置块这类不属于方块库的实例也从它取号。
- **盘面三层**：占用（`BinaryBoard`）、格 → 实例 id（`int[64]`，0 = 空）、死格掩码。只经 `BoardState` 的两个口子写：落子、清一格。存档只存后两层，占用在读档时重建。
- **`Core/` 五个文件一行不改**。死格挡落子的做法：落子类查询改问一块「占用 | 死格」的影子 `BinaryBoard`。这推翻了 02 研究「补一个重载」的建议。
- **离场**：一块的最后一格被消掉才算离场，从盘上移进消尽堆。一块在盘上还剩几格不另存，从格层数出来。
- **区**：方块库挂在局上；抽牌堆、待放置区、盘上、弃置堆、消尽堆挂在盲注上。库里每块在盲注里恰好在一个区（守恒，单测查）。「盘上」不存列表，从格层推出来。
- **洗回不是一个操作**：方块库从来不会被搬空，盲注状态只按 id 引用它。盲注结束时直接丢掉盲注状态，下一个盲注重建抽牌堆。只在本盲注有效的东西一律挂在盲注上、按 id 记，不挂在块上。
- **旋转**是待放置区槽位的状态，取 0..3，不按朝向数折算。抽到时为 0，落子时作为参数传入，放下后不再保存。
- **同形态比 `Kind`**：朝向不算，镜像算两种。形状一律由 `GetRotated(基准 id(Kind), rot)` 取。
- **层次**：局和盲注各有状态对象。组没有自己的对象，就是待放置区加一个组序号。步不留状态，它是从一个稳定状态到下一个稳定状态的整体事务；旋转不算步。

没有一项会改变目的地或产品形状，全部按授权自裁。类型名是建议，命名空间以 [10 工程形态](10-规则核心的工程形态与跑局测试.md) 为准。

### 1 方块实例

```
BlockInstance               // 只装跟着块走、跨盲注保留的属性
  int           Id          // 本局唯一，> 0
  TetrominoKind Kind        // I O T S Z J L，显式取值 0..6；可改写（§4.3 改形态的改造）
  int           Points      // 点数，就是基础值（§2.1）；永久加点直接改它
  Enhancement   Enhancement // None / Glass 琉璃 / Steel 铁芯 / Gold 金箔 / Wild 万态
  Edition       Edition     // None / Foil 闪箔 / Holo 镭射 / Polychrome 多彩
```

- **不存形状 id**。`Kind → 基准 id` 是一张七项常量表：I 17、O 9、T 10、S 14、Z 18、J 8、L 33（[02 研究](../research/02-可移植面.md) §1.2）。各朝向经 `GetRotated(基准 id, rot)` 取。
  这样改造改形态只改一个字段，不会出现「Kind 是 T、shape id 却是 L」。
- **不存朝向**，见 §4。
- **不存所在区**。区由盲注上的几个有序列表决定（§3），实例上再记一份就成了两份真值。
  block-client 的占用以对局引擎为准、颜色层只是投影，两者在一步中途有意错开，读档还得重投影对齐（`BB/BoardLayers.cs:15-17`）。3B 不重蹈。
- **枚举取值写死**，只追加、不改序。存档里写名字还是写数字，由 09 定。
- 强化、版本本图恒为 None（[05](05-首个可玩盲注的切片边界.md)）。

**id 怎么发：**

- 局上一个计数器 `NextInstanceId`，从 1 开始。唯一的取号口是 `RunState.IssueId()`。0 留作格层的「空」。
- 只增不复用（08）：碎裂、湮灭掉的 id 不回收。读档不能用「最大 id + 1」推计数器，因为最大号那块被毁之后会复用它的号。所以计数器本身进存档。
- 开局建方块库时，按默认库清单的顺序逐块取号。洗牌前要按 id 排序（08），所以**清单顺序加种子**决定了抽牌顺序，清单顺序必须写死。
- 首领预置块、将来「生成一块」的效果，也从同一个口取号。id 在局内唯一，但**不能假设 id 都在方块库里**（05）。
- 计数器只给方块实例用。

### 2 盘面

```
BoardState
  BinaryBoard Occupied   // 占用：判落子、判满线、判清屏。原样用 block-client 的类
  int[64]     Owner      // 格 → 实例 id，0 = 空。下标 = row*8 + col，row 0 在上、col 0 在左
  ulong       Dead       // 死格。位布局与 BinaryBoard 相同；本图恒为 0
```

- **不变式**（单测在每步之后断言）：
  - `Occupied` 某一位为 1，当且仅当 `Owner` 该格非 0；
  - `Dead & Occupied == 0`。
- **只有两个写口：**
  - `Place(instance, rot, col, row)`：沿原始朝向逐格遍历，经 `RotateCell` 转到 rot 档（照抄 `BB/BoardHandDealer.cs:121-141`），**在同一个循环里**写 `Owner` 和占用位。
    不调 `BinaryBoard.PutBlock`，免得掩码一路、逐格一路各算一遍。
    返回的 4 格按块内序号（原始朝向行优先）排列。表现层要用块内编号时从这里拿，盘面不另存。
  - `ClearCell(cell)`：清 `Owner` 和占用位，返回原来的实例 id；空格返回 0。这是借 `BoardLayers.ClearCellAt`（`BB/BoardLayers.cs:90-98`）的做法，行列交叉的格因此只算一次。
    死格不会被清，因为它根本不在满线里。
  - **不许调 `CanClearRowCols(doClear: true)`**：它只清占用、不清格层。找满线只用 `doClear: false`，清格一律走 `ClearCell`。
- **死格怎么挡落子**：
  - 落子类查询（`CanPutBlock`、`CanPut`、`CanPutAnyRotation`、`GetCanPutPoss`）一律问一块影子 `BinaryBoard`，它的占用是 `Occupied | Dead`。`Dead == 0` 时直接问 `Occupied`。
  - 满线判定只问 `Occupied`，死格自然算空洞（规则 §3.3）。清屏判定看 `Occupied` 是否为空，死格自然不算方块。
  - 这样 `Core/` 原样拷、一行不改，四个查询全部白得。02 研究建议「补一个带 blocked 掩码的重载」，那得给四个方法各补一个。
- **置死格只留钩子**：`SetDead(cell)`，只允许在空格上置，否则就破坏不变式。本图只有单测调它。占着块的格变成死格怎么处理，等有死格来源的票再定。
- **两套下标别混**：数组按 `row*8 + col`；掩码按 `BinaryBoard` 的位布局，最左列是行内最高位（`BB/Core/BinaryBoard.cs:4, 48`）。换算只写在一个助手里。
- **存档只存 `Owner` 和 `Dead`**，`Occupied` 读档时从 `Owner` 重建。磁盘上只有一份真值。

**离场：**

- 一块放下后就在「盘上」，直到它的最后一格被消掉才离场，移进消尽堆。
- 一次消除让几块同时离场时，按 id 升序入堆。07 如果要按「最后一格被消的先后」排，改这一句即可。
- 一块在盘上还剩几格不另存，扫一遍 `Owner` 数出来，只有 64 格。
- 半消的块在盲注结束时照样整块回库，被消掉的格不损伤方块（已补进规则 §2.1）。

### 3 区与流转

| 区 | 挂在 | 形态 | 进 | 出 |
|---|---|---|---|---|
| 方块库 | 局 | `List<BlockInstance>`，按 id 升序（只追加，天然有序） | 开局建库；以后由商店、效果加块 | 碎裂、湮灭（本图没有） |
| 抽牌堆 | 盲注 | `List<int>`，下标 0 先抽 | 盲注开始：库按 id 排序后洗牌（08） | 发组 |
| 待放置区 | 盲注 | 定长 `TraySlot?[每组块数]`，槽里是 `(id, rot)` | 发组：从槽 0 起依次填，库里不够就留空槽 | 落子、弃置：该槽置空，别的槽不挪 |
| 盘上 | 盲注 | **不存**，就是 `Owner` 里出现的 id，按 id 升序枚举 | 落子 | 最后一格被消 |
| 弃置堆 | 盲注 | `List<int>`，按弃的先后 | 弃置 | — |
| 消尽堆 | 盲注 | `List<int>`，按离场先后 | 离场 | — |
| 盲注临时块 | 盲注 | `List<BlockInstance>` | 首领预置块（本图没有） | 随盲注状态一起丢弃 |

- **守恒**：盲注进行中，方块库和临时块里的每个 id，恰好在抽牌堆、待放置区、盘上、弃置堆、消尽堆其中之一。单测在每步之后查。
- **待放置区不挪位**：放掉中间那块，两边的不动，界面上的槽位就是稳的。槽全空了才发下一组（规则 §2.2）。
  命令和事件都只用 id 指块，不用槽号。
- **洗回**：方块库从不被搬出去，盲注状态只按 id 引用它。盲注结束（本图里也就是一局结束）直接丢掉整个盲注状态；下一个盲注开始时，再从方块库重建抽牌堆。
  「整块洗回」于是不用写任何代码，也不会有块漏在某个区里没回来。
- **永久的改块，临时的挂盲注**：
  - 永久改动（强化、版本、形态、永久加点）直接改方块库里的实例。
  - 只在本盲注有效的（比如 §4.3.1 强铸改造「本盲注内有效」、首领对块的削弱）挂在盲注状态上、按 id 记，盲注状态一丢就没了。
  - 对比 Balatro 1.0.1o：首领的 debuff 直接写在牌上，盲注结束要逐张调 `set_debuff(false)` 撤回（`blind.lua:624-651`），漏撤就会带进下一个盲注。
  - 本图两样都没有来源，这里只定放在哪。
- **碎裂、湮灭**（本图没有）：从方块库和它所在的区一起删掉，id 不回收。

### 4 旋转

05 已定：旋转是手上这块的状态，落子时作为参数传入，朝向进存档。本票补三点：

- **rot 取 0..3，不按朝向数折算**。I、S、Z 的 rot 2 和 rot 0 形状相同，但逐格转出来，块内编号是倒过来的。
  不折算，表现层连转两下看到的就是转了 180°，不会跳回原样。只有判「怎么转都放不下」时才按朝向数截断，`CanPutAnyRotation` 本来就是这么做的。
- **抽进待放置区时 rot = 0**。放下之后不再保存朝向（格已经写进盘面），回库也不带朝向。
- **改朝向是一个不算步的命令** `SetRotation(id, rot)`：只改槽里的 rot，不加步数、不碰随机流、不吐事件（调用方自己知道转了）。
  落子命令仍然带 rot 参数，以参数为准。改朝向之后什么时候存档，由 09 定。

### 5 同形态与形状

- 同形态比的是被消各格所属块的 `Kind`。**朝向不算**：竖放和横放的 I 是同一形态。**镜像算两种**：S 与 Z、J 与 L 不同。已补进规则 §3.3。
- 比的是消除那一刻各块的 `Kind`。现在改形态的改造只作用于待放置区的块（§4.3.1 凝方、刃凝、环凝、棱隅），放下的块形态不会变。
  将来如果有效果改盘上块的形态，格子的占位不变、只改判定口径，到时候再看要不要另裁。
- 同形态判定做成一个函数：输入被消各格的 owner，输出是否同形态。万态「参与任意形态」以后只改这一处。

### 6 层次

| 层 | 状态 | 进存档 |
|---|---|---|
| 局 `RunState` | 种子文本、各随机流（08）、`NextInstanceId`、方块库、消除类型等级（11 项，本图恒为 1，计分查表要读它）、基因栏（空列表，计分管线要遍历它）、当前盲注 | 全部 |
| 盲注 `BlindState` | 规格（段、层、目标分、弃置次数、每组块数；开局拷进来，之后不变）、抽牌堆、待放置区、盘面、弃置堆、消尽堆、临时块、剩余弃置、连击、累计分（数值类型归 07）、步数、组序号、结局（进行中 / 胜 / 负）与失败原因（预算耗尽 / 放不下） | 全部 |
| 组 | 没有单独的对象：就是待放置区，加上盲注上的组序号 | 随盲注 |
| 步 | 不留状态。一步（落子或弃置）是从一个稳定状态到下一个稳定状态的整体事务，结果对象归 07。中途态不会出现在状态里，所以存档只可能落在两步之间 | — |

- **局上不放金钱、利息**（05 已定）。等级和基因栏要放，因为本图的计分管线就要读它们，只是恒为初值。
- **段、层**：本图唯一的盲注是第 1 段第 1 层，随机流的键 `shuffle@1.1` 由它拼出来（08）。
- **步数**：每完成一步加 1，从 0 起。事件、存档对账、跑局测试的逐步比对都用它。
- **组序号**：每发一组加 1。

### 7 对序列化与表现层的约束

- **对象之间只用 id 引用**。盲注里的各区只存 id，实例对象只存在方块库和临时块这两个列表里。存档是一棵树、没有环，读档时按 id 重新连起来。
- **不靠字典遍历序**。要遍历的一律是有序列表；按 id 查的字典在读档时现建，不进存档，也不拿来遍历。
- **派生量不进存档**：占用掩码、盘上集合、一块剩几格。
- **能深拷贝**：`RunState.Clone()` 拷全部，也就是几个数组和列表，很便宜。跑局测试的落子策略试走一步、对拍同一局，都靠它。
  拖动预览用不着拷：它只算到定类型（05），是只读查询。
- **表现层只拿只读视图**（`IReadOnlyList`、只读的盘面接口）。改状态只经命令，得知变化只经事件，事件内容归 07。

### 为什么不是别的做法

- **死格并进 `BinaryBoard`，或者在格层里用哨兵值表示**（02 研究提的另一条路）：死格要「挡落子、不算满」。并进占用，满线判定就会把它当满；用哨兵值，满线判定还是得认它，都要改核心。影子盘不改核心就能做到。
- **实例上记 `Zone` 字段**：查「在哪」快一点，但和各区列表成了两份真值。区列表又必须有序（抽牌顺序、槽位），这一份省不掉。
- **待放置区用变长列表、放掉一块就前移**：槽号会变，界面要跟着挪，用槽号指块的命令也会指错。
  定长、带空槽，与 block-client 三槽的做法一致（`BB/BoardHandDealer.cs:25, 148`）。
- **盘上的块也存一个列表**：要和格层同步，还是两份真值。扫 64 格的代价可以忽略。
- **每格再存块内序号**：3B 的点数、强化、版本都按块，不按格，没有规则读它。要用时从落子结果里拿。以后真要进盘面，加一层、升存档版本即可。
