# 14 · 文本 key 表的接法

Type: wayfinder:grilling
Status: resolved
Claimed by: text-key-table
Blocked by: 04

## Question

依 [本地化文本表的载体](04-本地化文本表的载体.md) 的调查，定：用哪个载体、key 怎么命名、表放哪、运行时怎么切语言、
规则核心吐的是文本 key 还是枚举（规则核心不该碰文本）、字体怎么配。

本图只接战斗界面这一批文本，但规则要能给后面全游戏用。

## Answer

**据此裁定**：自建 key 表，格式用 Luban 文本表的 JSON；GameLogic 里放一个查表服务和一个绑定组件。
规则核心只吐枚举和数，枚举到 key 的映射放在表现层一个不依赖引擎的文件里。dotnet 测试把这个映射、文本表和预制体放在一起核对。
文字一律用 TMP，字体先用思源黑体 SC Bold 做一个 TMP 动态字体资产。

这张票只定工程口径，规则文档不用改。下面八条各附依据，要推翻哪条只改那一条。
（wayfinder 要求的 domain-modeling 技能本机没有，只按 `.agents/skills/grilling` 裁。）

### 1 载体

裁定：用研究 04 的方案 A。不提前接 Luban（那是阶段 5 的事），不搬 I2，也不用 Unity Localization。

依据：
- A 的成本最小。表格式就是 Luban 的 `l10n` 文本表，阶段 5 不用迁移：研究 04 附录实测过，同一个文件既能当 `TbText` 表，又能当 `text` 字段的校验源。
- B 要把阶段 5 的全套接入件提前做，运行时那层照样得自己写。
- C 的授权没核实。
- D 和 YooAsset 是两套资源系统。

### 2 表放哪、长什么样

- **文件**：整个游戏只用一个 `Demo/Assets/AssetRaw/Configs/l10n/texts.json`，它既是源文件也是运行时资产。
  - YooAsset `Configs` 组的收集过滤现在是 `'*.bytes'`（`Assets/Editor/AssetBundleCollector/AssetBundleCollectorSetting.asset`），要改成也收 `*.json`。
  - 寻址规则是 `AddressByFileName`，所以文件名本身就是地址，同组里不能再有重名文件。
- **格式**：JSON 数组，每条是 `{"key": …, "zh": …, "en": …}`。
  - **一行一条，按 key 的字典序排**。两个槽位同时加文本时冲突最少，diff 也好读。
  - `zh` 指简体中文。以后加语言就加列（如 `zh_hant`、`ja`）。
  - 列名只用 ASCII 小写标识符，因为阶段 5 它们要当 Luban bean 的字段名。
- **收什么**：只收玩家看得到的文本。
  - 日志、异常信息、只给开发者看的调试界面都不进表。
  - 主界面的「3B」「BLACK BLOCK」是字标，也不进表。
- **不写富文本标签**：表里只放文字和占位符，颜色、字号由界面决定。
  阶段 5 的基因描述要行内着色时，再定标记写法。
- 依据：
  - 本图只有几十条文本，一个文件就够。分不分文件，等接 Luban 时按表源的组织方式再定。
  - 放在 `Demo/` 下，是因为槽位只检出 `Demo/` 和 `新游戏/`。
  - 阶段 5 这个文件的去留由接 Luban 的票定：可以继续读这份 JSON，也可以把源文件挪进 Luban 的 `Datas/`、运行时改读 `TbText` 的 bin。两条路查表 API 都不变。

### 3 key 命名

- **字符**：小写 ASCII 字母、数字、下划线，段与段之间用 `.` 隔开，至少两段。正则是 `^[a-z][a-z0-9_]*(\.[a-z0-9_]+)+$`。
- **首段是域**，有三种形态：

  | 形态 | 用途 | 例 |
  |---|---|---|
  | `ui.<界面>.<元素>` | 界面上的固定文案 | `ui.battle.discards_left`、`ui.common.confirm` |
  | `<规则概念>.<值>.<属性>` | 规则核心枚举的显示文本 | `clear_type.full_clear.name`、`defeat_reason.no_space.desc` |
  | `<表>.<行 id>.<字段>` | 阶段 5 起配置表里的名称和描述，Luban 的 `text` 字段存的就是它 | `gene.<id>.name` |

  - 「值」这一段取枚举成员名的 snake_case，例如 `FullClear` 写成 `full_clear`。
  - 「属性」这一段（`.name`、`.desc`、`.title`）必须写。这样以后加描述时，旧 key 不用改名。
- **整句一个 key**：参数用 `{0}`、`{1}` 占位，交给 `string.Format`。
  - 同一条的 zh 和 en，占位序号的集合必须相同。
  - **代码里不拼句子片段**，因为不同语言的语序不同。
- **key 不跟着文案改**：只有意思变了才换新 key，同时删掉旧的。
- **数字转字符串**：分数这类数字转成文字时，一律用 `CultureInfo.InvariantCulture`，不跟随系统区域。否则德语系统会把 1000 显示成 1.000。
- 依据：
  - 首段分域，按 key 排序后，同一界面、同一概念的条目会挨在一起。
  - 属性段必写，是给基因描述留的位置。
  - 占位序号一致这条可以机检，见第 8 条。

### 4 规则核心吐什么

- 裁定：规则核心只吐**枚举和数**，比如消除类型、失败原因、分数、剩余预算、剩余弃置次数。
  它的结构化事件里不带任何显示用的字符串，它也不知道 key 的存在。
- **枚举到 key 的映射**集中写在 GameLogic 的一个文件里（暂名 `TextKeys.cs`），内容有两类：
  - 界面固定文案的 key 常量；
  - 每个需要显示的枚举各一个 `Of(…)`，把枚举值映射成 key。
- **这个文件不得引用 UnityEngine**。dotnet 测试工程会把它链接进去一起编译，一旦引了引擎就编不过，约束自己就能把关。
- 依据：
  - 这是研究 04 §6 最后一条的推荐。
  - 规则核心要在 dotnet 里批量跑局（工程计划），不该背表现层的命名。
  - 映射集中在一处，测试才能遍历「每个枚举值都有 key」。

### 5 运行时查表与切语言

- **查表服务**放在 GameLogic，暂名 `TextTable`。
  - 启动时、打开主界面之前，经 `GameModule.Resource` 同步读 `texts.json`。PC 离线模式下可以同步加载。
  - 用 Newtonsoft 解析，manifest 里已经有了。内存里只留当前语言那一列。
  - 提供 `Get(key)` 和 `Format(key, args)`。查不到的 key 返回 key 本身，每个缺的 key 只警告一次。
  - 提供 `Current` 和 `SetLanguage(lang)`。切换之后，触发服务对象上的 `event Action LanguageChanged`。
- **通知路径**：按 `Demo/.claude/references/tengine/event-system.md`「选哪条通知路径」里「服务模块 → 订阅它的 UI」那一行走。
  窗口里用 `UIPanelMono.AddServiceEvent` 登记。不走 `GameEvent` 总线，也不新开事件 ID。
- **绑定组件**暂名 `LocalizedText`，挂在 TMP 文字节点上，序列化存一个 key。这个字段的名字要定死，因为测试要扫它。
  - `OnEnable` 时设一次文字并订阅，`OnDisable` 时解绑。它是裸 Mono 部件，按规约要手写成对解绑。
  - 静态文案都用它。动态文案（分数、剩余预算、带参数的句子）由持有它的窗口在同一个事件里重绘。
- **热切换**：切语言不重启游戏，也不重开窗口。
  - 全游戏的规则是：**切换发生时开着的窗口**必须响应 `LanguageChanged`；切换后才打开的窗口，打开时按当前语言画就行。
  - [切片边界](05-首个可玩盲注的切片边界.md) 已定本图只在主界面切语言，所以本图只有主界面要订阅，战斗界面和结果浮层不用订阅。
  - 以后战斗中能打开「选项」时，战斗界面再补订阅。
  - `LocalizedText` 不受这条影响，任何时候都订阅。
- **默认语言**：第一次启动时看 `Application.systemLanguage`。`ChineseSimplified`、`ChineseTraditional`、`Chinese` 进 zh，其余进 en。
  - 繁体也进 zh，是因为现在还没有繁体列，简体比英文更接近。
  - 接 Steamworks 之后，改成优先取 Steam 客户端的语言设置。这不在本图。
- **存在哪**：存在玩家设置里，不进局内存档，因为它不属于某一局。
  - 用 TEngine 的 `Utility.PlayerPrefs`，存语言代码字符串（`"zh"` / `"en"`），不存序号。
  - 阶段 5 做「选项」界面时，如果设置改存成文件，这一项跟着搬过去。
- **切换入口**：主界面的「语言」按钮，规则 §8.1 已经列了这个按钮。点它在中英之间来回切。
  本图验收要能看到两种语言，这是最小的入口。主界面现在只有字标，按钮要新加。
- 依据：
  - PC 离线模式可以同步加载。
  - 通知路径照工程现有的规约走，不再加一套。
  - 语言选择是跨局的偏好，研究 04 §6 已经指出它不属于局内状态。

### 6 文本组件：TMP

- 裁定：
  - 所有新界面都用 `TextMeshProUGUI`，对应生成器的 `m_tmp` 前缀，不再新建旧版 `Text`。
  - 移植 block-client 的战斗表现层代码时，把 `Text` 换成 `TMP_Text`。两者 `.text` 的用法一样，只换类型。
  - 本图的战斗界面照 [战斗界面线框](13-战斗界面线框.md) 新搭预制体。
- 依据：
  - Unity 6 已经把旧版 `Text` 标成 Legacy。
  - 分数跳字、消除类型名要描边、发光和缩放，用 SDF 才清晰。
  - `GameLogic.asmdef` 已经引用 `Unity.TextMeshPro`，UI 脚本生成器也支持 `m_tmp`。
  - 移植的代价只是把类型换一下。

### 7 字体

- **字源**：思源黑体 SC Bold，OFL 1.1 授权。
  - 直接取 block-client 的 `Assets/AssetRaw/Fonts/GBK.otf`，研究 04 §4.2 确认过就是这套字体。
  - 改名为 `SourceHanSansSC-Bold.otf`，放进 `Demo/Assets/AssetRaw/Fonts/`。
  - 同目录放 OFL 许可全文，随包分发时必须附带。block-client 里没有这份文件，要从 Adobe 的 source-han-sans 仓库取 LICENSE；下载前先经用户同意。
  - 只带这一个字重。阶段 5 出现长描述后，再看要不要补 Regular。
- **主字体资产**：用这套字做一个**动态** SDF 的 TMP 字体资产，打开多图集，同样放在 `AssetRaw/Fonts/`，作为工程的主字体。
  - 中英文都用它，思源黑体自带拉丁字形，所以切语言不用换字体。
- **挂法**：**每个 TMP 组件直接引用主字体资产，不改 `TMP Settings` 的默认字体。**
  - 默认字体放在 `Resources/` 下。如果把它改成主字体，主字体会在 Resources 和 YooAsset 的 Fonts 包里各出一份，运行时也会有两个各自独立的动态图集。这是研究 04 §4.3 的推断，没实测过。
  - 新建的 TMP 组件默认挂的是 LiberationSans，漏改的话中文会显示成豆腐块。这由第 8 条的测试拦。
- **动态还是静态**：本图用动态图集，加字不用重新烘焙。
  - 首发前如果要压包体，或去掉第一次出字时的卡顿，可以改成静态图集，字表从 `texts.json` 里取。这不在本图。
  - `TMP Settings.asset:25` 已经是 `m_ClearDynamicDataOnBuild: 1`。
  - 动态字体资产在编辑器里会被写脏，可能被带进提交。执行票要核实并处理。
- **像素中文字体不在本图定**。
  - 那是美术方向的事，而正式美术不在本图范围内。留给用户在定美术风格锚时决定，字体授权必须允许商用。
  - 上面的挂法保证换字体只动主字体资产这一处：TMP 的字体资产生成器可以覆盖已有资产，引用不会断。
- 依据：思源黑体本地就有，授权干净，字符覆盖全。只有一个主字体资产，就只有一个替换点。

### 8 校验

在 dotnet 测试里跑，客户端自检带上这一道。它要读三样东西：`texts.json`、链接编译进来的 `TextKeys.cs`、`Assets/AssetRaw/UI/` 下预制体的 YAML。查五件事：

1. key 合规（第 3 条的正则）、不重复、按字典序排列；
2. 每条的 zh 和 en 都不为空，`{n}` 占位的序号集合相同；
3. `TextKeys` 里的每个常量、每个枚举值经 `Of(…)` 得到的 key，都在表里；
4. 预制体里 `LocalizedText` 存的每个 key 都在表里；
5. 预制体里 TMP 组件用的字体都是主字体资产，按 GUID 比对。

「表里有、但没人用」的孤儿 key 不查，因为静态扫描扫不全。阶段 5 接 Luban 后可以用 `text-list` 补上。

依据：这五项都不需要 Unity，可以和规则核心的单测在同一道里跑。
1–4 就是研究 04 §5 的第 4 步；第 5 项是为了抵消「不改 TMP 默认字体」带来的风险。
