### 代决策（轻量无人值守，依据附后）

- **判线定类型在写盘之前做**：落子一步先调 `ResolveClear`（就是预览那个只读函数），再写盘。它在 `BinaryBoard` 的拷贝上 `PutBlock` 后问 `CanClearRowCols(false)`，满线判定仍只有 Core 这一处。被消格里落子前是空的格就是这块自己的格，不用另算落点。
- **`ClearResolution.Type` 是 `ClearType?`**，不成线或放不下时为 null。没给 `ClearType` 加 `None`：那个枚举进存档，加值就是改存档形状。
- **结算前、结算后、步收尾三个挂点问谁**：07 只给了逐格和基因段的次序。定成「有格被消的块，按被消格顺序里第一次出现的次序，各问强化、版本；然后基因从左到右」；步收尾只问基因（弃置、没消除时没有被消的块）。强化、版本为 None，或注册表里没登记的，不问。规则写在 `EffectContext` 的类注释里。
- **上下文里还没有改状态的方法**（改等级、碎裂、改基因计数）：本图没有可改的状态，类型表也只有 1 级，加了也没有用例能验。三个改状态的挂点现在是 void、上下文只读；阶段 5 第一个真效果来时，在上下文上加方法、由管线吐对应事件（07 §5 已定这个形态）。
- **`EffectDelta` 的 `default` 是「无效果」**：独立倍率存成相对 ×1 的偏移，不会因为漏写而 ×0。乘项为负、重触发次数为负都抛异常（效果写错了）。
- **独立倍率与单个乘项都按 `XMultCap = long.MaxValue / 1000` 截**：这就是 07 §6 说的「不让中间积溢出的上限」，⌊x·y/1000⌋ 拆成 (x/1000)·y + ⌊(x%1000)·y/1000⌋ 时后一项不会溢出。约合 ×9.2 万亿，玩不到。
- **注册表交给 `RuleConfig` 时封住**：`PlaceholderTuning.Config` 是静态共享的，往里登记测试替身会串到别的用例。查表用以 `(EffectSource, int)` 为键的字典，只查不遍历。
- **`LibraryEntry` 加了强化、版本两个可选参数**：单测要「把库里几块的强化设成对应枚举」，只走公开 API 就得从开局清单给。默认库全是「无」。
- **`RunState.AddGene(geneId)`** 是公开的基因钩子，本图只有单测调用，口径同 `SetDead`；槽数上限、买卖、换位归阶段 5。
- **开盲注的事件**：`BlindStarted` → `GroupDealt` →（判负时）`BlindEnded`，没有 `StepEnded`（不算步）。`BlindStarted.DrawLeft` 是发第一组之前的块数。开盲注不判胜，照 07 §4。
- **被拒的先后**：落子是 BlindOver → NotInTray → CannotPlace（rot 不在 0..3 也算 CannotPlace，不抛）；弃置是 BlindOver → NotInTray → NoDiscards。还没开盲注时也是 BlindOver。
- **事件成员补的两处**：07 写成 `RepetitionGranted{…}` 的定为 `{Source, SourceIndex, Cell, Count}`；`GroupDealt.Slots` 是各槽的实例 id，空槽为 0。
- **`ClearRules.Priority` 公开**：28 的左栏类型表要按优先级排行。`ClearType` 的取值序仍不是优先级（19 已注明）。
- **判负与稳定态共用一个函数** `RunState.PendingFailure()`（internal），段 #16 和 `Validate()` 都调它，两边不会判岔。
- **新目录与文件的 `.meta` 手写**（随机 GUID，形状同 19 提交的那批）。
- 提交信息末尾的 trailer 由 `单仓提交.ps1` 自动补成 `agent-zp`，没有写 Claude 的那一行。
