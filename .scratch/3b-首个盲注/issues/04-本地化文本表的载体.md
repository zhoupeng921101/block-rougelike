# 04 · 中英文本表在本工程里的载体

Type: wayfinder:research
Status: resolved

## Question

工程计划：「文本一律走 key 表，首发中英双语」。战斗界面的文本（消除类型名、分数、剩余预算、弃置次数、胜负提示）是第一批要过 key 表的。
`Demo/` 里现在有什么能用？

要查的事实：

- Demo 带的 TEngine 有没有本地化模块（Localization、TextKey 之类），怎么加载、怎么切语言、和 TextMeshPro 怎么接。
- block-client 怎么管文本：走 Luban 表、TEngine 模块，还是 `SubBoardPureBoardTexts.cs` 这类代码常量；有没有切语言。
- Luban 的本地化支持；工程计划说 Luban 配置程序集推迟到第一张表才建，`TEngine/Luban` 菜单里的路径还指着 `UnityProject/`。
- 字体：中英双语的 TMP 字体资源 Demo 现在有没有。

产出：可选载体及各自的接入成本，附出处。只读调查。

## Answer

**Demo 里没有现成载体。表、运行时查表、切语言、中文字体，四样都要补。**

- **TEngine**：Demo 带的 6.0.0 没有本地化模块（`GameModule.cs:12-77`）。上游有一个，是 I2 Localization 改了命名空间的版本，block-client 拷框架时就剪掉了。
- **block-client**：没有本地化。中文硬编码在各模块的 `*Texts.cs` 里（如 `TimedOrderTexts.cs:3`、`SubBoardPureBoardTexts.cs`），没有切语言，没有英文。表里的文本字段也是直接写字。
- **Luban**：Demo 里没有工具、表源、运行时库，`TEngine/Luban` 菜单还指着 `UnityProject/`。
  block-client 那份实测过（版本不明，gitignore 掉了）。它能做三件事：`text` 字段的 key 校验（`l10n.textProviderFile`）、`text-list` 导出、同一个 JSON 同时当表和校验源。
  **它做不到**：导出时把 key 换成原文、运行时查表、切语言。生成的代码里就是 `string`。
- **字体**：Demo 的 TMP 只有 LiberationSans，一个汉字都没有。启动器字体是思源黑体的 679 字子集，缺「弃预胜利倍率盲」等字。
  block-client 用整套思源黑体 SC Bold（`GBK.otf`，17MB，OFL），配旧版 UGUI `Text`，0 个 TMP；它的战斗表现层也全是 `Text`。
- **载体与成本**：
  - A：自建 key 表 —— 小；
  - B：现在就接 Luban —— 中到大，而且还得再写 A 的运行时那层；
  - C：搬上游 I2 模块 —— 中，授权待核；
  - D：Unity Localization —— 大，要走 Addressables，和 YooAsset 打架；
  - E：代码常量 —— 违反工程计划。
- **推荐 A**：表格式直接用 Luban 文本表的 `[{key, zh, en}]` JSON，放 `AssetRaw/Configs`（收集规则加 `*.json`）。
  GameLogic 里写查表、切语言事件和绑定组件；规则核心的 dotnet 单测读同一份 JSON 查漏。
  阶段 5 接 Luban 时，这个文件登记成 `TbText`，同时当校验源，不用迁移。
- **字体**：先补思源黑体 SC。用 TMP（动态或静态）还是旧版 `Text`、要不要像素中文字体，交给 14 号票定。
- **范围外**：启动器 `LoadText.cs` 是写死的中文，跑在热更之前，首发双语要单独处理。

详细记录见 [04-本地化载体](../research/04-本地化载体.md)。
