## 结论

**Demo 里没有任何现成的本地化载体，四样都要自己补：表、运行时查表、切语言、中文字体。**

- TEngine（Demo 带的 6.0.0）**没有本地化模块**。上游 TEngine 有一个，是 I2 Localization 改了命名空间的版本，block-client 拷框架时就剪掉了，Demo 跟着没有。
- block-client **没有本地化**：文本是中文硬编码，集中在各模块的 `*Texts.cs` 静态类里。没有切语言，也没有英文。
- Luban **Demo 里一件都没有**：没有工具、表源、运行时库、配置程序集。block-client 那份 Luban 实测过：`text` 类型只做「key 存不存在」的导出期校验，生成的代码里就是普通 `string`。**运行时按 key 查、切语言，Luban 都不管。**
- 字体：Demo 现有字体**都打不出战斗界面的中文**。TMP 只有 LiberationSans（纯拉丁）；启动器字体是思源黑体的 679 字子集，「弃预胜利倍率盲」这几个字都缺。block-client 用的是整套思源黑体 SC Bold（17MB），配旧版 UGUI `Text`，没拷进 Demo。

**推荐：本图自建一个轻量 key 表**（下文方案 A）。
表文件**直接采用 Luban 文本表的格式**（`key / zh / en` 的 JSON 数组）。
阶段 5 接 Luban 时，同一个文件既当 `TbText` 表，又当 `text` 字段的校验源。这条已用 block-client 的 Luban 实测可行（§附录）。
这样载体不用迁移，运行时 API 也不变。字体先补一套思源黑体 SC（OFL）。用 TMP 还是旧版 Text，交给 14 号票定（§4）。

### 4.3 字体的接入成本

- **最少要做的**：在 `Assets/AssetRaw/Fonts/` 放一套能打中文的字体。思源黑体 SC 是 OFL，可以随商业包分发；block-client 的 `GBK.otf` 就是它。
- **旧版 Text**：字体文件直接拖上组件就能用（block-client 的做法），几乎零成本。缺点是没有 SDF 的描边、发光、清晰缩放，而且 Unity 6 已经把它标成 Legacy。
- **TMP**：要在编辑器里生成字体资产，有两种：
  - **动态**：随包带源字体，运行时往图集里填字。中文要开多图集（`m_IsMultiAtlasTexturesEnabled`）。
  - **静态**：按字表预烘图集。key 表能把全部用字列出来，正好喂给字表。
  - 建议挂在拉丁主字体的 fallback 上。
  - 注意：`TMP Settings.asset` 在 `Resources/` 下，它引用的字体会被打进包体的 Resources；同一字体如果又在 YooAsset 包里，就会出两份。CJK 字体最好只让 prefab 引用，或在运行时加进 fallback。这是 Unity 打包的通用行为，**本工程没实测**。
- **像素风**：规则 §8 的美术方向是太空像素风。要不要换成像素中文字体（且必须 OFL 之类可商用授权），是美术侧的选择，不阻塞本图。
- **启动器不在战斗文本这一批里**：`Launcher/Scripts/LoadText.cs:5-59` 是写死的中文，有 JSON 覆盖钩子，但调用处传的是 `null`（`Launcher/Procedure/ProcedureInitPackage.cs:39`）；字体是 LauncherFont 子集。启动器在热更程序集之前跑，用不上 GameLogic 里的 key 表。首发双语要单独处理它，不在本图范围。

### A 的接入步骤（推荐方案的展开，key 命名和表位置由 14 号票定）

1. **表文件**：`Assets/AssetRaw/Configs/` 下放一个 JSON 数组，每行 `{"key":…, "zh":…, "en":…}`。这就是 Luban `l10n` 文本表的格式。
   - 收集规则：`Configs` 组的 `UserData` 从 `'*.bytes'` 改为 `'*.bytes|*.json'`；或者另开一个收集组。
2. **查表**：GameLogic 里放一个静态类，提供：
   - 启动时经 `GameModule.Resource` 读 `TextAsset`，Newtonsoft 已在 manifest 里；
   - `Get(key)`、`Format(key, args)`；
   - 缺 key 时返回 key 本身并打日志；
   - 当前语言（默认按 `Application.systemLanguage`，简中进 zh，其他进 en；玩家选过就存本地）；
   - `SetLanguage`，切换后广播一个 TEngine 事件。
3. **绑定**：一个挂在文字节点上的组件，存 key；启用和收到切语言事件时重设文字。动态文本（分数、剩余预算）由持有它的界面在同一事件里重绘。
4. **校验**：规则核心的 dotnet 单测直接读这份 JSON，检查三件事：key 唯一；每行 zh、en 都非空；规则核心每个需要显示的枚举值都有对应 key。不用 Unity。
5. **阶段 5 接 Luban 时**：把这个文件登记为 `TbText` 表，同时作为 `text` 字段的校验源（实测可行）。基因、科技、改造表里的名称和描述用 `text` 类型存 key，导表时 Luban 就会拦下拼错的 key。

## 6. 交给 14 号票的待裁项

- 载体：按上面的推荐，取 A，并锁定 Luban 文本表格式。
- 文本组件用 TMP 还是旧版 `Text`：
  - TMP 的好处：Unity 6 主推，有 SDF 特效，生成器支持 `m_tmp`。
  - 代价：移植 block-client 战斗表现层时要把它的 `Text` 换掉。
- 字体：思源黑体 SC 的哪一字重；TMP 用动态还是静态；要不要像素中文字体（美术）。
- key 命名、表放哪、默认语言规则、语言选择存在哪（玩家设置还是局内存档；它不属于局内状态）。
- 规则核心只吐枚举或结构化事件，由表现层把枚举映射成 key：这条与 A 的 dotnet 校验正好接得上。

|---|---|
| 不带 l10n 参数 | 日志「option: '-x l10n.textProviderFile=<textProviderFile>' not found, text validation is disabled」；导出原样 |
| `-x l10n.textProviderFile=*@Datas/l10n/texts.json -x l10n.keyFieldName=key` | 报「记录 "TbItem[2].name":"item.missing.name" … 不是一个有效的文本key」，退出码 0 |
| 同上加 `--validationFailAsError` | 「encounter some validation failure. exit code: 1」 |
| 加 `-x l10n.languageFieldName=en -x l10n.convertTextKeyToValue=1 -x l10n.textFile.languageFieldName=en` | 导出的 `name` 仍是 key，**没有替换** |
| `-d text-list -x l10n.textListFile=texts.txt` | 输出两行 key |
| `-c cs-bin` | `Item.Name` 生成为 `public readonly string Name`，读 `_buf.ReadString()` |
| 表和校验源指向同一个 `texts.json` | 两者都正常，`tbtext.json` 导出 1 行 |

上游对照：[Luban l10n 文档](https://www.datable.cn/docs/quality/l10n)、[`DefaultTextProvider.cs`](https://github.com/focus-creative-games/luban/blob/main/src/Luban.L10N/DefaultTextProvider.cs)（main 上已有 `convertTextKeyToValue` 和 `TextKeyToValueTransformer`）。
