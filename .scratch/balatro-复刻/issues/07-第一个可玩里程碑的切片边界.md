# 第一个可玩里程碑的切片边界

Type: wayfinder:grilling
Status: resolved

## Question

全量是 150 小丑 + 22 塔罗 + 幽灵牌 + 优惠券 + 牌组 + 标签 + 28 个 Boss 盲注
+ 20 个挑战 + 补充包 + 强化/版本/蜡封。一次做完不现实。第一个**可玩**的切片切到哪？

切法候选：

- **纵切**：一副基础牌组、完整出牌结算、Ante 1–3、小丑池只放 5 张、商店只卖小丑。
  最快摸到「能玩」，且四条轴都能在小范围内验收一遍。
- **横切**：结算管线做全（含所有强化、版本、蜡封），内容只放一副牌。
  先把最难的正确性问题解决掉。
- 别的切法。

切片边界要**同时**满足四条轴的验收——切出来的东西必须能对拍、能看出外观对不对，
否则里程碑不成立。

**阻塞已解除**——[Lua 到 TS 的翻译策略](03-Lua到TS的翻译策略.md) 裁定走直译，含事件队列。
切片因此不是「先写哪些模块」，而是「先直译哪一段 Lua、哪些小丑分支先接上」。

## Answer

**纵切到「用红牌组打过 Ante 1 的小盲注」。**

### 里程碑的定义

开局 → 发 8 张手牌 → 选牌出牌 / 弃牌 → 计分 → 累计达到 **300 分** → 过关画面。
达不到 300 就 GAME_OVER。

全部数字已从源码核实：

| 项 | 值 | 出处 |
|---|---|---|
| Ante 1 基数 | **300** | `misc_functions.lua:922` `get_blind_amount`，`amounts[1]` |
| 小盲注倍率 | **×1**（所以需求就是 300） | `game.lua:267` `bl_small.mult = 1` |
| 起手金钱 | 4 | `misc_functions.lua:1855` `get_starting_params` |
| 手牌上限 | **8** | 同上 |
| 出牌次数 | **4** | 同上 |
| 弃牌次数 | **3** | 同上 |
| 牌组 | 红牌组 52 张标准牌 | `配置CSV/P_CARDS.csv` |

### 在范围内

**状态机**：`SELECTING_HAND` → `HAND_PLAYED` → `DRAW_TO_HAND` → 过关/失败。
`BLIND_SELECT` 简化成直接进小盲注，不做选盲注界面。

**要直译的 Lua**：

- `misc_functions.lua:379` `evaluate_poker_hand` —— 牌型判定
- `state_events.lua:592` `evaluate_play` 的第 **3、4、7、9、14** 步
  （牌型判定 / 确定计分牌集合 / 取基础值 / 逐张计分 / 最终乘法）
- `cardarea.lua` 的手牌区：排序、选中、抽牌
- `misc_functions.lua` 的 `pseudoshuffle` —— 洗牌，**这是本切片唯一的 RNG 消费点**
- `card.lua` 里与「牌面筹码」相关的部分（不含 `calculate_joker`）

**要重写的**（按 [03 号票](03-Lua到TS的翻译策略.md)，UI 不直译）：
手牌的 Phaser 呈现、拖拽排序、出牌/弃牌按钮、分数显示。

**RNG 要补的**：`pseudoshuffle`（[01 号票](01-工程骨架落地.md) 里列为「等切片定了再补」的那几个之一）。
`pseudorandomElement`、`randomString`、`sort_id` 计数器**本切片用不到**，继续不写。

### 明确不在范围内

小丑（全部 150 张）、商店、强化牌、版本、蜡封、优惠券、塔罗、幽灵牌、标签、
补充包、大盲注、Boss 盲注、回合结算与金钱收益、其余 17 个牌组、局外解锁。

### 四条轴在本切片的验收手段

| 轴 | 怎么验 | 自动化 |
|---|---|---|
| 机制与数值 | 固定一手牌 → 断言得分。牌型判定逐型写测试 | ✅ 单测 |
| 同 seed 同局 | 固定 seed → 断言洗牌后的 52 张顺序 | ✅ 单测，但**真值待定**（见下） |
| 像素级外观 | 人眼比对截图 | ❌ 只能手工 |
| 音效与音乐 | 人耳 | ❌ 只能手工 |

### 一条要连带处理的

**本切片的对拍真值还没有着落。** 已有的 16 条向量覆盖的是 Boss Blind 选择，
而本切片的 RNG 消费点是**洗牌**，两者不是一回事。

[原版对拍基准能否导出](04-原版对拍基准能否导出.md) 因此从「优先级下调」**回到关键路径**：
要先确认社区工具（Blueprint / balatro4j）能不能吐出指定 seed 的初始牌序。
吐不出来的话，「同 seed 同局」这条轴在本切片内**无法验收**，
里程碑就要么改口径、要么等实机导出。

### 为什么不是别的切法

- **票里原写的「横切：结算管线做全」自相矛盾。**
  15 步里第 6、11、15 步全是小丑遍历，而管线的难度恰恰在小丑。
  零小丑时这三步空跑，等于「把最难的部分做全」却测不到它。
- **「打通整个 Ante 1」太大。** 要商店 UI（`UI_definitions.lua` 6,607 行里的大头），
  还要从 144 个小丑分支里挑出能自洽的一组。留作第二个里程碑。
- **「零 UI 的逻辑层骨架」风险最低但不符合 destination。**
  它确实更稳（逻辑层有外部真值，渲染层没有），但 destination 要的是可玩的复刻件；
  且 shader 风险已由 [Phaser 4 渲染路线 spike](13-Phaser4渲染路线spike.md) 单独覆盖，
  不需要靠里程碑去扛。
