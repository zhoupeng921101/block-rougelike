# 消耗品的切片边界

Type: wayfinder:grilling
Status: resolved

## Question

[15 号票](15-第二个里程碑的切片边界.md) 已交付：带小丑打过 Ante 1，415 个测试绿，
小丑覆盖面 111/150，实测贪心策略能打到 Ante 2–4。

止步原因是**牌型永远 1 级**：需求曲线是 300 → 800 → 2000 → 5000 → 11000，
而 1 级牌型的天花板在几千分。没有星球牌就过不了 Ante 3。

所以下一个大件是消耗品。但「消耗品」不是一个东西，是四个：

- **消耗品槽位**（`consumable_slots = 2`）与 `Run` 上的持有
- **星球牌** 12 张（`level_up_hand`）
- **塔罗牌** 22 张（其中 8 张的效果是给扑克牌加强化）
- **补充包** 32 个 center（商店第三格，会改商店的 RNG 消费顺序）
- 外加**幽灵牌** 18 张（只能从幽灵补充包与 The Soul 来）

切到哪为止？连带要裁定四件事（来自上一轮的交接）：
商店 RNG 顺序怎么补、`soulable` 在商店路径走不走、
09 号票那条「delay 可以压成 0」是否到期、`level_up_hand` 的上下限。

## Answer

### 一、切片边界：**槽位 + 星球 + 塔罗。幽灵牌与补充包不在本票。**

理由是「幽灵牌在本切片里根本拿不到」：

- `G.GAME.spectral_rate` 默认 **0**（`game.lua:2111` 那张权重表里没有它，
  `create_card_for_shop` 里 `G.GAME.spectral_rate = G.GAME.spectral_rate or 0`），
  所以**商店永远不出幽灵牌**。
- 幽灵牌的两个来源是**幽灵补充包**与 **The Soul**，而 The Soul 也进不了商店（见第二节）。
- 所以「不做补充包」自动蕴含「不做幽灵牌」。这两件是同一刀，一起推到 17 号票。

留在本票里的是**通往 Ante 8 的那条必经路**：星球牌把牌型升级，
塔罗牌把商店那 28.6% 的空格填上一半。

**强化牌（`m_bonus` / `m_mult` / `m_wild` / `m_steel` / `m_glass` / `m_gold` / `m_lucky` / `m_stone`）
也在本票内**，这是对交接建议的一处偏离。交接写的是「要强化牌的地方先跳过并登记」，
但 22 张塔罗里有 **8 张的全部效果就是加强化**（Magician / Empress / Hierophant /
Lovers / Chariot / Justice / Devil / Tower），跳过等于塔罗只做了一半，
而且那 8 张会在商店里被买到、买了什么也不发生。
强化牌同时解开 `coverage.test.ts` 里 `强化牌` 那组的 9 张小丑——
它是继消耗品之后第二大的阻塞组。

### 二、`soulable` 在商店路径**不走**——The Soul / Black Hole 出不了商店

这条交接里标成「要确认」，源码里是确定的：

```lua
-- UI_definitions.lua:825
local card = create_card(v.type, area, nil, nil, nil, nil, nil, 'sho')
--                       _type, area, legendary, _rarity, skip_materialize, soulable, forced_key, key_append
```

第 6 个实参是 **`nil`**。`create_card` 的 soulable 分支门口写着
`if not forced_key and soulable and ...`，所以商店路径整段不进，
`pseudorandom('soul_'..type..ante)` 这次掷点**不消费**。

旁证：`get_current_pool` 里有一条无条件剔除
（`common_events.lua:2062`：`if v.name == 'Black Hole' or v.name == 'The Soul' then add = false end`），
所以这两张连池子都进不去。它们**只能**从 soulable 路径来，
而 soulable 只在补充包里传真值 —— 又一条「补充包与幽灵牌是同一刀」的旁证。

### 三、商店的 RNG 顺序：塔罗／星球格**只多一次掷点**，不是 6 次

现在 `shop.ts` 的 `createCardForShop` 在掉到塔罗／星球档时直接返回
`kind: 'unimplemented'`，不消费任何 RNG。接真消耗品之后要补的，
逐条对着 `create_card` 数下来只有 `get_current_pool` 那一次：

| 消费点 | 小丑格 | 塔罗／星球格 |
|---|---|---|
| `rarity<ante>sho` | ✅ | ❌ —— `get_current_pool` 的 rarity 掷点在 `if _type == 'Joker'` 里面 |
| `<Type>sho<ante>` 抽下标 | ✅ | ✅ `Tarotsho<ante>` / `Planetsho<ante>` |
| `..._resample<n>` | ✅ | ✅ |
| `soul_<Type><ante>` | ❌ | ❌ 见第二节 |
| `front<append><ante>` | ❌ | ❌ 只有 `Base` / `Enhanced` 才掷 |
| `etperpoll<ante>` | ✅ | ❌ —— 整段永恒／易腐／租赁在 `if _type == 'Joker'` 里面 |
| `edi sho<ante>` | ✅ | ❌ 同上 |

**所以现在这一版没有分叉**：漏掉的那次掷点用的是 `Tarotsho<ante>` / `Planetsho<ante>`，
是两个独立的 key，`PseudorandomState` 按 key 分记状态，不影响小丑那条链。
补上之后同样只动这两个 key。

塔罗／星球的池子剔除比小丑多两条，两条都改池子的**内容**而不是长度：

- `used_jokers` **对消耗品同样生效**。`card.lua:350` 的标记循环是
  `for k, v in pairs(G.P_CENTERS) do if v.name == self.ability.name then ... end`，
  按**名字**匹配全体 center，不区分小丑与消耗品。
  所以同一个商店里两格不会出同一张塔罗。
  但 `card.lua:4829` 的 `Card:remove()` 里有对称的清除
  （`if not next(find_joker(name, true)) then used_jokers[k] = nil end`），
  牌被用掉／卖掉／离开商店时会还回去——**不是一局只见一次**。
- **星球的 `softlock`**：Planet X / Ceres / Eris 要对应牌型 `played > 0` 才进池
  （`common_events.lua:2044`）。所以新档的星球池实际只有 9 张可用、12 个位置。

### 四、09 号票那条「delay 可以压成 0」——**本切片内仍然成立**

09 号票列了 5 处带 `delay` / `blockable = false` 的消耗品／补充包 RNG 消费。
逐个核到底，本切片实际命中 **1 处**：

| 位置 | 属于 | 本切片命中 |
|---|---|---|
| `card.lua:1312`（delay 0.7） | Familiar / Grim / Incantation 造牌 | ❌ 幽灵牌 |
| `card.lua:1456`（delay 0.4） | Wraith | ❌ 幽灵牌 |
| `card.lua:1472`（delay 0.4） | **The Wheel of Fortune** / Ectoplasm / Hex | ✅ **塔罗** |
| `card.lua:1723` | `Card:open()` 开补充包 | ❌ 补充包 |
| `common_events.lua:397` | `draw_card` 的 `flipped_card` | ❌ 挑战模式 modifier |

命中的那一处**不构成换序**：The Wheel of Fortune 的三次 RNG
（门口的 `pseudorandom('wheel_of_fortune')`、事件里的 `pseudorandom_element(…, pseudoseed('wheel_of_fortune'))`、
`poll_edition('wheel_of_fortune')`）**共用同一个 key**，
在一次 `use_consumeable` 里严格先后、事件按 FIFO 追加在门口那次之后。
一次只能用一张消耗品，中间不会插进别的 `wheel_of_fortune` 消费者。

**裁定：本票继续把 delay 压成 0，不引入虚拟时钟。**
到 17 号票（补充包 + 幽灵牌）时 `card.lua:1723` 与 Familiar 那三张会进范围，
那时再核一次——**这条结论不要带过 17 号票的边界**。

### 五、`level_up_hand` 的上下限——**现在的实现是错的，本票顺手修掉**

`common_events.lua:467`：

```lua
G.GAME.hands[hand].level = math.max(0, G.GAME.hands[hand].level + amount)
G.GAME.hands[hand].mult  = math.max(G.GAME.hands[hand].s_mult  + G.GAME.hands[hand].l_mult *(level-1), 1)
G.GAME.hands[hand].chips = math.max(G.GAME.hands[hand].s_chips + G.GAME.hands[hand].l_chips*(level-1), 0)
```

三件事与 `scoring.ts` 现在的 `levelUpHand` 不一样：

1. **等级下限是 0**，不是无下限。现在的注释写「不做下限保护，原作允许等级降到 0」——
   前半句错了，原作是 `math.max(0, …)`。
2. **倍率与筹码是从基础值重算的，不是增量加减的**。现在是
   `info.mult += l_mult * amount`。只要等级不撞下限，两者等价；
   一撞下限就永久跑偏（`The Arm` 在 1 级时会降到 0）。
3. **倍率下限 1、筹码下限 0**。High Card 是 `s_mult = 1, l_mult = 1`，
   降到 0 级时原作给 `max(1-1, 1) = 1`，现在给 `0` ——**一手牌直接 0 分**。

**没有上限。** 星球牌接进来不改这一条。

今天这个 bug 打不出来，只因为 `blinds.ts:298` 的 `The Arm` 有一条
`if ((context.handLevel ?? 1) > 1)` 的守卫，等级到不了 0。
但那条守卫是 `The Arm` 自己的语义，不是 `level_up_hand` 的保护。
**本票把 `HandInfo` 补上 `s_chips` / `s_mult`，`levelUpHand` 改成重算 + 三个 clamp。**

### 落地顺序

每一步都留一个全绿的仓库，可以单独提交：

```
1. levelUpHand 修正（s_chips/s_mult + 三个 clamp）      —— 不依赖任何新东西
2. 生成器抽 c_ 的 center（tools/gen-consumable-centers.mjs）
3. 消耗品槽位与 Run 上的持有 + 商店真的卖消耗品（补那次掷点）
4. 星球牌 12 张                                        —— 最简单且最急
5. 强化牌 8 种（含 m_glass / m_lucky 的两处 RNG）
6. 塔罗牌 22 张
7. 回填 13 张小丑，删 coverage.test.ts 对应行
```

第 3 步之后「星球牌能买到」就成立了，第 4 步之后 Ante 3 的墙就破了——
**如果中途要停，停在第 4 步之后**。

### 不在本票

- **补充包与幽灵牌** → 17 号票。补充包会改商店的形状（第三格）与 RNG 顺序
  （`packetper` / `packssjr` 两个 key、`soulable` 真的传真值）。
- **优惠券**（voucher）。商店第四格，与消耗品无关。
- **标签 / 跳过盲注**。`coverage.test.ts` 的 `标签` 组，另一刀。

### 两个原先就错的 bug（不是这一轮写出来的）

1. **`levelUpHand` 是增量加减且无 clamp**，原作是从 1 级值重算 + 三个 clamp。
   今天打不出来只因为 `The Arm` 自带 `handLevel > 1` 守卫。
2. **`used_jokers` 的语义一直是错的**：复刻件当「本局见过的，永久剔除」，
   而 `card.lua:4829` 的 `Card:remove()` 有一条对称的清除，
   **重掷商店与离开商店都会走它**。池长度不变但内容窄了，
   `_resample` 的次数对不上 → 同 seed 从第二个商店起分叉。

### 一条推翻本票预设的实测

**星球牌没有把 Ante 3 的墙推倒。** 八个 seed 的贪心深度
2.875 → 3.0，接完塔罗与强化牌之后仍是 Ante 2–4。原因：
商店两格里只有 ~28.6% 是消耗品、其中一半是塔罗，整局买到 1–5 张星球，
而且抽到哪个牌型不由人挑（买到 Two Pair 的星球，策略打的却是同花）。

**原作里星球的主要来源是天体补充包**（一包 3 张、Jumbo 5 张）。
本票的「落地顺序」把补充包放在最后是对的（它会动商店形状与 RNG 顺序），
但**优先级判断错了**——它不是收尾工作，是破墙的那一刀。
→ **17 号票（补充包 + 幽灵牌）是下一个大件。**

### 范围上的两处收窄

- **`The Wheel of Fortune` 没做**（22 张塔罗里唯一一张）：它给小丑加**版本**，
  而版本系统整个不在范围。半实现会掷掉三次点再什么也不发生，所以登记为未实现。
- **消耗品这一刀只解开 8 张小丑，不是交接说的 13 张。** 剩下 5 张要的
  不是「消耗品」而是幽灵牌（`Sixth Sense` / `Seance`）、补充包（`Hallucination`）、
  Negative 版本（`Perkeo`）、补充包定价（`Astronomer`）。
  `coverage.test.ts` 里那一组已经从「消耗品」改名「幽灵与补充包」——
  原来的分组名把阻塞的真实原因说错了。

### 顺手记下、不在本票范围的两个洞

`To Do List` 与 `Mr. Bones` 都是「有 handler 但效果落空」，
而且被 `isJokerImplemented` 报成已实现。**「有 handler」不等于「有效果」**——
这是覆盖面那套机制挡不住的漏网形态。两张都已开后台任务。
