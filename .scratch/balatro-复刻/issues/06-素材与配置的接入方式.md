# 素材与配置的接入方式

Type: wayfinder:grilling
Status: resolved

## Question

原 PNG、音频、配置表怎么进 `复刻/Balatro/`？

- **引用**：构建时从 `参考/产物/Balatro_1.0.1o/` 读。不重复占体积，
  产物更新自动跟随；代价是 `复刻/` 不自包含，且跨目录引用要配 Vite 的 `publicDir` / alias。
- **拷贝**：复制一份进 `复刻/Balatro/public/`。工程自包含、干净；
  代价是仓库多出一份几十 MB 的副本，且与产物脱钩后会漂。
- **构建期转换**：写个脚本把 `配置CSV/` 转成 TS 类型 + JSON，产物仍是唯一真相源。

两条既有约定要照顾到：

- 仓库总则「**改生成器，不改产物**」——不管选哪条，都不能改 `参考/产物/` 里的东西。
- 图集：Balatro 的 PNG 是按 sprite sheet 组织的，Phaser 要 atlas JSON。
  这份 atlas 是新生成的产物，它该归谁、放哪，一并定掉。

带着推荐答案去问用户。

## Answer

**素材：拷贝进 `public/assets/` 并入库，只拷用得上的。字体只带拉丁。**
**配置：从 Lua 直译，不碰 `配置CSV/`。**

### 票里的三个选项少了一刀

原票把「引用 / 拷贝 / 构建期转换」并列成三选一。但**配置表和素材是两个问题**：
CSV 不能直接喂给 TS，必须转换；PNG / 音频只需要决定「引用还是拷贝」。
分开之后才发现配置那一半另有答案。

### 配置：源头是 Lua，不是 CSV

`P_CARDS` 等表**完整内联在 `源码/game.lua:302` 起**，
`配置/配置CSV/` 是 `工具/balatro_*.py` 从同一批 Lua 表**派生**出来的研究产物，隔了一层。

更要命的是 CSV 装不下行为。`配置/总表索引.md` 自己标着
**`_小丑总表.csv` 的「配置驱动」只有 19/150 = 13%**——
另外 87% 在 `calculate_joker` 的 144 个分支里。

按 [03 号票](03-Lua到TS的翻译策略.md) 的直译裁定，复刻件的配置源头就该是 Lua 源码。
**CSV 属于研究层（给人看的），不属于复刻层。** 不写生成器，不建立依赖。

### 素材：拷贝进 public/assets/ 并入库

第一个切片实际只要 **288K**：

| 文件 | 大小 | 为什么 |
|---|--:|---|
| `textures/8BitDeck.png` | 46K | 52 张标准牌的图集 |
| `textures/Enhancers.png` | 75K | 卡面底板与强化牌 |
| `fonts/m6x11plus.ttf` | 35K | 默认字体（`game.lua:937` 第 1 条），Balatro 的招牌像素字体 |
| `sounds/*.ogg` × 10 | 各约 10K | 出牌、滑牌、筹码、按钮 |

**不拷 CJK 字体**（`GoNotoCJKCore.ttf` 18M 等，合计约 60M）。
第一个切片只有英文 UI；真做本地化时应当**子集化**而不是整个搬。

选拷贝不选引用的理由：`参考/产物/` 是**固定版本**的拆包资料，不会变，
所以「拷贝会与产物脱钩漂移」这个常见顾虑在这里不成立。
跨目录引用的代价反而更实在——路径含中文与 `../../`，跨平台构建多一个踩坑点。

清单与来源写在 `复刻/Balatro/public/assets/来源.md`，开头就是那条
「只跑 localhost，素材受版权保护」的前提。

### 图集：不用手写 atlas JSON

Balatro 的图集是**规则网格**：

- 格子尺寸来自图集注册表，`game.lua:982`
  `{name = "cards_1", path = "…/8BitDeck.png", px = 71, py = 95}`
- 帧坐标来自各条目的 `pos = {x, y}`，如 `C_2 = {… pos = {x = 0, y = 1}}`

校验：`8BitDeck.png` 实测 **923×380 = 13 列 × 71、4 行 × 95**，严丝合缝。

所以 Phaser 要的 atlas 元数据**纯可推导**。落在 `src/core/atlas.ts`。

### 实测发现：`Shader` GameObject 不会自动应用 spritesheet 的帧

第一次接上真图集时，**整张 923×380 的图被画进了每个 quad**。

原因是 `Shader` GameObject 的 `outTexCoord` 默认跨整张纹理，
Phaser 的 frame 体系对它不生效。必须显式调
`shader.setTextureCoordinatesFromFrame(frame, texture)`（`Shader.js:559`）。

改完之后 40 张牌各显示正确的一张：证据见 `复刻/Balatro/spike/证据-图集分帧正确.png`
（2♥ 3♥ 4♥ … J Q K A、梅花、方块，帧全对）。

**这反而让移植更贴原作**：Balatro 自己的 `texture_details` / `image_details`
两个 uniform 就是干这个的（`sprite.lua:103-104`），
语义是 `(格子列, 格子行, 格宽px, 格高px)` 与 `(图集总宽, 图集总高)`——
原样传进去即可，不需要另造一套 Phaser 侧的帧映射。

### 与既有约定的关系

仓库总则「**改生成器，不改产物**」不受影响：
本票只从 `参考/产物/` 往外拷，一个字节都没往回写。
