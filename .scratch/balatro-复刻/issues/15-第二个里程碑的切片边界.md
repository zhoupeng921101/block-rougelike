# 第二个里程碑的切片边界

Type: wayfinder:grilling
Status: resolved

## Question

第一个里程碑（[07 号票](07-第一个可玩里程碑的切片边界.md)）已交付：
红牌组打小盲注，8 张手牌 / 4 出牌 / 3 弃牌，300 分过关，106 个测试绿。

07 号票同时留下一条硬结论：**「结算管线做全但不要小丑」是自相矛盾的**——
15 步里第 6、11、15 步全是小丑遍历，零小丑时这三步空跑、测不到。
所以第二个里程碑绕不开小丑。

但小丑不是一个能单独跑的东西：小丑要从**商店**买，商店要**钱**，
钱要从**回合结算**来，回合结算要有**盲注推进**。切到哪为止？

## Answer

**纵切到「带小丑打过 Ante 1」。**

### 里程碑的定义

小盲注 → 商店 → 大盲注 → 商店 → Boss 盲注 → 商店 → 进 Ante 2 的过场。
全程能买小丑、卖小丑、重掷商店，小丑在结算里真的出力。

| 项 | 值 | 出处 |
|---|---|---|
| 三个盲注的需求 | 300 / 450 / **600** | `game.lua:267-298` 的 `mult` 1 / 1.5 / 2 × `get_blind_amount(1)=300` |
| 小丑槽位 | 5 | `misc_functions.lua:1855` `joker_slots` |
| 商店小丑位 | 2 | `get_starting_params` 的 `shop_jokers` 基数 |
| 每回合基础收益 | 小盲注 3 / 大盲注 4 / Boss 5 | `game.lua:267-298` 的 `dollars` |
| 利息 | 每 5 块 +1，上限 5 | `misc_functions.lua` 的 `interest_cap` |
| 剩余出牌次数 | 每次 +1 | `state_events.lua` 回合结算 |

**Ante 1 的 Boss 池是 8 个**——`boss.min <= 1` 的那些：
The Hook / The Club / The Manacle / The Psychic / The Goad / The Head / The Window / The Pillar
（`game.lua:270,273,274,284,285,290,293,295`）。八个的 `mult` 全是 2，所以需求都是 600，
但**八个的 debuff 各不相同，全部要实现**——它们是 `evaluate_play` 第 2/5/8 步
（`debuff_hand` / `modify_hand` / 逐张 debuff）的唯一内容，不实现这三步就是空的。

抽 Boss 本身消耗 RNG，而现有 16 条外部真值**正好就是 Boss Blind 选择**
（见 [02 号票](02-LuaJIT-RNG-复刻口径.md)）——这是本里程碑唯一一处有外部
ground truth 的地方，要用上。

### 在范围内

**小丑系统**：
- `card.lua:2294` `calculate_joker` 与 `common_events.lua:583` `eval_card` 的框架
- `evaluate_play` 补上第 **6、11、15** 步（出牌前遍历 / 逐张型 / 主遍历）
  以及第 **10** 步（手牌区遍历，`h_mult` / `Xmult` 靠它）与**重复触发**
- 首批小丑：**全部 61 张 rarity 1** + 形状需要的少量 rarity 2/3
- `Four Fingers` / `Shortcut` 接进 `poker-hands.ts` 已经留好的 `JokerFlags`

**经济层**：`ease_dollars`、回合结算收益、利息、卖牌价、商店价格。

**商店**：小丑生成（`create_card` 的稀有度掷点 + 池子 + 重复剔除）、买、卖、重掷。
**这是本里程碑的第二个 RNG 消费点**，且消费顺序与洗牌交织。

**盲注推进**：`BLIND_SELECT` 简化成「直接进下一个盲注」，但三个盲注都要跑；
Boss 盲注从 Ante 1 的池子里抽，**Boss 的 debuff 效果要实现被抽到的那几个**。

**Run 状态机**：一层在 `Round` 之上的 `Run`，管 ante / 盲注序 / 钱 / 小丑 / 牌组。

### 明确不在范围内

塔罗牌、星球牌、幽灵牌、优惠券、标签、补充包、跳过盲注、
强化牌（`bonus` / `mult` / `wild` / `glass` / `steel` / `stone` / `gold` / `lucky`）、
版本（`foil` / `holo` / `polychrome` / `negative`）、蜡封、
rarity 4（传奇）小丑、其余 17 个牌组、局外解锁、存档。

**Blueprint / Brainstorm 不在范围**——它们递归调用 `calculate_joker`，
终止条件是 `context.blueprint > #jokers + 1`，需要先有一批小丑才能验。
但 `context.blueprint` 这个字段**现在就要留在 context 里**，
因为有 17 处小丑行为靠 `not context.blueprint` 来禁自我升级。

### 为什么不是别的切法

- **「只接小丑、不做商店」测不到真东西。** 小丑得靠手写 fixture 塞进小丑区，
  那只验了管线，验不到「小丑是怎么进到手里的」——而稀有度掷点是 RNG 消费点，
  跳过它，后面所有 seed 都会跟原版分叉。
- **「做全 150 张小丑」的成本在错误的地方。** `calculate_joker` 1773 行
  （`card.lua:2294-4066`），其中 rarity 3/4 的 25 张大量依赖塔罗/版本/蜡封，
  而那些都不在本里程碑。先把 rarity 1 做完，形状就已经全覆盖。
- **「先做 Ante 1→8 的完整 run」太大。** 那要 28 个 Boss 全实现、
  要消耗品、要补充包。留作第三个里程碑。

### 四条轴在本切片的验收手段

| 轴 | 怎么验 | 自动化 |
|---|---|---|
| 机制与数值 | 每张小丑一条单测，手算期望值；管线形状逐 context 写测试 | ✅ 单测 |
| 同 seed 同局 | **Boss 盲注选择有 16 条外部真值**；商店生成只能结构性验证 | ✅ 部分 |
| 像素级外观 | 小丑区 / 商店的人眼比对 | ❌ 手工 |
| 音效 | 人耳 | ❌ 手工 |

### 连带处理的两条

1. **`09 号票`的「delay 可压成 0」这条到期了。**
   本里程碑进商店，而商店路径上有带 `delay` / `blockable=false` 的 RNG 消费。
   要逐个核：本切片实际命中几处。核完再决定虚拟时钟要不要如实复刻。
2. **`calculate_joker` 的翻译形状。** 原文是一条 `if context.X then ... elseif context.Y`
   的大链，链内再按 `self.ability.name` 逐个判。**按名字分发的表与原文语义等价**
   （名字唯一、每条命中即 `return`），150 张用 if 链会变成一个 2000 行函数。
   裁定：**按 context 分支保留原文的分支结构，分支内改成按名字查表**。
   这不违反 [03 号票](03-Lua到TS的翻译策略.md)——那条禁的是把卡牌重构成判别联合，
   不是禁用查表做同名分发。**唯一要守住的不变量：一张小丑在一次 context 调用里
   最多产出一个 effect**，原文靠 `return` 保证，表里靠「handler 返回单个值」保证。
