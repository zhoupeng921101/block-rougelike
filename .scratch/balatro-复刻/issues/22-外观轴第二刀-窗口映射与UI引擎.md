# 22 · 外观轴第二刀：窗口映射与 UI 引擎

Label: wayfinder:ticket · decision + task

## 为什么是现在

21 号票把复刻件放进了模拟器，第一次能与正版**同屏、同分辨率**比。CRT 修完之后，
剩下的偏差几乎全在两处：

1. **位置对不上。** 复刻件是固定 1512×806 的画布（只有房间 21×11.2 tile，没有留白）再 CSS 缩放；
   原作的窗口是房间 + 四周留白（22.6×12.4 tile），`love.resize` 按窗口等比算 `TILESCALE`、把房间居中
   （`main.lua:436`）。2560×1440 时每 tile 113.3 像素，房间原点在 (90.6, 85.7)——
   用这个算牌堆左上角是 (2180, 1043)，实机截图上量到的正是这里。
2. **UI 全是调试文字。** 左侧面板、盲注选择三张卡、按钮、回合收益……原作全由 `UIBox` 搭出来
   （`engine/ui.lua` 1085 行 + `UI_definitions.lua` 6607 行）。

## 裁定（自行裁定，依据如下，便于事后推翻）

**一、窗口映射照 `love.resize` 直译，落在相机上。**
世界坐标仍是固定的 72 像素 / tile（`coords.ts` 的 `toPx` 不动，10 号票的「T 全程 tile 单位」不受影响），
相机 `zoom = 实际每 tile 像素 / 72`、`scroll` 让房间原点落到 `love.resize` 算出的位置。
画布按**物理像素**开（`devicePixelRatio`），与原作「画布 = 屏幕分辨率」一致——
这顺带让 CRT 的 `scanlines` 回到原作的定义（`G.CANVAS:getPixelHeight()`）。
背景与 CRT 两个全屏 quad 跟着相机的可视区摆。

**二、UI 走「移植布局引擎 + 直译 UI 定义」，只有绘制与输入按 Phaser 惯例写。**
03 号票与地图写过「UI 是重写不是直译」。这条要细化：要像素级，最短的路是让**同一份定义算出同一份几何**，
所以 `UIBox:calculate_xywh` / `UIElement:set_wh` / `set_alignments` 这套布局（约 300 行、纯计算）原样移植，
`UI_definitions.lua` 里的定义函数逐个直译成返回同形状树的 TS 函数。
「重写」的只剩：`draw_self` / `draw_pixellated_rect` 换成 Phaser `Graphics`，文字换成 Phaser `Text`（m6x11plus），
点击 / 悬停走 Phaser 的输入。
- 布局部分**不 import Phaser**，放 `src/ui/`，能进单测
- 第一份直译的定义是 `create_UIBox_HUD`（左侧面板），验收拿模拟器截图量元素边框

**三、验收口径**：模拟器里两边都全屏 2560×1440，同一局面截图，量关键元素的像素边框。
允许 ±2 像素（字体光栅化与抗锯齿不可能逐像素一致）。

## 不在这一刀

- 卡牌的扇形排布与转角（`align_cards` 的 hand 分支，要 `VT.r`）——下一刀
- DynaText 的逐字弹跳、`juice_up`
- 悬停提示框（`h_popup`）

## 进展

**第一步：窗口映射**（已提交）。画布按物理像素开，相机照 `love.resize`。附带打通了复刻件的截图：
`?win=2560x1440` 钉死逻辑窗口，`tools/cdp.mjs snap` 经 DevTools 协议取回画布原图。

**第二步：UIBox 引擎 + 左侧面板。**
- `src/ui/uibox.ts`：`calculate_xywh` / `set_wh` / `set_alignments` / `align_to_major` 直译，连怪癖一起
- `src/ui/dynatext.ts`、`font.ts`（字宽表由 `tools/gen-font-metrics.mjs` 从 TTF 抽）、`colours.ts`、`format.ts`
  （`number_format`，`%.Nf` 复用 RNG 那边的精确展开——LuaJIT 对恰好一半取偶）
- `src/ui/definitions/hud.ts`：`create_UIBox_HUD` 逐节点直译；本地化由 `tools/gen-localization.mjs` 生成
- `src/game/ui-draw.ts`：像素圆角矩形（`draw_pixellated_rect` 的顶点表）、阴影、压花、T 节点文字、DynaText 逐字
- **布局的外部真值**：`tools/ui-oracle.py` 用 lupa（LuaJIT 2.1）原样加载原作的
  `object / node / moveable / ui / text / misc_functions / UI_definitions.lua`，只桩掉 LÖVE，
  跑同一份 HUD 定义导出 80 个元素的最终矩形。`uibox.test.ts` 逐个比到 1e-9，**第一次跑就全对**
- 盲注配色：`get_blind_main_colour` + `Blind:change_colour`。生成器原先把 `boss_colour` 剪掉了，现在保留

**实机对照**（2560×1440，选盲注界面）：面板各层颜色 ±3 级以内；元素位置与模型预测一致，
而实机整体比模型**低 3.5 像素**。原因不是布局：`update_canvas_juice`（`common_events.lua:1142`）让房间按
「屏幕震动」设置（缺省 50）做 ±0.02 tile 的正弦漂移、跟随光标的视差与 ±0.0015 弧度的旋转——原作的「呼吸」动画。
复刻件还没有它，下一步补；逐像素比对时两边把震动设成 0 来排除。

**第三步：房间摆动与按钮视差。**
- `src/game/room-juice.ts`：`update_canvas_juice` 直译。房间旋转以**屏幕上的** (ROOM.w/2, ROOM.h/2) 为轴
  （`Node:translate_container`），落到 Phaser 相机上要把原点设在那个轴点、滚动量补回房间偏移；
  背景与 CRT 两个全屏 quad 反转 −r 保持贴屏。`look.ts` 加 `screenshake`（缺省 50，`?shake=0` 关）
- 按钮的分层视差（`ui.lua:677`）：按钮及其子孙每带一层阴影就多挪 `0.4·sp/TILESIZE`，
  按钮里带阴影的文字挪两层（≈6.8 像素）。引擎里补上 `button_UIE` 的向下传递（`set_parent_child`）

**两边都关掉摆动之后**（实机 Settings → Game → Screenshake 0，复刻件 `?shake=0`）：
左侧面板 7 个区域的最佳对齐偏移全部 ≤1 像素（$ 那格除外，它有弹跳动画），整块平均逐像素差 26.6 → 3.8，
剩下的是字形边缘（原作 200px 栅格化后缩小 vs 复刻件按目标尺寸栅格化）。

> **实机的 Screenshake 现在是 0**，是为了比对临时改的。会话结束前调回 50（用户原来的值）。

**第四步：局内的区域与手牌。**
- CardArea 的底框与计数（`cardarea.lua:288` 的 `area_uibox`）直译，小丑区 / 消耗品区 / 手牌 / 牌堆四个框进了 Lua 真值
  （底板那行 `mid = true`，UIBox 以它居中、计数行挂在下面）。区域位置 `set_screen_positions` → `src/game/areas.ts`
- `align_cards` 的手牌 / 出牌区 / 小丑区分支 → `src/game/align-cards.ts`：扇形、两端下沉、±0.1 弧度转角、正弦微动。
  原作写进 `T`，但机制只用先后顺序、与 core 的 `i*CARD_W` 同序，所以 core 不动、表现层按原式摆
- 手牌区选牌时整体上移 1.9 tile、出牌时滑回（`cardarea.lua:236`），底框跟着走（`UIBox.followMajor`）
- 卡牌：按下标分深度（后压前）、阴影层（`dissolve` 的 shadow 模式、全部阴影在全部卡之下）、旋转、
  **`T.scale = 0.95`**（`card.lua:58`，所有卡都按 95% 画——漏了它卡牌大 5%、顶边高 8 像素）
- `dissolve` 的倾斜 uniform 在相机缩放后要用屏幕坐标（Phase 喂给顶点着色器的已是变换后的位置）

**实机对照**（小盲注首手）：同一张牌的包围盒 299×210 对 299×210；手牌顶边逐列偏差平均 0，±5 像素是逐张正弦微动的相位差。

还没做：`HUD_blind`（左上盲注信息）、选盲注界面、出牌 / 排序 / 弃牌按钮、牌堆的牌背堆叠、小丑与消耗品按 `align_cards` 摆、
卡牌 `VT` 的缓动（现在直接画在 `T` 上）、DynaText 的弹入。
