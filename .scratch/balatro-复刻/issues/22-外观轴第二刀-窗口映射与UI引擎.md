# 22 · 外观轴第二刀：窗口映射与 UI 引擎

Label: wayfinder:ticket · decision + task

## 为什么是现在

21 号票把复刻件放进了模拟器，第一次能与正版**同屏、同分辨率**比。CRT 修完之后，
剩下的偏差几乎全在两处：

1. **位置对不上。** 复刻件是固定 1512×806 的画布（只有房间 21×11.2 tile，没有留白）再 CSS 缩放；
   原作的窗口是房间 + 四周留白（22.6×12.4 tile），`love.resize` 按窗口等比算 `TILESCALE`、把房间居中
   （`main.lua:436`）。2560×1440 时每 tile 113.3 像素，房间原点在 (90.6, 85.7)——
   用这个算牌堆左上角是 (2180, 1043)，实机截图上量到的正是这里。
2. **UI 全是调试文字。** 左侧面板、盲注选择三张卡、按钮、回合收益……原作全由 `UIBox` 搭出来
   （`engine/ui.lua` 1085 行 + `UI_definitions.lua` 6607 行）。

## 裁定（自行裁定，依据如下，便于事后推翻）

**一、窗口映射照 `love.resize` 直译，落在相机上。**
世界坐标仍是固定的 72 像素 / tile（`coords.ts` 的 `toPx` 不动，10 号票的「T 全程 tile 单位」不受影响），
相机 `zoom = 实际每 tile 像素 / 72`、`scroll` 让房间原点落到 `love.resize` 算出的位置。
画布按**物理像素**开（`devicePixelRatio`），与原作「画布 = 屏幕分辨率」一致——
这顺带让 CRT 的 `scanlines` 回到原作的定义（`G.CANVAS:getPixelHeight()`）。
背景与 CRT 两个全屏 quad 跟着相机的可视区摆。

**二、UI 走「移植布局引擎 + 直译 UI 定义」，只有绘制与输入按 Phaser 惯例写。**
03 号票与地图写过「UI 是重写不是直译」。这条要细化：要像素级，最短的路是让**同一份定义算出同一份几何**，
所以 `UIBox:calculate_xywh` / `UIElement:set_wh` / `set_alignments` 这套布局（约 300 行、纯计算）原样移植，
`UI_definitions.lua` 里的定义函数逐个直译成返回同形状树的 TS 函数。
「重写」的只剩：`draw_self` / `draw_pixellated_rect` 换成 Phaser `Graphics`，文字换成 Phaser `Text`（m6x11plus），
点击 / 悬停走 Phaser 的输入。
- 布局部分**不 import Phaser**，放 `src/ui/`，能进单测
- 第一份直译的定义是 `create_UIBox_HUD`（左侧面板），验收拿模拟器截图量元素边框

**三、验收口径**：模拟器里两边都全屏 2560×1440，同一局面截图，量关键元素的像素边框。
允许 ±2 像素（字体光栅化与抗锯齿不可能逐像素一致）。

## 不在这一刀

- 卡牌的扇形排布与转角（`align_cards` 的 hand 分支，要 `VT.r`）——下一刀
- DynaText 的逐字弹跳、`juice_up`
- 悬停提示框（`h_popup`）

**第三步：房间摆动与按钮视差。**
