# 坐标驱动排序的解耦

Type: wayfinder:grilling
Status: open

## Question

Balatro 的计分顺序读屏幕坐标：
`table.sort(scoring_hand, function(a,b) return a.T.x < b.T.x end)`
（`源码/functions/state_events.lua:621`，另见 `:413` 出牌、`:484` 弃牌）。

`T.x` 是卡牌的渲染 transform。LÖVE 与 Phaser 的坐标体系、布局时机、
以及「卡牌动画到位之前 x 是多少」都不同——原样直译会让排序在动画中途取到错误的值。

这条有实际后果：`参考/结论/Balatro_1.0.1o/出牌结算管线.md` §2 指出，
「打出的第一张计分牌」（未断选票、照片吃的那个）就是最左边那张，**玩家靠调手牌顺序控制它**。
排序错了，这类小丑的行为就错了，而且是静默地错。

候选方案：

- **显式 order 字段**：逻辑层给每张牌一个 `order:number`，表现层布局后写回。
  干净，但要保证「写回」发生在计分读取之前，否则同样取到脏值。
- **逻辑层自持牌序**：手牌区在逻辑层就是一个有序数组，`T.x` 完全不进逻辑。
  最稳，但要核对原版所有「靠拖动改变顺序」的交互是否都能映射成数组重排。
- **原样直译**：TS 侧也维护一个 `T.x`，由表现层驱动。最贴近原版，
  但把渲染时序变成了正确性的一部分——与对拍目标相冲。

要确认的前置事实：除了这三处 sort，还有多少地方直接读 `T.x` / `T.y` 做**逻辑**判断。
先 grep 再定方案。

带着推荐答案去问用户。
