# 补充包与幽灵牌的切片边界

Type: wayfinder:grilling
Status: resolved

## Question

[16 号票](16-消耗品的切片边界.md) 已交付：消耗品槽位、12 张星球、21/22 塔罗、
8 种强化牌，570 个测试绿，小丑覆盖面 119/150。

**但它没有达成自己的目的。** 16 号票开票时的预设是「接上星球牌 → Ante 3 的墙就破」，
实测把这条推翻了：八个 seed 的贪心深度从 2.875 只抬到 3.0，接完塔罗与强化牌之后
仍是 Ante 2–4。商店只有两格、其中 ~28.6% 是消耗品、一半还是塔罗，
整局买得到 1–5 张星球，**而且抽到哪个牌型不由人挑**。

原作里星球的主要来源是**天体补充包**（一包 3 张、Jumbo 5 张、Mega 5 选 2）。
所以这一票的首要目标不是「补齐内容」，是**破墙**。

连带要裁定四件事（16 号票留下的）：
09 号票那条「delay 可以压成 0」这次到期没有、`soulable` 怎么传、
商店的 RNG 顺序怎么变、版本系统要不要一起做。

## Answer

### 一、切片边界：**补充包五种 + 幽灵牌 18 张 + 版本 4 种 + 蜡封 4 种**

比 16 号票大，但这一刀切不小——**补充包的五种口味各自拽着一个系统**：

| 包 | 拽着什么 | 已经有了吗 |
|---|---|---|
| 奥秘 Arcana | 塔罗 | ✅ 16 号票 |
| 天体 Celestial | 星球 | ✅ 16 号票 |
| 小丑 Buffoon | 小丑 | ✅ 15 号票 |
| 标准 Standard | 扑克牌 + **版本** + **蜡封** | ❌ |
| 幽灵 Spectral | **幽灵牌 18 张** + 版本 | ❌ |

把标准包与幽灵包切出去的代价是「买了一格什么也不发生」，
而补充包一格 $4–$8、还占着商店的位置——比一张买错的小丑贵得多。
**而且版本与幽灵牌互相拽**：`Aura` / `Hex` / `Ectoplasm` 三张幽灵牌全是版本，
`Perkeo` 要 Negative，`The Wheel of Fortune`（22 张塔罗里唯一没实现的那张）
也要 `poll_edition`。切开只会让两票都做一半。

**所以一起做。** 但落地顺序按「破墙优先」排，中途有明确的停靠点（见末尾）。

### 二、09 号票那条「delay 可以压成 0」——**这次仍然成立，但理由换了**

16 号票的理由是「只命中 The Wheel of Fortune，三次掷点共用一个 key」。
这一票 `card.lua:1723` 的 `Card:open()` 真的进范围了，得重新核。

`Card:open` 的形状是：

```lua
-- ① 入队：造包里的牌（trigger='after', delay=1.3*sqrt(GAMESPEED),
--          blockable=false, blocking=false）
G.E_MANAGER:add_event(Event({ ... for i = 1, _size do create_card(...) end ... }))
-- ② 同步：open_booster 的小丑遍历
for i = 1, #G.jokers.cards do
    G.jokers.cards[i]:calculate_joker({open_booster = true, card = self})
end
```

**注意 ② 是同步的，而 ① 只是入队。** 所以真实执行序是
**先跑小丑遍历（`Hallucination` 掷 `halu<ante>`、可能造一张 `Tarothal<ante>`），
再造包里那几张**。

这个顺序**有观测后果**：Hallucination 造出来的那张塔罗会被 `set_ability` 标进
`used_jokers`，而包里那几张塔罗的池子要读 `used_jokers`——
反过来的话包里就可能抽到那一张，`_resample` 的次数跟着变。

包里 `_size` 张牌在**同一个**事件的 for 循环里造，中间没有别的 RNG 消费者插进来，
而且各包的 key 互不相同（`ar1` / `pl1` / `spe` / `sta` / `buf`）。

**裁定：继续把 delay 压成 0，不引入虚拟时钟。**
但**必须守住** `Card:open` 里「小丑遍历在前、包里的牌在后」这个顺序——
照着读代码会写反，因为造牌那段写在上面。

Familiar / Grim / Incantation（`card.lua:1312`，delay 0.7）同理：
一次 `use_consumeable` 里严格先后，`random_destroy` → `familiar_create` / `spe_card`
三个 key 各管各的。

### 三、`soulable` 这次传真值——三种包各不一样

16 号票查明商店路径传的是 `nil`。补充包**全部传 `true`**：

```lua
-- card.lua:1734 起
create_card("Tarot",  G.pack_cards, nil, nil, true, true, nil, 'ar1')  -- 奥秘
create_card("Planet", G.pack_cards, nil, nil, true, true, nil, 'pl1')  -- 天体
create_card("Spectral", G.pack_cards, nil, nil, true, true, nil, 'spe') -- 幽灵
create_card("Joker",  G.pack_cards, nil, nil, true, true, nil, 'buf')  -- 小丑
```

而 `create_card` 的 soulable 段是**两个并列的 if**（`common_events.lua:2130-2143`）：

| `_type` | The Soul 那支 | Black Hole 那支 | 掷点次数 |
|---|---|---|---|
| `Tarot` | ✅ | ❌ | **1** 次 `soul_Tarot<ante>` |
| `Planet` | ❌ | ✅ | **1** 次 `soul_Planet<ante>` |
| `Spectral` | ✅ | ✅ | **2** 次 `soul_Spectral<ante>` |
| `Joker` | ❌ | ❌ | 0 |

三条要记住：

1. **奥秘包传的是 `'Tarot'` 不是 `'Tarot_Planet'`**（后者只有 `The Fool` 用），
   所以 key 是 `soul_Tarot<ante>`。
2. **幽灵包掷两次**，两次用同一个 key、紧挨着。
   第二次能覆盖第一次的 `forced_key`（Black Hole 压过 The Soul）。
3. **两支各自带一条「手上有就不掷」的守卫**：
   `not (G.GAME.used_jokers['c_soul'] and not next(find_joker("Showman")))`。
   握着 The Soul 的时候那一次**不消费**。

判据是 `> 0.997`，即 0.3%。

### 四、商店的 RNG 顺序：**末尾多两次 `shop_pack<ante>`，但第一个商店只多一次**

补充包是商店的**第三、四格**（`G.shop_booster` 的 `card_limit = 2`）。
生成顺序（`game.lua:3460` 起）是：

```
小丑／消耗品那两格   → create_card_for_shop ×2   （15、16 号票已实现）
优惠券那一格         → 读 current_round.voucher  （不在范围，且此处不掷点）
补充包那两格         → get_pack('shop_pack') ×2
```

`get_pack` 消费 `pseudoseed('shop_pack'..ante)` 一次，**但开头有一条提前 return**：

```lua
if not G.GAME.first_shop_buffoon and not G.GAME.banned_keys['p_buffoon_normal_1'] then
    G.GAME.first_shop_buffoon = true
    return G.P_CENTERS['p_buffoon_normal_'..(math.random(1, 2))]
end
```

三件事：

- **第一个商店的第一格恒是小丑包**，而且那一次**不消费 `shop_pack1`**。
  所以第一个商店消费 1 次、以后每个商店 2 次。
- 那个 `math.random(1, 2)` 走的是**全局流**（没有 `pseudoseed`），
  02 号票已查明全局流不参与可复现性。两张 `p_buffoon_normal_1/2` 除了
  图集坐标完全一样，所以**这处不可复现不影响任何数值**，取哪张都行。
- **补充包不参与重掷**：`reroll_shop`（`button_callbacks.lua:2965`）只清
  `G.shop_jokers`。包的 key 存在 `G.GAME.current_round.used_packs`，
  买掉置 `'USED'`，每回合重置。

池子是 `P_CENTER_POOLS['Booster']` 按 `order` 排（奥秘 1-8 / 天体 9-16 /
标准 17-24 / 小丑 25-28 / 幽灵 29-32），**权重总和 22.42**，
选中判据是 `it >= poll and it - weight <= poll`（累积权重）。

小丑包里造小丑那一支要消费 `packetper<ante>`（**不是** `etperpoll<ante>`）
与 `edibuf<ante>`——`common_events.lua:2180` 那行是
`(area == G.pack_cards and 'packetper' or 'etperpoll')..ante`。
`createJokerCard` 现在的 `inShop: boolean` 得扩成三档。

### 五、版本与蜡封：**一起做**

理由在第一节：它们被四处拽着（标准包、幽灵牌三张、Perkeo、The Wheel of Fortune），
而且**商店那两次 `edi` 掷点已经在消费了，只是结果被丢掉**——
把结果接上去不改 RNG，只把已经掷出来的数用起来。

- **版本 4 种**（`poll_edition`，`common_events.lua:2092`）：
  `negative` / `polychrome`（×1.5 倍率）/ `holo`（+10 倍率）/ `foil`（+50 筹码）。
  `negative` 在小丑上是「不占格子」、在消耗品上是「不占格子」。
- **蜡封 4 种**：`Red`（重复触发一次）/ `Blue`（回合结束造星球）/
  `Gold`（打出给 $3）/ `Purple`（弃牌时造塔罗）。
  蜡封只从标准包与几张幽灵牌来。

### 落地顺序

```
1. 生成器抽 32 个补充包 center
2. 商店第三/四格 + shop_pack<ante> 的账 + 开包状态机（choose N of M / skip）
3. 天体包 + 奥秘包                     ← 墙应该在这里破，**停一下实测**
4. 小丑包（packetper / edi 的账）
5. 版本 4 种                           → 解开 The Wheel of Fortune
6. 蜡封 4 种 + 标准包
7. 幽灵牌 18 张 + 幽灵包               → 回填 5 张小丑
```

**第 3 步之后必须实测一次贪心深度。** 16 号票的教训是「假设破墙」而没测；
这次把实测钉进落地顺序里。**深度没涨就是没破**，那时要停下来重新想，
而不是继续往下做。

**如果中途要停，停在第 3 步或第 5 步之后。**

### 不在本票

- **优惠券**（voucher）。商店第五格，与补充包无关，另一刀。
- **标签 / 跳过盲注**。`coverage.test.ts` 的 `标签` 组。
- **增删牌那 8 张小丑**。它们要的是「运行时造／毁扑克牌」的基础设施，
  标准包会铺一部分（造牌），但摧毁那半边不在本票。

### 顺带一提：`Red Card` 是第三张「有 handler 但长不了」的小丑

它的 MAIN 半边（读 `ability.mult`）在 `calculate.ts:775`，
但 `skipping_booster` 那半边（`card.lua:2444`）没有调用方，
所以 `ability.mult` 永远是 0、`flatMult` 恒返回 null。
它不在 `coverage.test.ts` 的未实现名单里——因为它**有** handler。

这与 16 号票收尾时逮到的 `context.after` / `using_consumeable`
是同一种形态，也与 `To Do List` / `Mr. Bones` 是同一种形态。
**「有 handler」不等于「有效果」**，第 2 步接上开包流程时顺带修掉。

### 破墙实测（本票钉进落地顺序里的那一次）

| 阶段 | 八个 seed 的贪心深度 |
|---|--:|
| 16 号票之前 | 2.875 |
| 消耗品（16 号票） | 3.0 |
| 补充包（本票） | **3.375** |

最深到 **Ante 5**（JHZ7FPM）。**墙松了两格，还是没破。**

本票开票时写的是「深度没涨就是没破，那时要停下来重新想」。
深度涨了，所以方向是对的——一个天体包一次给 3 张星球、Jumbo 5 张，
而商店整局才 1–5 张，供给确实上来了。

**但「还差多少内容」这个问题现在测不出来**，因为那个贪心策略：

- **不挑手牌**，所以 22 张塔罗里换强化／换花色的那 13 张、
  以及全部「给选中的牌加蜡封」的幽灵牌，一张都用不出来
- **买小丑不挑好坏**，谁便宜买谁
- **用星球不挑牌型**，抽到 Two Pair 的星球就升 Two Pair

→ **下一步该先写一个会挑牌的策略**，不然内容与策略这两笔账永远分不开。

### `/code-review high` 逮到的三条（全是真的）

1. **`Astronomer` 的价格算死在建格子那一刻**——原作在它进小丑区时把
   所有卡重新定价一遍（`card.lua:616`），所以「先买 Astronomer 再买天体包」
   应该免费。改成 `Shop.itemCost(i)` / `Shop.packCost(i)` 现算。
2. **Blue 蜡封造出来的星球没进 `usedJokers`**——全仓别的造卡路径都标了，
   只有这一处漏，漏了就不退出池子、`_resample` 次数跟着偏。
3. 一处过期的报错文案。

### 不在本票、也没做的

- **优惠券**（voucher）。商店第五格。`v_telescope`（天体包第一张必是最常打
  牌型的星球）与 `v_omen_globe`（奥秘包里出幽灵牌）这两张会改本票的账，
  接的时候要回来核。
- **标签 / 跳过盲注**。
- **增删牌那 8 张小丑**。标准包与三张造牌幽灵牌已经把「运行时造扑克牌」
  铺好了，摧毁那半边也有了（`removeCards`），所以这一组现在**也不阻塞了**。
