# 3B 工程计划

2026-10-26 立项定稿。本篇管「工程怎么搭、按什么顺序做」；玩法规则以 [设计/3B核心规则.md](设计/3B核心规则.md) 为准。

工程目录是仓库根的 `Demo/`。下文的 **block-client** 指同一团队的方块收集手游工程（`E:\TEngine_block`），本作的框架、盘面代码和开发流程都从那里取。

## 立项裁定

| 项 | 裁定 | 理由 |
|---|---|---|
| 定位 | 正式工程起点：原型直接长成上线产品 | |
| 平台 | PC（Steam）横屏首发，设计分辨率 1920×1080；手机横屏后移植 | 规则 §8 的草图是 16:9 横屏，两侧信息栏竖屏放不下 |
| 商业模式 | 买断制：无内购、无广告、无服务端 | 按个体调难度、在情绪低点弹窗这类变现手段会损伤肉鸽，见 [横向对比.md](../参考/横向对比.md) §10 |
| 框架 | 只带 TEngine 框架层（TEngine、Launcher、HybridCLR、YooAsset、Luban 工具链），从 block-client 拷快照 | block-client 对 TEngine 有本地修补，并已在同一 Unity 版本出过整包。它的游戏底座层 GameBase 直连联网层、启动流程含登录，单机不带 |
| 引擎版本 | Unity 6000.3.19f1 + URP，与 block-client 一致 | |
| 热更 | 保留热更程序集分层，首发用离线模式（资源全部随包，不连 CDN） | Steam 用不上热更；移植手机时打开即可，不改结构 |
| 仓 | 工程放本仓 `Demo/` | 规则文档与实现同仓，一次提交能同时改两边 |
| 战斗盘面 | 移植 block-client 的盘面核心（位棋盘、形状、消行判定，已是纯 C#）和拖拽落子、消除表现；计分按 3B 重写 | 自有代码，消除手感已调过多轮；3B 是 Balatro 式逐格触发计分，原计分对不上 |
| 规则核心 | 写成不依赖 UnityEngine 的纯 C# 程序集，表现层订阅它的事件 | 定标要在 Unity 外批量跑局，也方便单测 |
| 随机数 | 统一用种子，按用途分流（发块、商店、效果各一条） | 能复现 bug、跑测能重放、以后能开种子局。做法同 Balatro 的 `pseudoseed` |
| 局内存档 | 支持退出后接着玩当前这一局 | 局内状态第一天就要可序列化，后补得全部返工 |
| 本地化 | 文本一律走 key 表，首发中英双语 | 后补要把硬编码文本全扫一遍 |
| 美术 | 沿规则 §8 草图的太空像素风（BIG BLOCK BANG）用 AI 出正式图 | 草图本身的出图工具没有记录，只作风格方向，不直接入库 |
| 开发流程 | 整套搬 block-client 的 devflow（需求审计 → 槽位实现 → 槽位交付，含槽位 worktree、交付脚本、自检），去掉服务端通道 | |

## 落地时定的细节

可以改，改了在这里同步。

- `.claude/` 放在 `Demo/` 下，与 block-client 把它放在 Unity 工程目录下的做法一致；研究层仍按仓根 [AGENTS.md](../AGENTS.md) 走。
- 槽位先开 2 个。block-client 上限 3 是服务端协议分号的限制，这里不存在；但每个槽位要常驻一个 Unity 编辑器。
- 槽位 worktree 只检出 `Demo/` 与 `新游戏/`。`参考/` 和 `复刻/` 合计约 770MB，不复制进每个槽位。
- 各阶段的验收标准是立项后补的，阶段开工时可再细化。

阶段 1 落地时定的：

- **HybridCLR 暂关，Windows 用 Mono 后端**。本机没装 Visual Studio 的 C++ 工具链，Windows 出不了 IL2CPP 包，而 HybridCLR 只认 IL2CPP。热更程序集分层照留：GameLogic 仍在热更清单里，编辑器和 Mono 包都走启动器的非热更分支直接取程序集。要开热更（移植手机或 PC 改 IL2CPP）时：装 VS 2022 的「使用 C++ 的桌面开发」→ `ProjectSettings/HybridCLRSettings.asset` 的 `enable` 改 1 → 目标平台宏加 `ENABLE_HYBRIDCLR` → 资源收集加回 DLL 分组。
- **热更侧的 UI 框架取自 block-client 底座层的 UI 核心**：UIModule、窗口基类 UIPanelMono、窗口特性、资源加载器、错误日志窗、开关窗动画、倒计时，落在 GameLogic。剪掉了点击音和开窗音效（等音频表）。UI 脚本生成器连同它的设置页随阶段 2 一起搬。
- **规则核心程序集和 Luban 配置程序集推迟建**。前者随阶段 3 的第一批代码建（空程序集 Unity 不产出 dll）；后者等第一张配置表——block-client 的 Luban 流程带数据镜像、自定义模板和服务端目标，要按单端裁过，`TEngine/Luban` 菜单里的路径也还指着 `UnityProject/`。
- **出包入口**：菜单 `3B/出 Windows 包`（`WindowsBuild.Build`），产物在 `Demo/Build/Windows/3B.exe`。从没经 Unity Hub 启动的编辑器出包会带「trial version」水印，对外的包要从 Hub 打开的编辑器出。
- 启动器的背景与 logo 换成占位（横版深色底 + 3B 字标），其余启动器界面件沿用 block-client 的。
- 资源运行模式：主场景 GameEntry 设为离线（`OfflinePlayMode`），编辑器里按 TEngine 惯例走编辑器模拟模式。

阶段 2 落地时定的：

- **服务端通道按开关停用，不删分支**：`flow-config.psd1` 的 `ServerDirName` 留空即关。领取、交付、提交检查这些共用脚本里的服务端分支照留，和 block-client 保持同形，以后从那边同步脚本时好对；只属于服务端的脚本、检查道和规则篇删掉。
- **规则核心的 dotnet 单测道推迟到阶段 3**：规则核心程序集还没有，随它的第一批代码一起加进客户端自检。
- **出图 skill 不随工程搬**：`chatgpt-image` 在用户级目录，任何工程的会话都能用。
- **按需篇判据表留「预置支」**：遮罩、图集、Part 件这类本作还没写出来的件，判据照常点名、自检暂免零命中；一有对应代码，自检就要求撤掉预置标记。
- **会话要在 `Demo/` 下起**：devflow 的 hook 与 skill 都挂在 `Demo/.claude/`，在仓根起的会话挂不上。
- 槽位首次领取时，编辑器就绪约 90 秒（Library 从主工程拷进去预热过）。拷入后有 10 个 TEngine 框架脚本认不出类、进 Play 报 Settings 空引用，对这几个文件强制重导入即恢复；是拷 Library 引起的还是首次编译时序，待在 dev2 首次领取时对照。
