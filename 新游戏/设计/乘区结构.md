# 乘区结构

> 对应 [借鉴清单.md](../借鉴清单.md) 第 1、2 条的裁定：**走 Balatro 的可变乘区**。
> 这份文档把那条裁定展开成可实现的形状，并带上复刻 Balatro 时拿到的实测证据。

## 裁定回顾

**乘区的个数由玩家决定，用槽位当闸门。** 不采用 Brotato 的固定 N 条通道。

理由见清单：肉鸽卖的是「这一局是我打出来的」，而乘区个数由玩家的槽位决定，
正是这句话最直接的载体——上限是自己够出来的，不是数值表给的。

---

## 一、骨架：三轴一乘

照搬 Balatro 的结构，因为复刻时验证过它确实成立
（实现见 `复刻/Balatro/src/core/scoring.ts`）：

```
得分 = floor( ( 基础筹码 + Σ加算 ) × ( 基础倍率 + Σ加算 ) × Π(乘区) )
         └──── 轴 A ────┘   └──── 轴 B ────┘   └── 轴 C ──┘
```

**全局只有一次乘法。** 在那之前所有东西都只是往两个累加器里加、或就地乘 `mult`。
轴 A、轴 B 的项数固定（这是第 2 条「可精算」的局部回收），
**只有轴 C 的项数可变**——不可精算的部分因此被关进一个可数的槽位里，而不是散在全局。

由此推出的构筑规则，与 Balatro 一致：

> **任何乘区只放大它执行之前已经进到累加器里的部分。**
> 所以「先把加算堆满、再让乘算生效」是硬要求。

---

## 二、执行顺序必须是玩家可控的

Balatro 用**物理位置**定顺序：`table.sort(scoring_hand, a.T.x < b.T.x)`，
小丑从左到右依次结算，玩家靠拖动改变顺序。

复刻时查清了它的实现（见 [10 号票](../../.scratch/balatro-复刻/issues/10-坐标驱动排序的解耦.md)）：
坐标不是真相，**数组顺序才是**；坐标只是拖拽的输入通道。
没被拖动的牌，位置每帧由下标重算，排序对它们是恒等操作。

**本作采纳这个语义，但直接用数组顺序，不绕坐标。**
拖拽在表现层解析成「把第 i 个移到第 j 位」再回传。

这条不是细节。它是「可变乘区」能成为**决策**而非**运气**的关键：
乘区个数可变已经带来极大方差，若连顺序都不可控，玩家对结果的掌控感会塌掉。

---

## 三、代价必须配套对冲——第 4、5 条因此升级为必配

清单里已记：可变乘区的方差必须有对冲，否则「整局没撞到第二个乘数」的局会直接废掉，
而玩家无从补救。

复刻时对此有了量化的体感。用贪心最优出牌（且**完全不用弃牌**）跑 10 个种子打 Ante 1 小盲注：

```
U8RJYV6M  ✓ 344   Full House:344          ← 一手清
9ZXMM1M   ✓ 412   Two Pair:88  Straight:324
V3PUR5L4  ✗  95   Pair:28  High Card:16  Pair:36  High Card:15
                                          胜率 4/10
```

**在零乘区、纯加算的阶段，方差就已经是 95 到 412 的四倍差。**
这还是 Balatro 最平缓的第一关。乘区接进来之后，方差是乘上去的。

所以第 4、5 条（降方差商品、硬编码保底）不是可选项，是这条路线的承重墙。

---

## 四、槽位扩容物的稀有度就是全局难度旋钮

槽位是乘区个数的唯一闸门，所以「能加一个槽位的东西有多稀有」这个数字，
等价于「构筑上限锁得多死」。Balatro 把它定在 **0.3%**（负片版本）。

这个数字要单独调，不要跟其他稀有度混在一张表里——
它不是内容稀有度，是**难度参数**。

---

## 五、内容生产：修正「表外那条」

[借鉴清单](../借鉴清单.md) 的「表外的一条」写着：

> 80% 模板化的填充物负责撑住池子大小与稀有度曲线，20% 手写的规则负责制造流派。

**复刻之后要修正这条。** Balatro 的实际配置驱动率
（`参考/产物/Balatro_1.0.1o/配置/总表索引.md`）：

| 内容类别 | 条目 | 配置驱动 |
|---|--:|---|
| 小丑 Joker | 150 | **19/150 = 13%** |
| 优惠券 Voucher | 32 | 0/32 |
| 蜡封 Seal | 4 | 0/4（连 config 字段都没有） |
| 盲注 Blind | 30 | 6/30 = 20% |
| 幽灵 Spectral | 18 | 4/18 = 22% |
| 强化牌 Enhanced | 8 | 5/8 = 63% |
| 塔罗 Tarot | 22 | 17/22 = 77% |
| 牌组 Back | 16 | **16/16 = 100%** |
| 补充包 Booster | 32 | **32/32 = 100%** |
| 标签 Tag | 24 | **全驱动** |

150 张小丑里，**按名字硬编码 106 张、通用规则只有 19 张、外部引用 25 张**。
复刻时我在 `Card:calculate_joker` 里数到 **144 个 `self.ability.name ==` 分支**，
一个 1,799 行的单体函数，与上面的数字对得上。

所以真实规律不是「80% 模板化」，而是：

> **承载流派的那类内容几乎全手写；撑池子与定结构的那类内容几乎全配置。**

这不是 Balatro 偷懒，是**可变乘区的必然结果**：
当每个乘区都由一张具名内容提供时，那张内容本身就是一条规则，规则没法参数化。
牌组、补充包、标签能 100% 配置化，正因为它们不提供乘区。

### 对本作的三条约束

1. **别指望把流派内容做成配置表。** 提供乘区的那类内容，预算按「每条一段代码」算，
   不是「每条一行配置」。
2. **但不要重演 1,799 行的单体函数。** 复刻时那个函数是最难读的一处。
   拆成一条内容一个模块，用注册表挂上去——
   注意保住「顺序即优先级」的语义，别为了好看改成查表。
3. **配置化的额度花在结构层**：牌组、包、标签、稀有度曲线。那里 100% 可配置是能做到的，
   而且正是 A/B 与平衡调参真正需要的地方。

## 六、确定性：可变乘区的隐藏成本

复刻时发现一条不在清单上、但直接由「可变乘区」引出的代价。

乘区由具名内容提供，这些内容会**产生副作用**（生成一张牌、摧毁一张牌、加钱）。
Balatro 把这些副作用塞进事件队列延后执行，而队列的回调里会消耗随机数
（见 [09 号票](../../.scratch/balatro-复刻/issues/09-事件队列调度语义的复刻口径.md)）。

后果：**随机数的消费顺序由事件队列的执行顺序决定**，队列因此不是表现层，是逻辑层。
想做「同 seed 同局」，就得连队列调度一起复刻。

本作的对策：**把「算分」与「副作用」分开。**
结算阶段只读不写，产出一份副作用清单；清单在结算结束后按固定顺序一次性执行。
这样随机数的消费顺序由清单顺序决定，与动画、队列、帧率全都无关。

复刻件里已经用过这个形状——`evaluatePlay` 同步算完并吐出 `ScoreStep[]`，
表现层按轨迹重放，改动画不可能改分数。那是这条对策的雏形。

## 待定

- **乘区的载体是什么。** Balatro 是小丑，本作未定（题材还没定）。
  但载体必须满足两条：可数、可排序、可被玩家主动获取与丢弃。
- **轴 A／轴 B 的项数定为几。** 要等核心循环的时间结构定了才有意义。
- **初始槽位数。** Balatro 是 5。这个数字与第 4、5 条的对冲强度耦合，一起调。
