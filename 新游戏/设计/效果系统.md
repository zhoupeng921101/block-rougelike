# 3B 效果系统

> 2026-10-28 起草。本篇管本作的「buff」：基因、科技、改造、强化、版本、优惠券、标签、首领负面，
> 也就是一切改分、改参数、改规则的东西，挂在哪、什么时候被问、能改什么。
> 规则以 [3B核心规则.md](3B核心规则.md) 为准，本篇展开机制。
>
> 标注：**已定**是用户拍板或已写进规则的；**起草**是方向已定、写法由起草人拟，阶段 5 落地或定标时再核。

## 0 结论

- **不做通用 Buff**（持续时间、叠层、到点过期）。效果都挂在载体上，按「载体 × 时机 × 产出」三根轴组织。
- **计分是两个累加器，×倍率当场乘进倍率**（已定，2026-10-28）。基因的左右位置因此是硬机制。
- 计分段沿用规则核心已有的六个挂点和效果注册表；结算外的挂点用到才加。
- 参数类效果从载体重算，规则改写在判定处点名，状态变更只能走上下文方法。
- 填池子的基因走配置模板，定义流派的基因手写。

## 1 乘区：×倍率当场乘（已定）

2026-10-28 用户拍板，规则 §3.1、§3.2 已按此改写。

| | 原来：三区最后相乘 | 现在：当场乘 |
|---|---|---|
| 公式 | 底分 × 倍率 × 独立倍率，三区各自累加 | 底分 × 倍率，×倍率生效时乘进倍率 |
| 基因位置 | 只影响读累计值、复制相邻、概率判定三类效果 | 决定 ×倍率放大哪些加成 |
| 界面 | 要多显示一个数 | 底注、倍率两个数 |
| 倍率 | 整数 | 带小数，保留到 0.001 |

来由：

- 规则 §4.1 允许拖动换位，§1.3 把「乘区叠加」列为策略深度的来源。三区最后相乘时，这两条几乎落空，这是 07 号票 §7 推出的后果。
- 这样才和 Balatro 1.0.1o 真正同构：任何 ×倍率只放大它执行之前已经进到倍率里的部分
  （[出牌结算管线.md](../../参考/结论/Balatro_1.0.1o/出牌结算管线.md) §0）。玩家从原作带来的直觉直接能用。
- 战斗界面效果图只给了底注（亮蓝）、倍率（红粉）两种颜色（[工程计划.md](../工程计划.md)「美术」）。

后果：

- 块上的 ×倍率（琉璃、多彩）在逐格段，只放大基础倍率和排在它前面的加成；要放大全部加成，×倍率得放在基因段。
  原作同理：多彩贴在小丑上才放大小丑的加成（同上 §4.2）。
- 逐格的先后（规则 §3.1）开始影响得分：琉璃格之后的格给的 +倍率，不被那块琉璃放大。规则固定，玩家能预见。
- 打乱或锁定基因顺序成了有实际杀伤的首领负面，原作的琥珀之实就是这样（同上 §6）。设计首领时要算进去。
- 放弃的是「三个乘区各管各、一眼分清」的简单。玩家要多想一层先后。

## 2 载体与生命周期

| 载体 | 挂在 | 生命周期 | 规则核心现状 |
|---|---|---|---|
| 块的点数、强化、版本 | `BlockInstance` | 本局，跟着块洗回 | 已接（`CoreEffects`，2026-10-29） |
| 块的临时状态 | 盲注状态，按块 id 记 | 本盲注，或下一次放置 | 只在 `BlockInstance` 的注释里预留 |
| 基因（含计数、成长值、代价计数） | `GeneSlot` | 本局，到卖掉或湮灭 | 版本、成长计数、待生效代价三个字段已有 |
| 消除类型等级 | 局状态 | 本局 | 已有，科技升级 |
| 优惠券 | 局状态 | 本局 | 已有，12 张 |
| 标签 | 局状态 | 到它的触发时机，用掉即消失 | 已有，12 个 |
| 首领负面 | 盲注状态 | 本盲注 | 已有，8 个 |
| 消耗品（科技、改造） | 道具栏 | 一次性 | 已有，`RunState.UseConsumable` |

生命周期只有四档：本局、本盲注、下一次放置、一次性（起草）。

- **不设「N 步后过期」的计时器**。逐步衰减、隔几手触发的效果，写成载体上的整数计数，在步收尾或盲注结束时改它。
  计数显示在载体的说明里，界面上没有藏起来的倒计时，存档也只多几个整数。
- 盘面上的「永久」效果（死格等）只管到本盲注结束（规则 §3.3 末段），按本盲注档处理。
- 消耗品本身没有持续效果。使用时把效果写到别的载体上：科技写类型等级，改造写块的属性或临时状态。

## 3 产出：四类

| 类 | 改什么 | 例子 | 走法 |
|---|---|---|---|
| A 计分增量 | 这次消除的底分、倍率，以及某格的重触发次数 | +底分、+倍率、×倍率、某格多走一遍 | 只在结算挂点里返回 `EffectDelta` 或重触发次数 |
| B 参数修正 | 规则参数 | 每组块数、弃置次数、基因槽、道具栏、刷新费、利息上限、目标分倍率 | 从载体重算出 `RuleParams` |
| C 规则改写 | 判定本身 | 万态块参与同形态、死格、类型判定门槛 | 在判定处点名查开关 |
| D 状态变更 | 局状态 | 给钱、改块属性、碎块、加块进库、生成消耗品或基因、升类型等级、改自身计数 | 调上下文方法，由管线吐事件 |

### 3.1 A 计分增量

- 只有结算挂点能出 A。结算外的挂点不能加分：分只在一次消除里产生。
- 一个 `EffectDelta` 内部的次序：先 +底分、+倍率，后 ×倍率。
- 目标分的修正不算 A，算 B。

### 3.2 B 参数修正：重算，不撤销（起草）

Brotato 0.8.0.3 的做法是：所有道具效果往一个属性字典里累加，卖掉时调逐字对称的 `unapply()` 撤销
（[效果系统.md](../../参考/结论/Brotato_0.8.0.3/效果系统.md) §1.2）。本作只学累加这半边：

- 撤销要求每个 apply 都有对称的 unapply，写漏一处，数值就永久偏掉，存档里还看不出来。
- 改成 `RuleParams` = 默认值叠上各载体的修正：加法项相加，倍率项相乘，上下限各自截。
- 重算时机：盲注开始、商店里每次买卖之后、使用消耗品之后。它是局状态的纯函数，不进存档。

### 3.3 C 规则改写：点名（起草）

Balatro 1.0.1o 的四指、捷径、模糊、幻视，都是在判定函数里按名字查
（`参考/产物/Balatro_1.0.1o/源码/functions/misc_functions.lua:527`、`:570`，`card.lua:968`、`:4075`）。
这类效果少，每个只改一处，彼此又不一样，抽成通用钩子反而难读。本作照做：

- 每种改写在 `RuleParams` 里占一个具名开关，判定代码去读开关。
- 已知要改的判定点：同形态（万态块）、放置合法性与线满判定（死格、万态块）、清屏（死格）。
- 加一种改写，就是改一处判定代码、加一条单测。不做「任意改写」的通用机制。

### 3.4 D 状态变更：走上下文

- 效果对象自己不改局状态、不吐事件。它调 `EffectContext` 上的方法，比如给钱、改块属性、碎块、升等级；管线照调用改状态、记事件（07 号票 §5 已定）。
- 要随机就从 `RngStreams` 取，一个效果用一个键（同上）。
- 结算中途的状态变更（碎块、改属性）放在结算后挂点，不影响这次的被消格和得分。

## 5 结算内的次序

一次消除的完整次序，规则 §3.1 已写，这里汇总：

1. 定类型 → 结算前 → 读底注
2. 逐格：点数 → 强化 → 版本 → 基因从左到右；重触发把这一整段原样再走一遍
3. 基因段：基因从左到右
4. 入账 → 清格 → 结算后

×倍率当场乘以后，下面这几条先后会改变得分：

- 一个来源内部：先 +底分、+倍率，后 ×倍率（已定，规则 §3.1）。
- 块的版本排在它的强化之后，两者都排在基因对这一格的加成之前。所以块上的 ×倍率不放大基因给这一格的加成（已定）。
- 带版本的基因：加算的版本在本体之前，×倍率的版本在本体之后（已定，规则 §3.1）。原作小丑内部也是这个次序（[出牌结算管线.md](../../参考/结论/Balatro_1.0.1o/出牌结算管线.md) §6 的 ①②④）。

### 5.1 复制类基因（起草）

复制相邻基因时，管线以复制者的名义再问一遍被复制者的效果，上下文带一个「代行」标记。
被复制者在代行时只出效果、不改自己的计数，否则一次触发会成长两回。
Balatro 1.0.1o 的蓝图、头脑风暴也是靠 `context.blueprint` 区分的（`源码/card.lua` 里出现 51 次）。

## 6 代价也是效果

规则 §4.1 定了强效果必须绑真实负面。代价不另开系统，按产出归进四类（起草）：

- 目标分 +X%：B 类，盲注开始时读。「只作用于拿到之后的第一个盲注」写成基因槽上的待生效计数，用掉清零。
- 死格、塌陷格：C 类，属于盘面状态。
- 减槽、减每组块数：B 类。
- 碎裂、湮灭自身：D 类，在结算后或盲注结束时判。
- 负的 +倍率可以出现；×倍率乘之前，倍率低于 0 的先按 0 算（已定，规则 §3.1）。

## 7 内容生产：模板加手写（起草）

依据 [横向对比.md](../../参考/横向对比.md) §8：Balatro 1.0.1o 的小丑只有 19/150 是配置驱动的，全是低稀有度的加法类；越是定义流派的内容，越是手写。

- **模板效果**：一个 `RuleEffect` 子类读 Luban 表的一行，形式是「条件 → 产出」。
  - 条件：消除类型、被消格所属形状、连击数、线数、点数区间或奇偶、所在槽位。
  - 产出：A 类各项、给钱。
  - 普通、罕见的大部分基因用它。
- **手写效果**：稀有、传说基因，以及所有 C 类、复制类、成长型，每个写一个子类。
- 两种都按（来源，id）注册进 `EffectRegistry`，管线不区分。
- 工作量按「一个基因一段代码」估，见 [README](../README.md)「待解决的问题」末段。

## 8 工程约束（已定，07 号票）

- 效果对象无状态。状态挂在局状态的载体上，用整数，跟着克隆和存档走。
- 全整数：底分是 long，倍率改用千分值 long（1000 = 1），×倍率也用千分值。
- 事件由管线吐，钩子只返回数据。
- 效果注册表开局时封住，是规则配置，不进存档。

## 9 计分实现与回归

计分使用底分、倍率两个累加器；倍率按千分值保存。加倍率先加，乘倍率当场乘入，最终得分向下取整。
事件与演出时间表统一传递千分倍率，界面最多显示三位小数，省略末尾零。

2026-10-28 验证：客户端自检通过，288 项单测通过，编辑器与 Windows 平台宏编译无错误；
三个种子分别用 greedy、random 跑出的六局轨迹，在归一化倍率单位与退役字段后与改动前一致。
测试覆盖基因顺序、组合加成、负倍率截断、逐次千分取整与大数饱和。

累加器是步内临时量，不进存档；本次不改变存档结构，也不清除本地存档。

## 11 落地口径（2026-10-29，起草，代码已按此做，待拍板）

把规则 §3–§5 里写到、但没写细的几处补齐时定的口径。改哪条就改代码，数值都待定标。

**强化与版本**（`GameRules/Effects/CoreEffects.cs`）

| 件 | 口径 | 候选值 |
|---|---|---|
| 琉璃 | 每被消 1 格 ×倍率；结算后掷一次碎裂，碎了就湮灭（离开方块库） | 每格 ×1.2，碎裂 1/4 |
| 铁芯 | 每被消 1 格 +倍率 | +2 |
| 金箔 | 结算后给钱，一块一次（不按格） | $1 |
| 万态 | 只做同形态判定的改写：视作任意形态，全是万态也算同形态 | — |
| 块的版本 | 每被消 1 格生效，排在强化之后 | 闪箔 +10 底分、镭射 +2 倍率、多彩 ×1.1 |
| 基因的版本 | 基因段生效：闪箔、镭射在本体之前，多彩在本体之后 | 闪箔 +50、镭射 +10、多彩 ×1.5 |
| 负片 | 只给基因，没有计分效果，不占槽 | — |

- 琉璃按格乘是照规则 §4.4「这块每被消 1 格，触发一次它的强化」。一整块 4 格都被消就是 ×1.2⁴ ≈ ×2.07，所以单格的值取得比 Balatro 的 ×2 小得多。
- 万态的「可填入任意空格」没做：方块已经能放进任何放得下的空位，这句在落子上没有可改写的东西；「参与任意消除线」按同形态理解。要的若是别的意思（比如能压死格、能叠在别的块上），另提。

**消耗品**

- 科技从货格买下进道具栏，随时用（规则 §4.2）；从补给包里选的当场用掉，不进道具栏（同 Balatro 的天体包）。
- 软锁对 11 种类型一律生效：这一局打出过那种类型，对应科技才进货格、科技包、混合包与「科技」标签；御铸改造也只生成已解锁的。没有已解锁科技时，商店不挂科技包。
- 用消耗品不算一步：不走步收尾，不动连击。盲注已分出胜负时不能用（结算与离场之间）。
- 改造的目标：盲注进行中是盘上或待放置区的块（含首领的临时块）；不在盲注里是方块库里的块。删块之后待放置区若空了，补发一组、再判一次负。

**基因**

- 换位、出售随时可做，不算一步。卖价 = 按难度折过的基础价加版本附加费（+2 / +3 / +5 / +5），取 50%，回收券 75%，至少 $1。
- 代价「目标分 +X%」在拿到时记下，下一个开盲注时兑现、随即清掉；和首领、券、轻敌标签的修正并进同一个千分值。
- 传说不进货格；基因包里每个候选 3% 换成一张没出现过的传说。货格基因的版本：闪箔 2%、镭射 1.4%、多彩 0.3%、负片 0.3%；方块货：强化 20%、闪箔 2%、镭射 1.4%、多彩 0.6%。这一套另走 `edition@段.层` 随机流，出货那条流不受影响。

**商店**

- 补给包开了可以跳过（局外循环设计稿 §7.3 没写；没有跳过的话，候选全放不下时包关不掉）。
