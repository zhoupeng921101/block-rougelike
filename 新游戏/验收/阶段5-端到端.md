# 阶段 5 端到端验收记录

口径：工程计划阶段 5「从主界面能打通一整局」；一次只验一件事，记录里写清驱动方式与看到了什么。

## 2026-10-29 · 脚本驱动的一整轮循环

编辑器 Play 模式，用反射调 `RunFlow` 与面板按钮的 `onClick`（真实点击事件链，不是直接改状态），跑一轮：

| 步 | 动作 | 结果 |
|---|---|---|
| 1 | 主界面点「开始游戏」 | 选关屏开出，主界面自动关掉；`开新局写档` 落档 |
| 2 | 选关屏点可选节点 `Node_1` | 战斗窗开出，选关屏关掉；`进节点写档` 落档 |
| 3 | 战斗里走一步（调试落子） | 盘面/托盘/累计分刷新，无报错 |
| 4 | 把这一场判成赢（测试作弊），调 `ShowResult` | 结果浮层「盲注通过 / 通关奖励 $4 · 利息 $0 / 继续 / 返回主界面」 |
| 5 | 点「继续」 | 结算入账、盲注丢弃、商店屏开出，战斗与结果窗关掉 |
| 6 | 商店点第一个货格 | 钱 $8 → $4，货格变灰，落档 |
| 7 | 点「离开商店」 | 回选关屏，下一层返回 2 个可选节点 |

上一轮同样验证过输局：随机打到 389/455 输了 → 结果浮层只有「盲注失败 + 返回主界面」→ 点它回主界面，且 `save/run.json` 已删（只剩 `.bad` 隔离档）。

## 2026-10-29 · 六段打到通关（脚本驱动，规则核心路径）

按「选关 → 开盲注 → 判赢 → 结算 → 开商店 → 关店」的顺序把 6 段 × 3 层共 **18 个节点**全部走完，每一步都过 `RunState.Validate`：

| 观测 | 结果 |
|---|---|
| 走完的节点数 | 18（6 段各 3 层） |
| 结束时 `Progress.IsComplete` | true |
| 结束时持有金额 | $147（起始 $4 + 18 场通关奖励与利息） |
| 每一步 `Validate()` | 全部 null（区守恒、稳定态、快照形状都成立） |
| 通关后 `RunFlow.AfterResult(run, won:true)` | 关窗 + `EndRun`，`save/run.json` 已删（只剩隔离的 `.bad`） |

## 没验到的

- **真实鼠标/键盘输入**的整局（拖拽落子、旋转、弃置、Esc）：本轮是脚本驱动，输入层照 [阶段5-手测清单.md](阶段5-手测清单.md) 走。
- 31/32/33 的听感与演出节奏（同上，清单 F 组）。
- 关掉声音后重启仍关着：逻辑上走 `Setting.*Muted` 三个键，实机重启需手测确认。

## 已知的坑（本轮踩到）

- **同帧先关窗再开窗**会把 YooAsset 的异步加载卡死（新窗不出现、`UIModule` 的 pending 一直挂着）。`RunFlow` 已统一改成「先开新窗 → 等它开出来 → 再关旧窗」。
- 手动反射调 `ShowResult` 时若窗是「即开即关」（`_openedFrame == Time.frameCount`），退场动画不会播，面板会留在栈外；这是测试驱动方式的副作用，正常流程（`StepShowPlayer` → 结果浮层）不受影响。
