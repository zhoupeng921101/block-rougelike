# 阶段 5 端到端验收记录

口径：工程计划阶段 5「从主界面能打通一整局」；一次只验一件事，记录里写清驱动方式与看到了什么。

## 2026-10-29 · 脚本驱动的一整轮循环

编辑器 Play 模式，用反射调 `RunFlow` 与面板按钮的 `onClick`（真实点击事件链，不是直接改状态），跑一轮：

| 步 | 动作 | 结果 |
|---|---|---|
| 1 | 主界面点「开始游戏」 | 选关屏开出，主界面自动关掉；`开新局写档` 落档 |
| 2 | 选关屏点可选节点 `Node_1` | 战斗窗开出，选关屏关掉；`进节点写档` 落档 |
| 3 | 战斗里走一步（调试落子） | 盘面/托盘/累计分刷新，无报错 |
| 4 | 把这一场判成赢（测试作弊），调 `ShowResult` | 结果浮层「盲注通过 / 通关奖励 $4 · 利息 $0 / 继续 / 返回主界面」 |
| 5 | 点「继续」 | 结算入账、盲注丢弃、商店屏开出，战斗与结果窗关掉 |
| 6 | 商店点第一个货格 | 钱 $8 → $4，货格变灰，落档 |
| 7 | 点「离开商店」 | 回选关屏，下一层返回 2 个可选节点 |

上一轮同样验证过输局：随机打到 389/455 输了 → 结果浮层只有「盲注失败 + 返回主界面」→ 点它回主界面，且 `save/run.json` 已删（只剩 `.bad` 隔离档）。

## 2026-10-29 · 六段打到通关（脚本驱动，规则核心路径）

按「选关 → 开盲注 → 判赢 → 结算 → 开商店 → 关店」的顺序把 6 段 × 3 层共 **18 个节点**全部走完，每一步都过 `RunState.Validate`：

| 观测 | 结果 |
|---|---|
| 走完的节点数 | 18（6 段各 3 层） |
| 结束时 `Progress.IsComplete` | true |
| 结束时持有金额 | $147（起始 $4 + 18 场通关奖励与利息） |
| 每一步 `Validate()` | 全部 null（区守恒、稳定态、快照形状都成立） |
| 通关后 `RunFlow.AfterResult(run, won:true)` | 关窗 + `EndRun`，`save/run.json` 已删（只剩隔离的 `.bad`） |

- 31/32/33 的听感与演出节奏（同上，清单 F 组）。

## 2026-10-29 · 指针事件驱动的真输入（不含物理鼠标）

用 `EventSystem` 的指针事件（`IPointerDownHandler` / `IDragHandler` / `IPointerUpHandler`）按真鼠标的路径驱动 `BlockPieceDragger`，也就是玩家拖拽时会走的那条链：

| 动作 | 结果 |
|---|---|
| 从托盘拖一块到盘面 (6,0) | 规则核心 `Step` 1、落点格 owner = 这一块的 id（块真的落在盘上），托盘少一块 |
| 原地点一下托盘里的块 | 朝向 0 → 1（走的是 `TapSteps` 的点击转朝向） |
| 把块拖进弃置区 | 弃置次数 3 → 2、`Step` 1 → 2 |

这三条覆盖了手测清单 C1/C2/C3 的**输入层**；手感与音效仍要真人。

## 本轮修掉的真 bug

- **从战斗里「返回主界面」会剩一张空屏**：开局时主界面已经关掉，而战斗窗的返回只关自己。现在统一走 `RunFlow.BackToMenu()`（关局内各窗 + 把主界面开回来），输局与通关的出口也改走同一条。改后实测：点返回 → 只剩主界面。
- **「继续」把局接回来之后主界面还压在下层**：`Resume` 开完战斗窗/选关屏没有关主界面。现在两条路径都在新窗开出来后关掉主界面；实测续玩选关态与续玩战斗态都只剩一个窗。

## 2026-10-29 · 退出再进「继续」验到两态

存档写成「两场之间」（选关屏）与「盲注进行中」两种形状，各退出 Play 再进一次：

| 存档形状 | 点「继续」之后 | 观测 |
|---|---|---|
| `blind: null`、`current: 1`、`money: 8`、`difficulty: Advanced` | 回选关屏 | 节点 1、$8、进阶档都原样接上 |
| 盲注进行中（`outcome: InProgress`、`current: 2`、`step: 0`） | 回战斗窗 | 直接接着打这一场 |

## 2026-10-29 · 商店与情报的按钮链路

在商店屏上真点按钮（`Button.onClick`），逐项核对规则核心的状态：

| 动作 | 结果 |
|---|---|
| 买补给包（$5） | 钱 8 → 3；货架换成 4 个方块候选、标价 $0；标题「开包:选一件」 |
| 选第一个候选 | `picksLeft` 2 → 1，方块库 28 → 29 |
| 再选一个 | 包关掉、方块库 30，货架回到 4 货格 + 券，`Validate` 干净 |
| 刷新（补钱后） | 钱 98 → 92（$5 底价 + 1 次累计），`rerolls` 累到 2 |
| 柜台券后再开店 | 货格 4 → 5 |
| 再叠「扩货」标签 | 货格 5 → 6（上限） |
| 情报标签 | 地图上六个首领从「1-3 首领」变成「1-3 首领/预置盲」这样带负面效果 |

## 已知的坑（本轮踩到）

- **同帧先关窗再开窗**会把 YooAsset 的异步加载卡死（新窗不出现、`UIModule` 的 pending 一直挂着）。`RunFlow` 已统一改成「先开新窗 → 等它开出来 → 再关旧窗」。
- 手动反射调 `ShowResult` 时若窗是「即开即关」（`_openedFrame == Time.frameCount`），退场动画不会播，面板会留在栈外；这是测试驱动方式的副作用，正常流程（`StepShowPlayer` → 结果浮层）不受影响。
