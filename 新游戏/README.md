## 怎么推进

1. **规则改动直接改 [3B核心规则.md](设计/3B核心规则.md)**。docx 原件只读，不往回同步。

## 待解决的问题

[3B审计.md](设计/3B审计.md) 提的根问题和结构问题，**2026-10-22 已全部裁定**。
每条怎么定的见 [3B审计裁定.md](设计/3B审计裁定.md)，规则正文已经按它改过。
裁定的来源有两处：[3B审计问卷.html](设计/3B审计问卷.html) 收回的第一份答卷，以及之后对答卷冲突与缺口的逐题追问。

六个根问题定成了这样：

| # | 根问题 | 裁定 |
|---|---|---|
| R1 | 时间单位与每盲注预算 | 回合 = 盲注；预算就是方块库，抽完未达标即失败；一组 3 块放完再发，弃置有次数，旋转免费 |
| R2 | 网格跨盲注保留还是重置 | 每个盲注重新开盘，「永久」类效果只管本盲注 |
| R3 | 方块的生命周期 | 盲注结束整块洗回；强化、版本、点数都挂在块上，按格触发 |
| R4 | 方块的属性维度 | 七种四格骨牌 + 点数；不要花色，不要人头 |
| R5 | 牌库模型 | 有限牌组，纯随机抽取 |
| R6 | 消除类型表与网格边长 N | 8×8；11 种消除类型，判定与优先级见规则 §3.3（起草稿，定标时重排） |

接下来要做的：

1. **定标**：初始方块库、弃置次数、点数范围、各消除类型的基础值、目标分曲线、经济参数。
   完整列表见裁定记录第五节。
2. **三张清单重新长**：从形状、点数、位置、连击、空间这几个维度出发，现表只作参考。
3. **补内容**：标签、首领负面效果、补给包、优惠券，各出一张清单。
4. **补规则细节**：审计提过、这轮还没问的几处，见裁定记录第五节。

另外，内容量要按代码估。Balatro 的小丑只有 19/150 是配置驱动，其余是按名字写死的分支，
见[总表索引.md](../参考/产物/Balatro_1.0.1o/配置/总表索引.md)。
照这个比例，每个基因的工作量要按「一段代码」估，不是「一行配置」。

## 一直要记着

- **Block 不是肉鸽**。它按个体调难度、在情绪低点触发弹窗、逐关写死胜率，服务的是留存与 LTV。
  战斗层借它的放块消行没问题；要借这几种做法的话，先说明目标差异与适用条件。
  见 [参考/横向对比.md](../参考/横向对比.md) §10。
- **参考结论里的数值有口径**。Block 的包内数值只是客户端默认分支，照搬数字之前先读该条结论的前提。
