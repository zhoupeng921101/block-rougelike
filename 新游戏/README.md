## 待解决的问题

完整清单见 [3B审计.md](设计/3B审计.md)，**都还没裁定**。
改任何单条内容之前，先定这六个根问题（清单里的大部分逐条问题都是它们的下游）：

| # | 根问题 | 一句话 |
|---|---|---|
| R1 | 时间单位与每盲注预算 | 放置 / 消除结算 / 回合 / 盲注的层级没定义；预算有「方块用完」「放置次数」「出牌次数」三种口径 |
| R2 | 网格跨盲注保留还是重置 | 两头都有暗示，决定空间压力是局内累积还是每盲注清零 |
| R3 | 方块的生命周期 | 放下、部分消除之后回不回方块库，强化挂在块上还是格上 |
| R4 | 方块的属性维度 | 花色、点数、人头全压在「形状」上，L 拐角一身五用，点数没定义 |
| R5 | 牌库模型 | 有限牌组（52 枚 / 草图 35 块）还是加权池（§5.2），三处写法冲突 |
| R6 | 消除类型表与网格边长 N | 4 种 / 12 种两套口径，没有判定优先级和基础数值；N≥5 时「≥5 格直线」恒为真 |

另外，内容量要按代码估。Balatro 的小丑只有 19/150 是配置驱动，其余是按名字写死的分支，
见[总表索引.md](../参考/产物/Balatro_1.0.1o/配置/总表索引.md)。
照这个比例，每个基因的工作量要按「一段代码」估，不是「一行配置」。

## 一直要记着

- **Block 不是肉鸽**。它按个体调难度、在情绪低点触发弹窗、逐关写死胜率，服务的是留存与 LTV。
  战斗层借它的放块消行没问题；要借这几种做法的话，先说明目标差异与适用条件。
  见 [参考/横向对比.md](../参考/横向对比.md) §10。
- **参考结论里的数值有口径**。Block 的包内数值只是客户端默认分支，照搬数字之前先读该条结论的前提。
