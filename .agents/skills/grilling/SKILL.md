# grilling — 分段并列追问

连环追问用户,直到达成共识。每问都附上你的推荐答案。

## 为什么分段

一问一答的成本不在单轮延迟,在往返轮次:20 个决定就是 20 次往返。但不能简单地「把不关联的问题并列」——追问的价值恰恰来自上一个答案剪掉后面整片分支,并列会让用户在一个尚未确定的前提下作答。

分段是这两者的交点:**波及面大的决定单独问(它剪枝),波及面不出本段的决定一批问(它们不互相剪枝)**。

「一次只问一个,一次问多个会让人晕头转向」是本卡明确推翻的做法。晕头转向的成因不是问题数量,是问题之间没有梳理过依赖:一段里塞进互相剪枝的问题才会晕。段界判据就是用来消除这个成因的,消除之后并列不再有害。

## 段界判据:反转波及面

对每个待裁定项自问:**它若反转,会让后面哪些决定作废或改写?**

- 波及后续多个决定 → 它是**段界**,单独问,答完再往下展开。
- 波及面不出本段 → 归入段内,与同段其他项一批问。

不按领域主题聚类切段。主题边界与依赖边界不重合:一个属于 A 主题的根决定,波及的往往是 B 主题的一串结论,按主题切会把这条依赖切在段界两侧。

## 段的规模与载体

段的大小**只由依赖关系决定,不设上限**——不让工具的技术上限倒灌进语义判据,不因「第 5 项装不下」而切段。

按当前会话实际可用的 Codex 提问工具收集裁定:

1. 有 `request_user_input_async` 且适用时,用它收集本段问题。在每题的 `title` 中写清问题、推荐答案及简短理由,在 `options` 中列出简短选项,推荐选项放第一位。返回 `accepted: true` 只表示问题已发出,随后到达的用户回复才是回答;界面预选第一项不代表用户已提交。
2. 否则,有 `request_user_input` 且当前模式、问题用途符合工具限制时,按其实际格式和容量收集。若工具限定仅在 Plan 模式可用,则在 Default 模式跳过它;工具已暴露不等于当前可调用。不要为调用工具声称已切换模式。
3. 没有适用的结构化提问工具时,用编号问题和字母选项让用户逐项回答,例如 `1A、2B、3:补充内容`。推荐与理由紧邻对应问题,允许用户自填答案。

段内项数超过当前工具单次容量 K 时,按下述分页收,一段 = ceil(N/K) 页;工具未规定上限时,不沿用固定 4 问的限制:

1. 先列出本段**全部 N 项**及每项的推荐答案,让用户看到本段全貌与项数。按工具允许的方式展示;若不允许在说明文字中提问,将全貌写入工具允许的问题说明字段。
2. 再按工具容量逐页收齐,保留题号与已收到的回答。使用异步工具时,收到用户回复后再记录裁定,不把发出问题当作收齐答案。

分页不改变性质:**每一项都显式呈为可点选项(无适用工具时为编号选项),不存在「没看仔细就默认通过」**。不要把段内项写成散文清单、只用工具收「你要推翻哪几项」。未回答、预选、超时或工具返回空答案均不算确认。

段界决定本身单独一问,不与段内并列项混装在同一次调用里。

## 段内答案冲突时

并列的固有风险:同段某项的答案使另一项作废或矛盾。处置是**当场点名段界误判**,不静默重问:

1. 明说「这两项实际有依赖,段界划错了」。
2. 把先决项当作新段界。
3. 受影响项重开一段重问。

误判要显式暴露。同一场追问里第二次出现同类误判,说明段界判据用错了,当场复盘判据本身,不再逐次打补丁。

## 纪律

- **每问附上推荐答案与理由。** 不是把选择题原样丢回去,是先给出你的判断,让用户在有立场的基础上裁定。
- **未获用户确认达成共识前不动手实现。** 问题问完不等于结束,用户说达成共识才结束。
