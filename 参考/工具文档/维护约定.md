# 维护约定

改 `balatro_*.py` / `brotato_*.py`，或提交改动之前读这份。只做研究问答用不到。

总则：**改生成器，不改产物**；抽取得到的输入除非任务明确要求，否则原样保留。
各游戏的流水线命令与踩坑清单在各自的 README，格式与解析取舍在同目录的技术细节文档，
按任务路由见 [../AGENTS.md](../../AGENTS.md) 的「工具与资料维护」。

---

## 代码风格

Python 3.12，四空格缩进、`snake_case` 函数、大写常量，文件名按游戏加前缀（`balatro_<用途>.py` / `brotato_<用途>.py`）。路径一律相对脚本位置解析。保留中文目录名与 Windows 下的 UTF-8 控制台处理。Godot 格式解析集中在 Brotato 的 `godot_fmt.py`，不要散落到各脚本。没有配 formatter 或 linter。

## 编码

CSV 写 UTF-8 BOM（`utf-8-sig`），文本与 JSON 用 UTF-8。序列化 Lua / Godot 表时显式固定列序与键序，派生表还要固定并列项的排序，避免无谓 diff。

## 验证

没有自动化测试框架，也没有覆盖率门槛（`参考/产物/Balatro_1.0.1o/源码/functions/test_functions.lua` 是游戏自带的调试助手，不是测试套件）。改完生成器重跑受影响的步骤及其下游消费方，然后：

- **连跑两次比对哈希**。产物是幂等的：Balatro 492 个文件、Brotato 306 个文件应当逐字节相同
- 核对表行数与代表性数值；图表或报告改了版式，肉眼过一遍
- Brotato 的解析或本地化改动，另看解包／反编译的错误文件和 `文本/_覆盖率.txt`；GDScript token 表按本包的 Godot 3.5.1 校验，**不要套 Godot 4 的映射**
- 输出有意变化时，说明变了什么、为什么

## 源包不入库

`*.apk` 已 gitignore —— `tudouxiongdi.apk` 有 103 MiB，超过 GitHub 单文件 100 MiB 的硬上限，两个包也都不是我们能再分发的。自备副本放到仓库根的 `源包/`，各工具链按脚本位置解析默认 APK，放好即可，不需要配路径。除 `unpack` 外每一步都只读已入库的抽取产物，所以全新 clone 不带 APK 也能重新生成全部表；`brotato_all.py` 只在计划真的包含 `unpack` 时才要 APK，`--skip=unpack` 与 `--dry` 不需要。换包解包用 `python 工具/brotato_unpack.py "D:\path\game.apk"`，别拿 Balatro 的 `--apk` 开关去套 `brotato_all.py`。

## 提交与 PR

提交标题用简短的中文祈使句，与现有历史一致，例如 `修正小丑总表的确定性排序`、`升级卡系统.md 登记进导航`。PR 里写明改了什么、影响哪些生成器与产物、跑了哪些验证命令与结果，以及关联的 issue；图表或报告的版式改动附截图。不要把无关的抽取资产夹带进来。
