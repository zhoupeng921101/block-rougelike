# 研究约定

三个方向各自怎么查、各游戏有哪些条目类别、怎么追回源码。
入口表和「查之前先知道这三条」在 [AGENTS.md](../AGENTS.md)。

---

## 玩法、构筑与难度设计

围绕局内循环、决策取舍、成长方式、流派组合、Boss 限制和局外解锁展开分析。

- **Balatro**：重点看小丑配合、牌型与牌组构筑。28 个 Boss 盲注的压制面、抽取轮转和反制手段单列在 [Boss盲注专题.md](结论/Balatro_1.0.1o/Boss盲注专题.md)，20 个挑战的规则拆解与解锁机制单列在 [挑战模式.md](结论/Balatro_1.0.1o/挑战模式.md)。
- **Brotato**：重点看角色限制、属性收益、武器协同、套装组合和波次生存。升级卡抽取与保底规则单列在 [升级卡系统.md](结论/Brotato_0.8.0.3/升级卡系统.md)，敌人行为、Boss／精英状态机与刷怪投放单列在 [敌人与威胁设计.md](结论/Brotato_0.8.0.3/敌人与威胁设计.md)。
- **Block**：不做构筑，对应面是难度分配——508 种发牌算法按玩家行为动态调度，兴趣曲线跌进低谷时触发商业化，章节、皮肤各走三套 A/B。见 [数值设计报告.md](结论/Block_1.3.28/数值设计报告.md) 的第二、三章。

优先解释机制如何影响玩家选择，以及这些机制之间如何配合；涉及具体条目和参数时，再查总表与源码。

## 具体数值、经济和概率

围绕成长曲线、商店经济、价格、稀有度、出现概率和抽取权重展开分析。

- **Balatro**：重点核对得分公式与盲注需求。
- **Brotato**：重点核对伤害与属性加成、敌人每波成长、刷怪规则、材料收益和危险等级。
- **Block**：重点核对发牌权重 17 档、困难关写死的胜率、290 个 Trait 包的默认分支。

说明数值所处的版本、触发条件和计算口径，区分初始值、成长值与实际局内效果。

## 各类内容的详细数据

Balatro 与 Brotato 从各自的总表索引定位条目，再查该游戏目录下的 `配置/配置CSV/` 或 `配置/配置JSON/`；Block 没有总表索引，入口在它自己的 README。

- **Balatro**：小丑、塔罗、幽灵牌、优惠券、牌组、标签、盲注、补充包、强化牌、版本和蜡封等。
- **Brotato**：角色、武器、道具、敌人、波次、刷怪组、套装、升级、挑战、难度与属性等；构筑问题继续查角色构筑、属性道具、套装武器、武器协同和套装组合等派生表。`_效果总表.csv` 是所有内容条目的最小单位，它的字段含义、三种存储方式与消费端见 [效果系统.md](结论/Brotato_0.8.0.3/效果系统.md)。
- **Block**：数值表分散在三处——`配置/配置CSV/`（`cc.JsonAsset`）、`配置/JS数值表CSV/`（写死在 bundle JS 里的 507 张）、`配置/枚举CSV/`（385 个 TS 枚举）。做算法归因查 `配置/_算法总表.csv`；子链路分工见 [README.md](产物/Block_1.3.28/README.md) 的「`配置/` 的五条子链路」。

## 核对某条内容是否真的在游戏里

从消费端（数组、池、引用方）倒着查，不能只看资源目录或导出表的行数。三套资料都有「资源存在但没接进池子」的情况：

- Brotato：14 张升级卡、敌人 `009`
- Balatro：若干死配置字段
- Block：`comb_ske` 只在清单里登记，文件走热更

Block 还有一层：上报名与真实算法名有 **43 条对不上**，做算法归因别只认上报口径。

## 追回源码

需要确认触发时机、结算顺序或特殊规则时：

- **Balatro**：追溯 `源码/` 中的 Lua。
- **Brotato**：结合 `资源/` 中的 `.tres` / `.tscn` 与 `源码/` 中还原的 GDScript 核对。
- **Block**：追溯 `src/` 下的 `G_Cfg.js` 与引擎代码，以及 `assets/` 中各 bundle 的 `config.*.json` 清单和 `import/` 资产数据。
