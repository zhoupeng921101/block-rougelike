# 交付前手工安全审查清单

**触发** = `自审触发判定.ps1` 报 `SECURITY-REVIEW: required`(安全面判据 = 该脚本 `$SecurityPathRules` / `$SecurityContentRe`:存档读写路径与文件读写调用、外部数据反序列化、起外部进程、调试特权入口,以及将来接入的平台鉴权 / 网络)。

**范围**:槽位 current diff(槽位 Demo 相对分支基线的改动);只审本轮改动及其直接调用面,不做全仓扫描。手工执行,逐条读 diff。

本作单机买断、无服务端、无内购,没有「客户端不可信、服务端裁决」这层边界;安全面落在读进来的数据会不会把游戏弄崩、弄坏存档或写出工程外。

## 视角清单

逐条给结论,不适用写「不涉及」。

1. **存档与配置读入**:局内存档、设置文件、(接入后的)配置表读入时的边界处理——反序列化异常、版本不符、字段缺失与零值的区分、索引越界、枚举越界;读坏一份存档是否只影响这份(能报错退回),而不是崩溃或卡死在启动。
2. **存档写出**:写盘是否先写临时文件再替换(中途退出不留半截档);写失败有无兜底与日志;同一存档有无两处并发写。
3. **路径**:由外部字符串(存档名、种子串、命令行参数、mod / 导入文件)拼出的文件路径是否限定在应用数据目录内,有无路径穿越;是否经反射或命令调用执行外部字符串。
4. **敏感信息外泄**:日志与崩溃上报是否带出本机用户名、绝对路径以外的隐私信息或密钥类字符串。
5. **其他不可信输入**:剪贴板、拖入文件、网页链接(如有)的解析边界;由此导致的崩溃或卡死同属本项。

## 边界(不在本清单内)

正确性缺陷(空引用、边界条件、状态机漏分支、异步时序)、规则核心的计分与随机数复现、存量存档失配后的清档判定归每日审查,归属正本 = devflow 第三步「自审」。

## 定级与处置

- **确认级**(能给出具体触发路径):本轮修复后重新自审,不带入交付。
- **存疑**(读码可疑但给不出触发路径):不改码,记入第三步呈报「待裁定项」逐项点名,交人工定夺。
