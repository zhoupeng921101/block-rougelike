# 规则审计

触发:用户手动 `/rules-audit`。查项三模式共用(1-3 必查,4-9 条件查):

1. **重复** — 同一行为多处有源;疑似与模型/框架内置重复的条款 → 删除候选。
2. **死规则** — 连续多轮审计都举不出触发实例的条款 → 删除候选(看累计,不在单次窗口下结论)。
3. **矛盾** — 条款互相冲突,或与近期实际行为冲突。
4. **信道匹配**(注入集有增减时)— 新进/移出 `.claude/rules/` 的文件该常驻注入还是该移出按需读。
5. **净增趋势**(每轮记一行观察值,非硬性上限)— `.claude/rules/` 总行数 vs 上轮;连续净增且无删除 → 「总量复查」候选。
6. **无主旁注**(有规范被覆盖/删除时)— 被改/删规范的 `>` 旁注是否随之清理;抽查现存旁注其父规范是否还在。
7. **常驻内容错放层**(常驻文件本次有改动时查该文件;「总量复查」时全量)— 常驻内容里的一大段深内容(API 细则 / 长流程 / 事故复盘 / 带日期裁定)或只对某类任务有用且有现成去处的条款 → 挪按需层,原地留指针。判据:删掉它 agent 当轮行为会不会变,会变才配常驻。挪动候选报用户裁定,不自动移。
8. **写作规约合规**(扫描面内有文件 mtime 新于上轮合规基线时只查这些;准据被改则全量)— 拿 `.claude/rules-ondemand/file-conventions.md` 规则 1-3 逐句比对持久文件正文。范围 = 规则栈 + 记忆层;不含 `.claude/devflow/*.md`、`.claude/rules-archive/*.md`、业务代码注释(由 tengine-conventions「注释准入」在写入时约束),也不含仓根 `新游戏/`、`参考/` 下的文档(按仓根 `AGENTS.md` 的约定管)。判定粒度 = 文件:行 + 规则号 + 一句判据,不给猜测式改写。合规基线落 `audit-baseline.md`,缺失或读不出即全量。
9. **四类归属**(指令类文件——CLAUDE.md / `.claude/rules/` / `.claude/rules-ondemand/` / `.claude/skills/*/SKILL.md`——自上轮基线有改动时查改动条款;「总量复查」时全量)— 每条新增或改写的条款按 `.claude/rules-ondemand/rule-authoring.md` 第 0 条归类:防环境险 / 承载项目知识 / 教 agent 怎么想怎么排步骤查多深写多长 / 维护规则的规则。第三类 → 删除候选(能机判的改成脚本检查后再删);第四类 → 核其维护对象是否还在,对象已删的随删。判定给文件:行 + 归类 + 一句判据;归类拿不准的报用户裁定,不自行降级为「留」。

## 运行模式

- **增量(默认)**:读 `.claude/rules-archive/audit-baseline.md`,规则栈自上次审计无改动 → 记「无变化,跳过」即止;有改动只审 delta。写 audit-log + 推进基线。
- **全审(`全审` / `full` / `all`)**:无视基线,全栈 + 记忆层全量;条件查项 4-9 一律跑,判定基准 = 当前全量状态。写 audit-log + 推进基线。
- **指定目标(`@<路径>`,可多个)**:目标是焦点、非范围上限——查项全跑,目标文件逐条细审不走短路,其余规则栈文件作交叉比对背景。写轻量 audit-log 段(注明焦点),不推进基线(其余文件未逐条深审,推进会谎报)。

执行要点:

1. **规则栈范围**:项目根 `CLAUDE.md`、`.claude/rules/`、`.claude/rules-ondemand/`、`.claude/skills/*/SKILL.md`、`.claude/skills/*/references/*.md`、`.claude/references/tengine/*.md`。仓根 `AGENTS.md` 管研究层与设计层,不在本栈内。记忆层另走下节。
2. 跑 `.claude/devflow/理由对齐核对.ps1` 核外移理由的指针↔条目双向对齐,以脚本为准。
3. 结论写入 `.claude/rules-archive/audit-log.md`(一次审计一段);增量 / 全审模式更新 `audit-baseline.md` 的三行基线(规则栈 git rev/日期、记忆层 mtime、查项 8 合规 mtime,各自独立短路)。
4. **删除候选先报用户裁定,不静默删**;候选须过 `.claude/rules-ondemand/rule-authoring.md`「删减准入」的逐条判据与举证。

## 记忆层审查

范围 = user 级项目记忆目录(路径由 `.claude\devflow\记忆索引核对.ps1` 无参跑即得):`MEMORY.md` 索引 + 各 memory 文件。不在 git,增量短路用 mtime;全审全量;指定目标指向该目录时全方面审、不推进记忆基线。

逐条判定前先读该 memory 文件当前全文,不据索引摘要或会话起始快照判。

1. **重复** — 内容已被规则栈文档覆盖 → 删候选(规则文档是正本,memory 不留副本)。
2. **死记忆** — 连续多轮举不出「哪类会话会用到」 → 删候选。
3. **过时** — file:line / 代码行为断言与现状矛盾 → 现场核后重写或删,不叠勘误注。
4. **M1 索引-文件一致性** — 跑 `记忆索引核对.ps1`,得无主文件与悬空索引;修齐时索引与文件成对处置。以脚本为准,不肉眼比对;任何记忆增删的收尾也跑一次。
5. **M2 状态类生命周期** — `type: project` 与状态快照类:任务已闭环且已提交 → git 可推的进度不留,只留 git 推不出的残留(待验项、仓外路径、跨轮状态、勿删的反直觉字段);无残留整条删。

删除 / 瘦身候选先报用户裁定。
