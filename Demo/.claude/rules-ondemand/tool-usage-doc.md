# tool-usage-doc.md — 工具须自带最小使用知识

> 按需规则:**新增或修改一个供他人调用的工具**时读。总原则:调用方不该靠读实现来学会调用。工具的作者手上有全部上下文,写一次说明是分钟级成本;调用方没有这份上下文,每次都要逆推入口、参数、副作用,成本按调用次数翻倍,且逆推结果不保证对——漏看一个参数就可能覆盖用户文件。义务在作者侧,不在调用方侧。

**适用**:所有 agent(含子 agent)。触发时机:新增或修改**供他人调用**的工具——Unity Editor 工具与其公开静态方法、`.claude` 下的脚本入口、跨模块调用的公开 API、供 agent 经 MCP 调用的任何入口。

**写 `.claude` 脚本另遵**:`.claude/rules-ondemand/script-authoring.md` 承载参数形态与安全(R6-R11);本卡承载「有没有说明」,两卡正交,新增脚本入口两卡都过。

## 最小使用知识 = 六项

调用方读完就能正确调用一次、且知道调用会发生什么。缺一项就要逆推:

| 项 | 缺了会怎样 |
|---|---|
| **入口全名** | 调用方从菜单项 / Inspector 按钮反查代码,菜单挂在哪个类跟入口在哪个类经常不是一处 |
| **每个参数该传什么**(不是类型,是语义与典型值) | 签名只给类型;`bool isGenImp` 看不出传 false 是「不覆盖用户实现」 |
| **前置条件** | 漏了就静默失败或报错在别处(如「组件须已挂在 prefab 根上」) |
| **副作用:写哪些文件、是否覆盖** | 这是唯一会造成不可逆损失的一项,必须显式写,不能靠调用方猜 |
| **调用后要做什么** | 如 `AssetDatabase.Refresh()`、等编译完成、刷新导入 |
| **配套入口** | 一件事分两个入口时(如生成与绑定分离),只说一个等于没说 |

## 写进去的命令与路径,自己先跑过

六项里的**前置条件**与**调用后要做什么**常常落成一条能直接复制执行的命令。这类内容进文档前现场核验:命令实际跑一遍,路径实际确认存在。**从既有文档继承的同样要核** —— 旧文档里的路径可能一开始就是错的、或早已随实现漂移,继承时不核等于给一条未验证的断言重新背书。

只圈两类,不泛化到所有断言:**可直接执行的命令**、**文件与目录路径**。核不动时(要连生产机、要跑破坏性操作)写明「未验证」,不写成确定语气。

接错症状:文档通篇读着合理,照做却拿到 `No such file or directory`;更坏的一种是命令跑得通却没做成事,使用者以为前置条件已满足,实际配置静默不生效、且下游全程报成功。

## 写在哪:就近

- **C# 工具** → 写在**入口方法或其宿主类的 XML 头注释**(`<summary>` / `<remarks>`),与代码同源不会漂。
- **`.ps1` 脚本** → 写在**脚本头注释块**,与 `-CheckOnly` 等参数声明相邻。
- **跨多个文件才讲得清的流程** → 才升格为 `.claude/references/` 篇目,并在各入口头注释里指向该篇。**不默认升格**:分离的文档会与代码分叉,`refs-check` skill 的存在本身就是这份分叉成本的证据。

## 边界:哪些不要写

过度执行会把注释写成噪音,以下明确不在适用面:

- **私有方法、只有单一调用点的内部函数** —— 调用方就是作者自己,读实现是最短路径。
- **签名已自解释且无副作用的纯函数** —— `GetBtnFuncName(string varName)` 不需要六项。
- **把实现逻辑复述一遍** —— 说明写的是**契约**(怎么调、会发生什么),不是**实现**(内部怎么做到的)。复述实现的注释会在重构后变成假话,比没有更坏。

## 遇到无说明的既有工具

逆推出来的那份知识**就是缺失的说明**,补回入口处,不要只用完即弃。判据:如果下一个调用方(或三个月后的自己)还得重挖一遍,就该补。补注释属产品代码改动,按 CLAUDE.md 的通道规则走。
