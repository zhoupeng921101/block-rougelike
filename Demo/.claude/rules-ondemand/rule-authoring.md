# rule-authoring.md — 规则准入核对

> 按需规则:**新增/修改常驻指令**时读,承载只在这个时机触发的准入程序。

**适用**:所有 agent(含子 agent)。触发时机:要新增或修改常驻指令(项目根 CLAUDE.md / `.claude/rules` / `.claude/rules-ondemand` / `.claude/skills` 下规则文件)。

## 规则准入(新增常驻指令前必查)

常驻指令(适用节列出的全部文件)也是持久文件,准入前过以下提问:

0. **机判优先,文字只承载环境险与项目知识** — 能写成脚本检查(自检道次 / 提交校验 / hook)的不写成文字规则。文字规则只收两类:防环境险(并发会话、主工作树状态、编码与进程边界、工具绑定)与承载项目知识(本工程决策、契约、接入点);教 agent 怎么思考、怎么排步骤、查多深、写多长的方法论不进。事故复发时先问能否机判,能则加脚本,不能才回文字。
1. **查重** — grep 整个规则栈(上一句列出的全部文件),并 grep `.claude/rules-archive/audit-log.md`(`/rules-audit` 首次运行后才有;block-client 的审计记录没有带过来)查拟增条款是否曾按裁定删除或否决:命中已删条款(原文或改写)的只走下节「回滚」条恢复,举不出归因为「规则缺失」的缺陷实例即不进;命中被否决的新增(含「不加检查」类)的,原否决理由仍成立即不进,前提已变的点名变了什么、报用户裁定。模型与框架内置无法 grep,默认用人工自答「这条是不是模型默认就会做」并留一句理由。仅当存在真实争议、人工自答无法得出定论时才动用**行为探针**(成本高:干净会话喂场景跑 2-3 次防采样噪声、再注入新规则跑对照,基线侧测「是否重复」、注入侧测「是否有效」)。探针非每次准入必跑——长期零触发则按审计死规则路径评估降级。
2. **分层** — 这条是性格宣言还是操作程序?同层重复才删,跨层是补充。
   > 理由见 .claude/rules-archive/rules-rationale.md#conv-admission-layer-example
3. **触发** — 举得出「没有这条会做错」的具体场景吗?举不出 = 死规则,不进。**并问复发性**:该场景是会反复发生的结构性问题,还是一次性事故(工具/通知损坏、单次环境抖动、一次措辞失误)?一次性事故优先 git 回滚或一次口头提醒,不上升为常驻规则;只有论证出复发机制才进常驻信道。
4. **反噬** — 被过度执行会怎样?无条件指令会被当成默认动作(如「多用列表」导致 bullet 泛滥),改成条件触发再进。
5. **反向冲突** — 新规则是否与既有条款矛盾?是否使某既有条款过时(被涵盖/被替代)?有 → 在同一次改动里改或删旧条款,不留给定期审计(此刻上下文最全,改旧成本最低)。

## 删减准入(删除或压缩常驻指令前必查)

适用于瘦身、`/rules-audit` 删除候选,以及任何删减既有条款的改动。

- **启动**:只在两种情况下启动一轮成批删减——体积回长(`/rules-audit` 查项 5 / 9 的观察值),或具体条款造成了错误行为 / 无效仪式,且举得出实例。「看起来还能再压」不构成启动理由。扫描不设候选配额,「无可删」是合法结论。
- **逐条判据**(每条都要过,任一不过即留):
  1. 删掉它,agent 当轮行为不变。
  2. 它防的场景没有复发机制(与上节第 3 条对称)。
  3. 已被脚本机判全覆盖;只覆盖一部分的,保留「未覆盖面」一句。
  4. 段落若在解释规则为什么存在,挪进对应 rationale、原地留指针,不直接删。
  5. 没有别处把它当正本引用(卡片、脚本注释、台账);有则先改引用。
- **举证**:每个删除候选写明「它防什么场景」与「为什么现在不需要」,只标类别不算。拿不准的报用户裁定,未裁定则留。
- **豁免**:防环境险类条款与脚本 VERDICT / 出口码契约只可改写得更短,不可删。
- **回滚**:删减与其他改动分开提交。观察期内缺陷归因为「规则缺失」且对上已删条款的,恢复该条并在其理由条目注明「曾删后恢复」,之后不再列为删除候选。
> 理由见 .claude/rules-archive/rules-rationale.md#deletion-admission-asymmetric

## 收尾

改完规则文件,提交前跑 `/rules-audit @<该文件>`(指定目标模式,分钟级):它按四类归属、重复、矛盾深审这一个文件,并跑理由对齐脚本。规则文件改动没有提交时机判,这一步是改一处即核一处的唯一在场手段。
