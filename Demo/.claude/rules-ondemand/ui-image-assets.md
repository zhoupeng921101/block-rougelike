# ui-image-assets.md — UI 图片进不进图集、怎么取

> 按需规则:**新增、替换或搬动 UI 图片,或给节点接按名换图**时读。图集体系本身的设施(打包、导入强制)在 `.claude/skills/devflow-ui/references/ui-tools.md`「图片与图集」节,本篇只管归类、落点、九宫图的打包方式、取图方式与搬家时的险。

**适用**:客户端 UI 图片资源(devflow-ui / devflow-client 段与主工程通道同此)。触发面:往 `Assets/AssetRaw/UI` 下加图、换图、搬图;给配置表加图名列;新增一处按名取图的代码。

## 归类与落点

图集只装小件。下面几类不进图集,放 `Assets/AssetRaw/UI/Texture/`,每张图自成一个资源包、按文件名寻址。

| 类 | 判据 | 落点 |
|---|---|---|
| 小件 | 按钮、图标、角标、九宫小框、列表行底;以及同屏大量出现或战斗常驻的图标族 | 图集源目录(TEngine 图集工具的收集根,见 `ProjectSettings/AtlasConfiguration.asset` 的 `sourceAtlasRootDir`)下按功能名分子目录,进图集 |
| 大图 | 整幅背景、面板底框、主视觉插图:单个界面只出现一次,短边不小于 512 | `UI/Texture/<功能名>/`,目录名同该功能的图集目录 |
| 目录型图标 | 按配置名取用,种类多且会持续增加,任一时刻同屏只出现其中几张 | `UI/Texture/<类型名>/` |
| 要按名换的图 | 图名由配置或运行时决定、代码要按名取 | `UI/Texture/<功能名>/`:图集成员不可寻址(见「取图方式」) |

放错的后果不报错:大图或目录型图标进了图集,界面只要用到该图集的任一小件,整张图集连同它们一起驻留内存;目录型图标每加一批还会把图集继续撑大。

两种容易判错的:

- 尺寸大但用途是按钮、图标、气泡的,不算大图,是源图偏大,该缩源图而不是搬出图集。
- 种类多但同屏也多、且要合批的(盘面上的方块皮肤),留图集。判据是「同屏只出现其中几张」,不是「种类多」。

## 进图集的九宫图

**有透明边、又被九宫拉伸的图,设成按完整矩形打包**(导入设置 Mesh Type = Full Rect)。新加图、原位换图、把图搬进图集三种情况都要查:进图集时透明边默认被裁掉,节点是 Sliced 且某一边没有 border 时,那一边按未裁的范围采样,会采到图集里相邻的图,表现为图的边缘外多出一条线或一块别的颜色。

- 换图也算:新图的透明边比旧图宽,采样就可能越过打包间隔,原先没事的节点在换图后才显形。
- 独立贴图没有邻居,编辑器非运行态也不走图集,这两处都看不出来;要进 Play 或出包后在用到该图的界面看。

## 独立贴图的约束

- **文件名全工程唯一**:按文件名寻址,与任何其他可寻址资源(prefab、图集、音频、别的贴图)重名即寻址冲突。图集里允许跨图集重名,搬出来之前先查重。
- 导入设置由目录规则强制(各平台压缩格式、无 mipmap、Sprite + Single),手调会在下次导入被改回。

## 取图方式

- **静态图**:prefab 上直接拖 Source Image。图集成员只能这样用。
- **按名取图**:图放 `UI/Texture`,代码调框架的 `SetSprite(location)`(用法见 `.claude/references/tengine/resource-api.md`)。图集源图不在任何 YooAsset 收集组里,没有 location,按名取不到;block-client 按名取图集子图的 `ExImage` / `SpriteBind` 没有搬进本作。
- **同一节点不混用异步 `SetSprite` 与同步换图**(直接赋 `sprite`、清图)。框架只在同一节点发起新的 `SetSprite` 时取消上一次在途加载,同步赋值拦不住它:先发起加载 A、再同步换成 B,A 到达后把 B 盖掉,只在加载慢时显形。非混用不可的,给 `SetSprite` 传自持的取消令牌,同步换图前先 Cancel。
  > 理由见 .claude/rules-archive/rules-rationale.md#ui-image-async-load-registered
- 同一节点轮流显示不同对象(复用的列表格、商品格)时,换对象先清掉旧图再发起新加载,否则新图到达之前画的是上一个对象的图。
- 配置表里图名列的说明写明落点目录。

> 客户端自检的 `图集子图组件核对` 核的是 block-client 的 `ExImage` 用法;本作没有 `ExImage`,该道空过,图集成员被代码按名取这件事没有检查拦,靠上面的归类判据。

## 把图搬出图集

1. **用编辑器搬(`AssetDatabase.MoveAsset`),不在文件系统里删旧建新**:guid 不变,prefab 上的引用才不断。
2. **搬之前查硬编码的源目录**:编辑器工具里按目录找图的(grep 目录名),按旧目录找不到图时多半静默跳过。
3. **不要把一个图集搬空而不善后**:同一轮删掉搬空的源目录及其 `.meta`,并确认没有 prefab 还引用该图集里的图。
4. **图集改动随本轮一起提交**:已跟踪图集的成员变化(含整个图集的删除)要列进 `单仓提交.ps1` 的清单。图集按 guid 登记成员、不看路径,漏提的话搬走的图既留在图集里、又各自成包。做法与理由见 `ui-tools.md`「图片与图集」节讲 `Assets/AssetArt/` 的那一条;被搬空的图集另须删掉本体。
5. 被搬空的源目录若还剩 `.DS_Store` 之类被忽略的文件,目录不会消失,编辑器会给它重新生成 `.meta`。提交前一并清掉。

## 把图搬进图集

搬法与提交同上节第 1、4 步(往已有图集加图同样要把图集列进清单),另有两处只在这个方向出现:

1. **先查有没有代码按名取它**:`SetSprite` 的 location 字符串(含拼接出来的名字前缀)、配置表里的图名列。图进了图集就不再可寻址,有人按名取就不能搬进来——那个节点会当场取不到图,只在该界面打开时显形。
2. **有透明边的九宫图按「进图集的九宫图」节处理**:搬之前是独立贴图,看不出问题;搬完对改动的界面做一次前后对比。
