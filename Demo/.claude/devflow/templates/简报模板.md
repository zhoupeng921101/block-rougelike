# 简报模板(正本)

四段 `## ` 标题为机器校验面:`简报校验.ps1` 从本文件解析必填段清单,改段名/增删段 = 改校验契约,须同步 devflow 卡「出口产物」与 `tests\简报校验测试.ps1`。段内「(填写指引:…)」行写简报时**必须替换**为实际内容——`填写指引` 字样本身是校验的占位符探测点,留着即拒。

## 目的

(填写指引:一句话回答「为什么做」,不得是需求复述)

## 需求与方案

(填写指引:经澄清与完善后的需求定稿(含用户已裁决的结论)+ 需求级方案(做什么、落在规则核心 / 表现层 / UI 哪层;依据的规则文档章节);不含实现级改法,改哪个类/方法由实现段现场推导)

## 验收点

(填写指引:只写照「目的」跑一遍看不出对错的点——边界 / 异常路径 / 同种子复现 / 存档接局或时序相关,用户视角、可观测;常规功能写「同目的」一行即可;"适当处理 X"类空话不算验收点)

## 调查摘要

(填写指引:事实判断 + 证据锚点,禁含改动方案;「无」「不适用」是合法值。改动范围按需另起 `## 改动范围` 段,属调度参照非范围承诺)
