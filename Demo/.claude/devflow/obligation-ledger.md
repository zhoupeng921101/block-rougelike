# obligation-ledger.md — 义务台账(义务 → 绑定事件 → 保证等级)

> 单一信息源:每条工作流义务在此登记其绑定对象与诚实的保证等级。新增文字规则先过 `rule-authoring.md` 第 0 条(机判优先)。本表只登记义务、绑定到哪个脚本/函数、保证等级与未覆盖面;判据、步骤、出口码的正本在绑定脚本的头注,本表不复述——脚本改判据不改本表,只有义务、绑定对象或保证等级变了才改。备注列只写「防什么」与「未覆盖面」,事故经过查 git 与 audit-log;行长由 `静态扫描.ps1` R17 机判。
>
> 本表随 devflow 从 block-client 搬来时已删去服务端通道(服务端自检及其构建前置各道、协议导出、部署)、Luban 四道与底座件各道的行;本作接入 Luban 或相应底座件时随脚本一起加回。

保证等级三级:**机器保证**(框架确定性执行,绕过须蓄意多步操作且留痕)/ **确定装载·概率遵从**(义务必然进上下文,执行靠模型)/ **弱约束·审查保障**(无机器事件,靠审查与人)。

机器保证的诚实口径:未通过检查不交付走**两信道**——①会话命令面裸 git 由 PreToolUse hook `hooks/提交检查.ps1` 拦(注册在 `settings.json`;失败放行,两条失败即停例外见其头注。注册带 `if` 预筛,命令文本含 `git` / `run_tests` 才拉起 hook:属 harness 侧 best-effort,判不出命令时照跑 hook;常见大小写写法(git / Git / GIT)的覆盖由 `tests/命令通路检查测试.ps1` S 段核,2026-10-20 真 harness 演练 26 种应拦形态全中。未覆盖:Bash 侧匹配区分大小写,`gIt` 一类混合大小写写法被预筛漏掉);②Agent 面入口 `槽位交付.ps1` 与主工程通道的 `单仓提交.ps1` 内置同源校验,**失败即停**。两信道校验单源 = `hooks/校验库.ps1`。**会话外终端敲的 `git commit` 两条信道都不覆盖**(唯一例外:UI 绑定一项另挂 git 提交前钩子,见该行)。威胁模型只防执行者为省成本跳过流程步骤,不防蓄意伪造与检查自身故障;活性靠遥测 error 行为零。

客户端自检各道(下表「内置于 `客户端自检.ps1`」各行)的「机器保证」指 devflow 通道:改动碰到该道读取面时 `槽位交付.ps1` 必跑检查、`集成交付.ps1` push 点验凭据(读取面登记见「客户端自检触发面」行)。主工作树上 `单仓提交.ps1` 只对 `Assets/GameScripts|Launcher` 的代码验凭据(面 = `校验库.ps1` `GatedRe`),只改其余读取面的提交不验票,先跑自检靠 CLAUDE.md「devflow 适用面」主工程通道与人工入库通道两条条款装载——属确定装载·概率遵从;漏跑的违规会在下一次碰读取面的槽位交付里以本轮之外的 GATE-FAIL 显形。
